# Результат проверки зашифрованного обмена

**2026-09-09: spike завершён как исследование; результаты приняты с ограничениями.**
Контейнер v3, ротация, восстановление, реальный Iroh и хранение проверены:
**45 тестов прошли на macOS и 45 на ARM64-эмуляторе Android 12**.
По решению владельца исследовательский этап пройден. Приёмка безопасности
продолжается в этапе 2 roadmap; фактическое покрытие остаётся частичным:
обнаружена проблема очистки Automerge, а реальные телефоны, защита полного
локального отката и большой формат ещё не проверены. Это не аудит безопасности.

Проект: [DESIGN.md](DESIGN.md). Команды воспроизведения: [README.md](README.md).
Исходники: [контейнер](src/container.rs), [сценарии](src/container/tests.rs),
[сеть](src/network.rs), [хранение](src/storage.rs), [граница секретов](src/session.rs).
Предыдущий этап 2026-09-08 проверял v2 и 33 теста только локальной модели;
следующие результаты расширяют его, а не начинают новый spike.

## Сценарии и пределы доказательства

| Сценарий | Проверенный результат |
| --- | --- |
| Несколько пропущенных ротаций | Актуальный пароль открывает текущий ключ и исторический набор; допустимые старые правки восстанавливаются без промежуточных паролей |
| Автоперенос и конфликты | Сохраняются исходные change hashes/deps, конфликтные значения и промежуточная история через `fork_at` |
| Отозванный автор и зависимости | Полное замыкание проверяется до merge; непринятая зависимость требует просмотра, независимая правка применяется |
| Повторный допуск | Разрыв допуска не исчезает после повторного включения identity или переупаковки change |
| Недостающие deps | `AwaitingDependencies`, затем повторная оценка и идемпотентное применение |
| Ручное извлечение | Новая подписанная версия действующего автора с происхождением; исходные revoked changes не применяются и допуск не возвращается |
| Восстановление копии | Предварительная отдельная копия, новые синхронизируемые операции, сохранение актуального пароля, manager и membership |
| Идемпотентность | Receipts сохраняются с документом; рестарт и повтор не дублируют версии, другой запрос с тем же ID отклоняется |
| Отказы сохранения | Пять injected fault; после rename нет ложного ACK, повтор читает целое поколение |
| Завершение процесса во время записи | Дочерний процесс выходит с кодом 77 до/после rename; новое открытие и повтор завершаются |
| A → locked B → C | Настоящие отдельные Iroh-процессы, direct и forced loopback relay; B не получает пароль/read key, применение после unlock |
| Обрыв и отказ сети | Усечённое сообщение, сбой до/после rename, повтор и рестарт; без маршрута и с отключённым relay соединение не удаётся |
| Приглашение | 256 случайных бит, group/recipient/manager, TTL 300 секунд, явное подтверждение, однократность и атомарный membership; peer берётся из QUIC identity |
| Передача управления | Подписанное согласие получателя, durable relinquish до доставки, retry после неоднозначной записи; successor доставлен direct/relay, управлять может новый получатель |
| Fork | Доказательство сохраняется и останавливает обмен/управление после рестарта; локальное чтение и новый доверенный набор доступны |
| Сбой сохранения fork | Остановлена текущая сессия; после рестарта без сохранённого evidence потребуется повторная доставка доказательства |
| Подмена member checkpoint | v3 не принимает его как принятую историю новой эпохи; нужен baseline с подписью управляющего |
| Локальная целостность | SHA-256 anchor обнаруживает откат файла и удаление очереди при неизменном маркере; подготовленное поколение восстанавливается после прерывания |
| Резервные снимки | Сохраняются ровно 10 предыдущих читаемых контейнеров; отдельные копии перед ротацией/восстановлением/миграцией |
| Миграция v2 → v3 | Явная локальная операция управляющего, backup исходника, отказ чужому signer; сеть не мигрирует v2 автоматически |
| Блокировка и черновик | Worker с открытым документом завершён и reaped до ответа lock, даже при неудачной записи; AEAD-черновик локальный, очередь не меняется |
| ENOSPC / read-only macOS | Реальный ограниченный HFS+ disk image; запись отвергнута, предыдущий контейнер побайтно сохранён |
| Права / размер | Новые файлы 0600, отказ конечным symlink, чтение файла и потока ограничено 1 МиБ |

Восстановление копии поддерживает map/скаляры; редактирование и извлечение —
строки во вложенных map. List/text и неоднозначные конфликтные значения снимка
отклоняются до записи. Полная схема Pass2P, вложения и интерфейс выбора не входят
в этот прототип. Согласие на handoff создаётся внутри теста, доставка successor
идёт через сеть; интерактивное получение согласия и QR-рендерер не реализованы.

## Обнаруженные проблемы и принятые меры

**Обход отзыва через снимок обычного участника исправлен.** В v2 допущенный member
мог подписать снимок с непринятыми данными отозванного автора и объявить их принятой
историей нового control. V3 отделяет management baseline; отрицательный тест
проверяет, что такие значения не проникают при приёме новой эпохи. Локальная ранее
принятая история остаётся доступной, а чужие retained checkpoint не дают полномочий.

**Drop Automerge не очищает секреты.** Инструментированный allocator проверяет
публичный canary перед освобождением памяти. На обеих средах:
`zeroizing_uncleared_frees=0 automerge_uncleared_frees=1`.
[Лог macOS](evidence/memory.log), Android — в общем логе. Диагностика возвращает
**exit 2**, это отрицательный результат требования очистки, а не пройденный тест.
Проверена граница отдельного процесса, который обязательно завершается при lock.
Она удаляет адресное пространство worker; не доказывает затирание UI/JVM-копий,
всех аллокаций KDF, swap, core dumps или физической RAM. В продукт переносить
обычный `drop(document)` как реализацию блокировки нельзя.

**Android требует Context до старта Iroh.** Первые native CLI тесты обмена проходили,
но сопровождались перехваченной паникой `ndk-context` и fallback DNS. Добавлен
JNI-стенд с Looper, JVM и живущим до завершения процесса global Context reference.
Повторные network tests прошли без этой паники; [диагностика JVM](evidence/android-jni.log).
Ожидаемые строки `synthetic network scenario did not complete` относятся к
намеренно оборванным/отклонённым обменам. `app_process` под adb shell не проверяет
разрешения APK, lifecycle приложения, Doze, Keystore или foreground service.

**Локальный marker имеет ограниченную модель доверия.** Он защищает состав файла
при сохранённом marker, но не полный откат/удаление каталога злоумышленником.
Это не переносимый подписанный manifest и не OS-защищённый high-water mark.
Приватный каталог и один писатель остаются предпосылками; гонки symlink родительских
каталогов и конкурентные писатели не закрыты.

## KDF: фактическая калибровка

64 МиБ, p=1, t=3..256; до четырёх реальных измерений, допуск ±20%, без sleep.
Результат сохраняется в зашифрованном состоянии и парольной обёртке, повторное
редактирование/unlock сохраняет выбранный профиль. Калибрует только управляющий.
До вызова калибратора синтетическая БД использует t=3; автокалибровка при создании
продуктовой БД ещё должна быть подключена.

| Цель | macOS: t / мс | Android AVD: t / мс |
| --- | --- | --- |
| 500 мс | 15 / 465 | 14 / 418 |
| 1000 мс | 29 / 856 | 33 / 1097 |
| 5000 мс | 204 / 4664 | 136 / 4969 |

[macOS measurements](evidence/kdf-calibration.log), [Android measurements](evidence/android.log).
Это отдельные запуски с меняющейся нагрузкой; время эмулятора зависит от Mac.
Физический телефон, тепловой троттлинг и повторные серии ещё нужны для параметров
продукта. Калибратор сообщает попадание в допуск, а не гарантирует время unlock.

## Fuzzing и зависимости

Seeded parser fuzzing с ASan: **1 863 144 запуска за 61 секунду**, без найденного
crash/ASan-ошибки. [Лог](evidence/fuzz.log). Вход до 8192 байт, RSS-limit 1 ГиБ,
тайм-аут случая 5 секунд; seeds — публичный v3 контейнер, Automerge document/change.
Это короткая проверка парсеров, не fuzzing всех миграций, больших документов,
сжатия, сетевого состояния или криптографических атак.

[Cargo audit](evidence/advisories.json): 0 известных vulnerability advisories,
**1 предупреждение unmaintained** — paste 1.0.15, RUSTSEC-2024-0436.
Оно не скрыто и не трактуется как уязвимость без соответствующего advisory.
[Лицензионная инвентаризация](evidence/licenses.json): 471 внешняя зависимость
во всём графе платформ, у всех объявлена лицензия. Это не юридическое согласование
выбранных лицензий и не проверка всех NOTICE/asset-файлов для выпуска.

## Обязательные проверки после spike

- Реальный ARM64 Android: KDF под нагрузкой, устойчивость файлового адаптера,
  OS credentials/Keystore, lifecycle и фоновый сервис. Эмулятор подтвердил исполнение
  ARM64-кода и сценарии, но не физическое питание/накопитель и аппаратные ключи.
- Проверенная граница секретов вместе с будущими UI/FFI-копиями; исследование
  workspace KDF, swap/core dumps. Обычный Automerge drop уже дал отрицательный результат.
- Полный откат локального состояния, аутентификация состава переносимого manifest,
  concurrency и ресурсные лимиты decompression/сложности; потоковые вложения и схема.
- Длительный fuzzing, миграции полной схемы, лицензионная политика и независимый
  разбор проекта безопасности. Последний нельзя заменить собственными тестами.

Ни UI, ни продуктовая БД не добавлены этим расширением. Проверки относятся к одному
писателю в приватном каталоге и к синтетическим процессам. Исследование завершено
с воспроизводимыми результатами и обнаруженными ограничениями. Это решение
не меняет отрицательное измерение памяти и не означает полной приёмки безопасности.

## Искусственные данные

Все БД создаются тестами во временных каталогах. Пароли `PUBLIC synthetic spike
password`, `PUBLIC new password`, `PUBLIC intermediate`, повторённые байты
Ed25519 seeds и canary — заведомо публичные fixtures. Никакие реальные БД,
ключи или приглашения пользователя не использовались. Соли/nonce из OsRng,
поэтому ciphertext не обязан повторяться побайтно. Проверяемые утверждения
детерминированы, а тайминги KDF приведены как измерения.
