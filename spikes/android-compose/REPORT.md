# Результат Android UI-spike

Дата: **2026-09-09**. Цепочка Compose → сгенерированный UniFFI → ARM64 Rust
собрана и выполнена на эмуляторе. **Полная UI-проверка этапа 1 ещё не закрыта.**

| Проверка | Результат и доказательство |

| Реальный вызов сгенерированных привязок, загрузка `.so` | Выполнен на Android 12 ARM64 AVD, Unicode возвращается без изменений, старое поколение отклоняется |
| Compose: ввод → Rust → показ → lock; фон; пересоздание Activity; тема/язык; старые ответы и события ввода | [7 инструментальных тестов прошли, 0 ошибок](evidence/2026-09-09/instrumentation.xml) |

| Реальное Android-устройство | Не подключено в проверенной сессии; аппаратная матрица не выполнена |

Эмулятор: `pass2p-spike`, `sdk_gphone64_arm64`, Android 12 / API 31,
fingerprint `google/sdk_gphone64_arm64/emulator64_arm64:12/SE1A.220630.001.A1/9056438:userdebug/dev-keys`.
Это выполнение настоящего Android-кода, но не замена телефона, его IME, GPU и Keystore.
Проверка выравнивания ELF/APK не означает запуска на ОС с 16-КиБ страницами.

Окружение сборки: Apple M4, macOS 26.6.2, Temurin 17.0.20.1+1,
Android Command-line Tools 22.0, platform-tools 37.0.1, SDK 35 r2,
Build Tools 35.0.0, NDK r27c / 27.2.12479018. Версии Gradle/Kotlin/Compose
и инструкция повторения — в [README](README.md), Cargo/Gradle lockfiles рядом.
AGP сообщает о более новой версии XML установленного SDK Manager; сборка успешна.

## Исправления по результатам запуска

- `InputStream.readNBytes` требовал API 33: заменён ограниченным чтением,
  работающим на API 31. Fragment обновлён до 1.8.6 для Activity Result API.
- Локализованный Context реагирует на `LocalConfiguration`; язык включён целиком
  в bundle. Биометрический диалог использует выбранную локаль приложения.
- Блокировка заменяет состояние поля и его Compose-поддерево, события ввода
  проверяют активность и поколение. Это закрывает путь старого callback к новой форме.
- Первые запуски тестов выявили таймаут теста доставки и сохранённый черновик
  после lifecycle-перехода. Добавлены явная прокрутка к кнопке, управляемая доставка
  уже выданного Rust-ответа и отдельная проверка старого события ввода.
  После исправлений полный набор из 7 тестов прошёл.
- Для NDK r27c явно задано выравнивание Rust ELF на 16 КиБ; проверены и остальные `.so`.
- Отключены backup и перенос данных приложения; разрешение INTERNET отсутствует.

## Границы результата

Инструментальные тесты вводят текст через Compose semantics, **не через настоящую IME**.
В тестах темы проверено сохранение редактируемого значения, а не вся визуальная матрица
цветов, фокуса и размеров. Маппинг основных ролей TOML реализован; некоторые состояния
компонентов пока наследуют значения Material3/Kit и требуют отдельной проверки.

Rust zeroize удаляет принадлежащий сессии буфер при lock. Это не доказывает очистку
копий в JNI/JNA, Kotlin String, InputConnection, редакторе, GPU или снимках процесса.
FFI-привязки возвращают копию только запрошенного образца; реальные ключи БД и протокол
разблокировки здесь отсутствуют. Проверка безопасности и основная реализация не начаты.

SAF импорт использует AtomicFile и sync; экспорт подтверждается после write/flush/sync/close.
Не проверены отказ провайдера, нехватка места, crash consistency, синхронизация каталога
и потеря питания. Успех этих синтетических операций не доказывает надёжность формата БД.
Биометрия выполняет операцию отдельным per-use AndroidKeyStore ключом; успешное/отказное
аппаратное подтверждение ещё не проверено. Отказ оставляет ручной ввод образца доступным.

Clipboard помечается sensitive, после 30 секунд очищается только совпадающее значение
с собственным случайным маркером. При недоступном чтении очистка откладывается до фокуса.
Маркер живёт в экземпляре адаптера: пересоздание Activity/процесса пока теряет задачу
очистки. Это открытый пробел, а не завершённая реализация продуктового буфера.
