# Taypeer — P2P CRDT Local-First Password Manager

## Обзор и первая версия

Taypeer — локальный менеджер паролей на Rust с интерфейсом по мотивам [KeePassXC](https://github.com/keepassxreboot/keepassxc). Он предназначен для одного человека, который хранит и синхронизирует свои БД между собственными устройствами. Каждая БД имеет отдельный файл, мастер-пароль, настройки и набор доверенных устройств. В приложении можно открыть несколько БД одновременно.

Работа с локальными данными не требует сети. Для обмена изменениями устройства должны быть доступны одновременно; если ноутбук выключен, телефон продолжает работать с последней полученной копией.

| Область | Требование первой версии |
| --- | --- |
| macOS | macOS 15+ на Apple Silicon |
| Android | Android 12+ на ARM64 |
| UI macOS | Rust + GPUI + GPUI Kit |
| UI Android | Kotlin + Jetpack Compose / AndroidX; доступ к общим Rust-сервисам через UniFFI |
| Тема интерфейса | Системная по умолчанию; ручной выбор светлой или тёмной |
| Локализация | Английский по умолчанию, русский по выбору |
| Распространение | Устанавливаемая сборка приложения / DMG для macOS и подписанный APK для Android |
| Использование секретов | Просмотр и ручное копирование |
| Совместимость | Импорт и экспорт KDBX |

Windows, Linux, iOS, Intel Mac, публикация в магазинах, автообновление, многопользовательские роли, браузерное расширение, системное автозаполнение, Auto-Type и вычисление TOTP не входят в первый релиз. Дополнительные секретные значения можно хранить как защищённые атрибуты. Телеметрии в первом релизе нет.

## Файл БД и локальное хранение

### Формат и переносимость

- Расширение собственного бинарного формата — **.taypeer**. Один файл содержит все переносимые данные одной БД: группы, записи, атрибуты, оформление, вложения, историю, корзину и данные, необходимые для продолжения синхронизации.
- Содержимое БД шифруется, включая названия, заметки, иконки, вложения и историю. Минимальный служебный заголовок для определения формата и подготовки ключа описывается в проекте криптографического формата.
- Формат имеет версию. Неподдерживаемая версия и повреждённый файл приводят к понятной ошибке без перезаписи исходного файла.
- Одного файла и его мастер-пароля достаточно, чтобы прочитать данные на новом устройстве без доступа к старым. Само копирование файла не выдаёт новому устройству сетевой допуск или полномочия управляющего.
- Приватные ключи устройства, средства биометрической разблокировки, локальные черновики и настройки интерфейса хранятся отдельно от переносимого файла. Секретные локальные данные защищаются средствами ОС и шифрованием.

### Версии и совместимость

Версия приложения, контейнера файла, схемы данных, протокола обмена и локального хранилища независимы. Эпоха ключей и последовательность управления не являются версиями схемы. Логическая модель описана в [docs/data-model.md](docs/data-model.md), контракт эволюции — в [docs/compatibility.md](docs/compatibility.md).

- Начиная с первого стабильного формата новое приложение сохраняет путь чтения и обновления всех ранее выпущенных стабильных форматов без установки промежуточных приложений. Экспериментальные файлы из `spikes/` в эту гарантию не входят.
- Совместимость определяется обязательными возможностями чтения и записи. Совместимое расширение допускает работу старого клиента только при сохранении неизвестных данных. Если запись несовместима, но корректное чтение поддерживается, БД открывается только для чтения; если несовместимо чтение, требуется обновление приложения. Исходный файл не перезаписывается.
- Обновление приложения само по себе не меняет схему БД. Несовместимую миграцию запускает управляющее устройство явным действием после разблокировки и надёжного сохранения отдельной исходной копии. Другие устройства получают единый проверенный переход. Собрать все устройства онлайн заранее не требуется.
- Миграция сохраняет идентичность БД и объектов, историю, исходные изменения, конфликты и неприменённые данные. Успех показывается после атомарной надёжной записи; сбой оставляет исправный источник, повтор не создаёт дубликатов.
- Запоздалые правки старой схемы сохраняются. Если для них нужны новые структурно преобразованные изменения, их записывает управляющее устройство: однозначные преобразования — автоматически, неоднозначные — после разбора. Пока управляющее недоступно, эти правки ждут, а допустимая локальная работа с текущей схемой продолжается.
- Получение и пересылка могут работать без поддержки чтения новой схемы, если поддержаны внешняя оболочка, необходимые проверки и надёжное хранение. Это не означает применения изменений. Неподдерживаемый обмен не выдаётся за успешный.
- Обратной миграции в старый формат Taypeer нет. Старый снимок остаётся читаемым поддерживающим его приложением, но не становится актуальной БД простым откатом файла. Восстановление в текущую БД преобразует выбранные данные в новые изменения, сохраняя текущие схему, пароль и управление. KDBX остаётся отдельным способом переноса с отчётом потерь.

Одного старого стабильного файла и его пароля достаточно для чтения актуальным приложением без управляющего устройства и без записи миграции. Это не выдаёт сетевой допуск или право менять общее состояние управления.

### Работа с файлами на платформах

| Действие | macOS | Android |
| --- | --- | --- |
| Создать | Пользователь выбирает директорию и имя файла | Рабочая БД создаётся во внутреннем хранилище приложения |
| Открыть .taypeer | Приложение работает с выбранным файлом | Выбранный через системный диалог файл копируется во внутреннее хранилище |
| Сохранить изменения | Изменяется открытый рабочий файл | Изменяется внутренняя рабочая копия |
| Сохранить копию наружу | Выбрать место для копии | Явно экспортировать копию через системный диалог |

На Android исходный выбранный файл автоматически не перезаписывается. Интерфейс объясняет, где находится рабочая копия. Импорт KDBX — отдельная операция преобразования формата.

### Сохранение и ошибки

Подтверждённые изменения автоматически сохраняются в рабочий файл атомарно. Кнопка «Сохранить» в редакторе подтверждает правки записи; отдельное ручное сохранение всей БД для обычной работы не требуется.

Успех показывается после надёжного сохранения. При нехватке места, потере доступа, ошибке записи или повреждении данных приложение сообщает причину и не выдаёт операцию за завершённую. Предыдущая исправная версия файла сохраняется. Неподтверждённый черновик не становится текущей записью.

Получение зашифрованных изменений также требует надёжного локального сохранения. Приложение не подтверждает сохранение данных, которые не удалось записать, и показывает незавершённый обмен с возможностью повторить попытку.

### Резервные копии

- Автоматически хранить **10 предыдущих исправных зашифрованных снимков БД**.
- Перед импортом в собственный формат, ротацией ключей и обновлением формата сохранять отдельную копию исходного состояния. При импорте KDBX сохраняется исходный KDBX, а преобразование создаёт новый файл.
- Предусмотреть ручное сохранение копии и восстановление данных из выбранного снимка в текущую БД. Пользователь видит, какой файл и состояние будут восстановлены. Перед восстановлением создаётся отдельная копия текущего состояния; восстановление становится новым синхронизируемым изменением. Актуальный мастер-пароль, сетевые допуски и управляющее устройство сохраняются.
- Локальные резервные копии занимают место отдельно от лимита вложений рабочей БД. Копии на том же устройстве не заменяют сохранение резервной копии вне устройства.
- Очистка истории, корзины или смена пароля в рабочем файле не меняют старые резервные копии. У них остаются прежние данные и действовавший для них пароль.

## Защита БД и разблокировка

### Мастер-пароль и подготовка ключа

У каждой БД один общий мастер-пароль для всех её копий. Пароль обязателен и не может быть пустым. Слабые пароли не запрещаются; интерфейс показывает оценку качества. Введённое значение используется точно: пробелы не обрезаются.

| Параметр | Значение |
| --- | --- |
| Подготовка ключа | Argon2id |
| Базовая память | 64 МиБ |
| Целевое время по умолчанию | 1 секунда |
| Настраиваемое целевое время | 0,5–5 секунд |
| Калибровка | На создающем, далее на управляющем устройстве |

Поле называется **«Целевое время подготовки ключа»**. Оно задаёт бюджет для калибровки KDF, а не искусственную задержку и не гарантированное время полного открытия файла. На другом устройстве те же параметры могут выполняться дольше; фактическое время подготовки ключа показывается отдельно, в том числе на Android. Минимально допустимые параметры и их проверка входят в проект криптографического формата.

### Биометрия и восстановление доступа

После разблокировки мастер-паролем пользователь может включить локальную биометрию: Touch ID на поддерживаемом Mac или биометрические средства Android. Она настраивается отдельно для каждой БД на каждом устройстве.

Биометрия не заменяет общий мастер-пароль и не передаётся другим устройствам. Если биометрическая разблокировка недоступна или перестала работать, приложение запрашивает мастер-пароль.

Ключа восстановления, серверного сброса и другого обходного доступа нет. Если мастер-пароль утрачен и ни одно устройство не может разблокировать БД биометрией, данные восстановить невозможно.

### Автоблокировка

| Событие | Поведение по умолчанию |
| --- | --- |
| Бездействие | Блокировка через 5 минут; таймер настраивается на устройстве |
| Сон или блокировка ОС | Немедленная блокировка независимо от таймера |
| Уход Android-приложения в фон | Немедленная блокировка |
| Ручная команда | Блокировка выбранной БД |

При блокировке удаляются расшифрованный документ, раскрытые секреты и ключи чтения из оперативной памяти приложения. Фоновый процесс может продолжать работу с зашифрованными данными и отдельными сетевыми учётными данными, которые не предоставляют доступ к содержимому БД.

Если открыт несохранённый редактор, приложение сохраняет локальный зашифрованный черновик перед удалением его открытого содержимого из памяти. После разблокировки предлагается продолжить или удалить черновик. Он не синхронизируется и не становится версией записи до нажатия «Сохранить». Если черновик не удалось записать, приложение явно сообщает об этом и не обещает его восстановление; ошибка записи не отменяет блокировку секретов.

### Буфер обмена

- Пароли и защищённые атрибуты помечаются как чувствительные средствами ОС.
- По умолчанию таймер Taypeer очищает скопированный секрет через **30 секунд**.
- В настройках устройства доступны произвольный положительный интервал в секундах и вариант **«Не очищать»**.
- Очистка допустима только при подтверждении, что буфер всё ещё содержит скопированное Taypeer значение. Последующее чужое копирование не удаляется.
- На Android приложение без фокуса может не иметь доступа к содержимому буфера. Если подтвердить совпадение нельзя, безусловная очистка запрещена; проверка повторяется после возвращения фокуса.
- Отключение таймера Taypeer не отключает системную автоочистку Android. Системная отметка чувствительности скрывает превью, но не шифрует буфер.

Ограничения: [Android clipboard access](https://developer.android.com/about/versions/10/privacy/changes#clipboard-data), [чувствительные данные в буфере](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste#sensitive-content).

## Синхронизация и доверенные устройства

### Модель обмена

Iroh обеспечивает транспорт между устройствами. Предпочтительно прямое соединение; при его недоступности разрешены общие relay. Пользователь может указать собственный relay или полностью отключить relay.

Обычный relay пересылает зашифрованный трафик и не хранит БД для будущей доставки. Если устройства не бывают доступны одновременно, изменения остаются на исходном устройстве до следующей возможности обмена. При отключённых relay невозможность прямого соединения означает отсутствие синхронизации.

Синхронизация разделена на два этапа:

1. **Получение:** передать, проверить в пределах доступной без расшифровки информации и надёжно сохранить зашифрованные данные. Этот этап доступен заблокированному устройству, включая дальнейшую пересылку.
2. **Применение:** после разблокировки расшифровать, проверить содержимое, объединить изменения и обнаружить конфликты.

Интерфейс различает «Изменения получены» и «Изменения применены». Получение не означает, что пользователь уже видит обновлённые записи или что конфликты разрешены.

Обмен запускается при доступности доверенного пира, после сохранения изменений и по команде пользователя. Прерванный обмен можно продолжить; повторная доставка не дублирует записи и версии. Ошибка сети не блокирует работу с исправной локальной БД.

### Фоновый режим Android

- Периодические фоновые попытки выполняются в пределах возможностей ОС, без обещания точного интервала или срока доставки.
- При открытии приложения начинается попытка обмена.
- Команда **«Синхронизировать»** запускает активную сессию с уведомлением, которая может продолжаться после сворачивания приложения. БД при этом блокируется по обычным правилам, а обмен продолжается зашифрованными данными.
- Ограничения ОС, остановка процесса и пользовательское завершение приложения могут прервать сессию. Состояние сохраняется для последующего продолжения.
- Непрерывная доступность Android-устройства как P2P-пира не гарантируется. После принудительной остановки нельзя обещать возобновление до действия пользователя.

Основания: [отложенные фоновые задания](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work#schedule_periodic_work), [ограничения foreground services](https://developer.android.com/develop/background-work/services/fgs/timeout).

### Управляющее устройство

Для каждой БД назначается **одно управляющее устройство**. При создании БД им становится создающее устройство.

Все доверенные устройства могут читать и редактировать данные в пределах совместимости приложения со схемой. Только управляющее устройство допускает и отзывает устройства, меняет общий мастер-пароль, параметры защиты и общие лимиты БД, запускает несовместимую миграцию схемы и записывает требующие её структурные преобразования старых правок. Операции управления требуют разблокировки.

Передача управления выполняется, когда оба устройства подключены и разблокированы, и подтверждается на обоих. Успешная передача оставляет ровно одно управляющее устройство.

### Получение БД и подключение нового устройства

1. На управляющем устройстве пользователь выбирает БД и команду **«Поделиться»**.
2. Создаётся одноразовое приглашение: длинный случайный код и QR с теми же данными. Оно действует **5 минут**, относится только к выбранной БД и связывается с идентичностью получателя при подтверждении управляющим устройством.
3. На новом устройстве пользователь выбирает **«Получить БД»**, сканирует QR или вводит код.
4. Управляющее устройство показывает запрос подключения; пользователь явно подтверждает новое устройство.
5. Получатель выбирает место хранения на macOS; на Android используется внутренняя рабочая копия. Приложение загружает зашифрованную БД с отображением состояния обмена.
6. Для чтения данных пользователь вводит мастер-пароль на новом устройстве. После успешной разблокировки можно включить локальную биометрию.

Остальные БД автоматически не передаются. Просроченное или использованное приглашение отклоняется. Отмена, отказ управляющего устройства и обрыв сети отображаются явно; незавершённая загрузка не выдаётся за готовую БД.

### Смена пароля, отзыв и потеря управления

| Операция | Результат |
| --- | --- |
| Смена мастер-пароля | Ротация ключей и распространение нового состояния БД |
| Отзыв устройства | Исключение из доверенных устройств, ротация ключей и обязательный новый мастер-пароль |
| Получение нового состояния | На оставшихся устройствах требуется новый пароль и повторное включение биометрии |
| Потеря управляющего устройства | Восстановление данных по файлу и паролю в новый доверенный набор устройств с новым управляющим, ключами и паролем |

Отзыв действует на конкретном устройстве после получения им нового состояния. Офлайн-устройство до этого не знает об отзыве; глобальное мгновенное исключение не обещается. После принятия отзыва новые изменения от отозванного устройства автоматически не применяются. Ранее принятые данные и история не удаляются только из-за отзыва автора.

После получения актуального состояния и ввода актуального пароля офлайн-правки устройства, непрерывно остававшегося доверенным, переносятся автоматически, включая правки после нескольких пропущенных ротаций. Исходные изменения, причинные связи, сохранённые версии и конфликтующие значения сохраняются. Если перенос требует впервые принять данные отозванного автора, в том числе отсутствующую запись из зависимостей, эта часть требует просмотра и подтверждения. Остальные допустимые изменения продолжают переноситься автоматически.

Если вместе с ротациями пропущены миграции схемы, действуют также правила совместимости: структурное преобразование может ожидать управляющее устройство, неоднозначные данные — отдельного разбора. Возможность расшифровки историческим ключом не отменяет проверку схемы, допуска или окончательной очистки объекта.

Данные отозванного устройства сохраняются отдельно от текущего документа. Пользователь может извлечь выбранные значения как новые изменения действующего устройства с сохранением происхождения; это не восстанавливает сетевой допуск. Неперенесённые данные сохраняются до успешного завершения или отдельного явного удаления. Повтор переноса и восстановления не создаёт дубликатов.

Исторические ключи чтения сохраняются бессрочно под защитой актуального независимого ключа, отдельно от приватных ключей допуска и управления. Актуальная БД и актуальный пароль позволяют прочитать допустимые старые пакеты и снимки без промежуточных паролей. Новый ключ никогда не защищается старым; возможность расшифровать пакет сама по себе не разрешает его применение.

Новые ключи защищают последующие изменения на устройствах, принявших ротацию. Удалённое стирание старой копии на потерянном устройстве невозможно; старые файлы сохраняют прежние данные и пароль.

При потере управляющего устройства прежние сетевые допуски не переносятся в новый доверенный набор. Оставшиеся устройства подключаются заново. Восстановление управления не объединяет автоматически два независимо созданных доверенных набора.

При обнаружении противоречащих подписанных состояний управления операции управления и обмен прекращаются. Локальное чтение остаётся доступным; продолжение работы с обменом требует восстановления нового доверенного набора. Предотвращение скрытого расхождения при краже управляющего ключа не входит в первую версию.

## Данные, конфликты и ограничения

### Группы и записи

- Новая БД содержит **ноль групп и ноль записей**. Автоматически созданной видимой корневой папки нет.
- Группы верхнего уровня образуют дерево с произвольной вложенностью. В дереве показываются только группы.
- Каждая активная запись принадлежит группе. Сначала пользователь создаёт и выбирает группу, затем может создать запись.
- Названия группы и записи обязательны. Остальные содержательные поля, включая пароль записи, необязательны.
- Клонирование группы копирует всё поддерево и текущие версии записей: поля, атрибуты, оформление и ссылки на вложения. Новые объекты получают новые ID; их история начинается с клонирования.
- Клонирование записи создаёт новый ID и текущие данные без старой истории.
- Группы можно перемещать с изменением порядка и вложенности; записи — между группами.
- Удаление группы отправляет всё поддерево в корзину после подтверждения. После удаления последней активной группы снова показывается пустое состояние.

### Объединение и конфликты

Automerge используется для объединения изменений, но пользовательские правила конфликтов задаёт Taypeer.

| Сценарий | Поведение |
| --- | --- |
| Одновременное изменение разных полей | Автоматически объединить изменения |
| Разные значения одного поля | Сохранить варианты, пометить конфликт и потребовать явного выбора |
| Удаление и параллельная правка | Оставить объект в корзине с сохранёнными изменениями и пометкой конфликта |
| Входящее изменение во время редактирования | Сохранить локальный черновик; при подтверждении учитывать обе правки по общим правилам |
| Конкурирующие перемещения | Не терять объекты и не показывать циклическое дерево; конфликт размещения доступен для разбора |
| Повторное получение изменений | Не создавать дубликатов объектов или версий |

Текстовые поля, включая заметки и пароль, изменяются целиком без посимвольного объединения. Теги считаются одним изменяемым набором. Атрибуты и вложения имеют собственные стабильные ID; переименование не меняет их идентичность. Значение атрибута и признак его защиты изменяются как единое значение: параллельное снятие защиты не должно раскрывать другой новый секрет. Имена атрибутов обязательны и уникальны в записи при точном сравнении; параллельно возникшие совпадения сохраняются для разбора.

Неразрешённое значение не выбирается автоматически по времени последнего изменения. Общая кнопка копирования конфликтующего значения отключена; в окне разбора каждый вариант можно отдельно раскрыть и скопировать. Пользователь выбирает актуальный вариант или вводит собственное итоговое значение; исходные варианты остаются доступны в истории.

О конфликтах сообщают счётчик и постоянное уведомление в рабочей области. Окно разбора не открывается автоматически и не прерывает текущую работу.

Для конфликта удаления пользователь выбирает восстановление объекта или подтверждение удаления. Восстановление создаёт новое текущее состояние и не переписывает прошлую историю.

### История и корзина

Хранятся все сохранённые версии записи. Автоматического ограничения числа версий и срока хранения нет. Пользователь может просматривать изменения, восстанавливать версию новой текущей версией и явно очищать историю.

Сохранённая версия соответствует подтверждению состояния записи. Автоматическое объединение сохраняет исходные версии, но не добавляет отдельную системную строку истории. Разрешение конфликта и восстановление создают новую версию; техническая миграция — нет.

Корзина хранится до ручной очистки. При очистке пользователь подтверждает потерю доступности удаляемых данных в рабочей БД. Нерешённый конфликт не должен исчезать вследствие обычной очистки истории без его разрешения.

Очистка синхронизируется и сохраняет отметки, препятствующие возврату уже очищенных данных при повторной доставке. Если после окончательной очистки объекта пришли новые офлайн-правки, объект автоматически не возвращается ни в активные данные, ни в корзину: правки сохраняются отдельно для просмотра и явного восстановления. Неприменённые источники не удаляются обычной очисткой истории или корзины.

Если исходная группа восстанавливаемой записи отсутствует, пользователь выбирает существующую группу или создаёт новую. Восстановление завершается только после выбора назначения; служебная группа для этого молча не создаётся.

Удалённое из текущей записи вложение продолжает занимать место, пока используется историей, корзиной или другим объектом. Очистка рабочей БД не является обещанием безопасного удаления данных из старых файлов, резервных копий и устройств.

В первой версии очистка освобождает содержимое вложений и изображений, на которое больше нет нужных ссылок, после проверки истории, конфликтов и неприменённых данных. Неизвестные ссылки ожидающих источников могут задержать освобождение места. Полного удаления старых значений полей из CRDT-журнала и полного уплотнения файла не обещается; очищенные данные недоступны через обычные сценарии продукта.

### Вложения

Поддерживаются любые типы файлов в пределах лимитов. Действия: добавить, сохранить наружу, переименовать, заменить целиком и удалить. Встроенного редактора и автоматического открытия для редактирования внешним приложением нет. Для изменения содержимого пользователь выбирает заменяющий файл; прежняя версия остаётся в истории.

| Ограничение | По умолчанию | Максимум настройки |
| --- | --- | --- |
| Одно вложение | 10 МиБ | 100 МиБ |
| Сумма вложений одной БД | 100 МиБ | 1 ГиБ |

Общие лимиты меняет управляющее устройство; они распространяются на остальные. Сумма учитывает уникальное содержимое вложений в активных данных, всей доступной истории и корзине. Одинаковый файл, используемый несколькими объектами или версиями, не считается несколько раз.

Варианты нерешённых конфликтов также удерживают вложения и учитываются в лимите. Содержимое, используемое только как иконка, ограничено правилами изображений и не расходует лимит вложений. Очередь неприменённых данных и резервные снимки занимают физическое место отдельно; их нельзя удалять автоматически для устранения превышения лимита.

Добавление сверх действующего лимита отклоняется с объяснением. Если два устройства офлайн добавили допустимые файлы, а после объединения сумма превысила лимит, уже принятые изменения сохраняются. Приложение показывает превышение и запрещает новые добавления до очистки или повышения лимита. Общий лимит, таким образом, допускает превышение после объединения.

Недостаток физического места — отдельная ошибка: несохранённые файлы не считаются полученными, и обмен остаётся незавершённым.

## Тема интерфейса

### Выбор режима

Настройка **«Тема» / “Theme”** относится к установке приложения на устройстве, применяется ко всем окнам и БД и сохраняется между запусками. Она хранится отдельно от файла БД и не синхронизируется. Выбор доступен через настройки устройства также на приветственном экране и при заблокированных БД.

| Режим (ru / en) | Поведение |
| --- | --- |
| Системная / System | По умолчанию; автоматически следует светлому или тёмному режиму ОС |
| Светлая / Light | Фиксирует светлую палитру независимо от режима ОС |
| Тёмная / Dark | Фиксирует тёмную палитру независимо от режима ОС |

Тема применяется при запуске. В системном режиме изменение режима ОС обновляет весь интерфейс без перезапуска; после возвращения приложения из фона режим ОС проверяется снова. Переключение сохраняет ввод, черновики, фокус и навигацию, включая открытые формы и диалоги. Оно не меняет состояние блокировки БД.

Если режим ОС определить невозможно, используется последний известный системный режим; при его отсутствии — светлый. При возвращении к выбору «Системная» применяется актуальный режим ОС с тем же правилом резерва. Вычисленная светлая или тёмная палитра не заменяет сохранённый выбор «Системная».

ОС определяет только светлый или тёмный вариант. Системный акцент и динамические цвета не подхватываются; цвета задаёт палитра Taypeer.

### Встроенные палитры первой версии

Один внутренний **TOML-файл**, поставляемый с приложением, содержит секции `light` и `dark` с одинаковым полным набором семантических цветовых ролей. Роли охватывают поверхности, текст, границы, акцент, выделение, фокус и состояния элементов. Компоненты получают цвета через слой темы продукта с адаптерами к GPUI Kit на macOS и Compose на Android, без независимых палитр отдельных экранов. Обе сборки используют один источник встроенных палитр.

Файл задаёт цвета; шрифты, размеры и геометрия регулируются отдельно. Явно заданные цвета самой записи сохраняют своё значение при переключении темы; палитра определяет оформление по умолчанию и не переписывает данные записи.

В первой версии обе палитры задаёт разработчик во внутреннем файле. Пользователь выбирает режим; загрузка пользовательского файла и графический редактор цветов относятся к будущему этапу.

### Будущая персонализация

Предусмотреть отдельный локальный пользовательский TOML с частичными переопределениями цветовых ролей для `light` и `dark`. Допустимо переопределить даже один цвет одного варианта; неуказанные значения берутся из соответствующей встроенной палитры. Встроенный файл остаётся основой и не изменяется при персонализации.

Будущий графический редактор читает и сохраняет тот же пользовательский файл, который можно редактировать вручную. Допускаются любые корректно записанные цвета без проверки или предупреждений о контрасте и без скрытой коррекции. Предусмотрено действие **«Сбросить цвета» / “Reset colors”**, возвращающее обе палитры к встроенным значениям без изменения выбранного режима.

Подробности автоперечитывания и сохранения пользовательского файла проектируются на этом будущем этапе. Наличие этих требований не означает готовность пользовательских тем в первой версии.

## Экраны

### 1. Приветственный экран

Действия: **«Создать БД»**, **«Открыть БД»**, **«Получить БД»**. Если ранее открывались БД, показывается список последних. Также доступен отдельный сценарий **«Импортировать KDBX»**.

После запуска всегда показывается приветственный экран с последними БД. Открытая сессия автоматически не восстанавливается.

#### Создание БД

На macOS открывается модалка, на Android — соответствующая форма.

| Поле | Описание |
| --- | --- |
| Название БД | Обязательное |
| Описание БД | Необязательное |
| Мастер-пароль | Непустой; показ качества без запрета слабых паролей |
| Повтор пароля | Должен совпадать с мастер-паролем |
| Целевое время подготовки ключа | 1 секунда по умолчанию, диапазон 0,5–5 секунд; объяснение калибровки |
| Директория и имя файла | Выбор на macOS; на Android пояснение внутреннего хранения |

Кнопки: **«Отмена»** и **«Создать»**. После начала создания отмена блокируется, кнопка показывает загрузку. При ошибке отображается причина и возвращается возможность исправить форму или отменить действие.

После успешного создания открывается БД с пустым деревом и кнопкой **«Добавить группу»**. В центре поясняется, что для первой записи нужно создать группу. Создание записи до выбора группы недоступно.

#### Открытие и последние БД

«Открыть БД» запускает системный выбор .taypeer и переводит к разблокировке. На Android предварительно создаётся внутренняя рабочая копия.

При повторном выборе файла БД, уже имеющей внутреннюю рабочую копию на Android, предлагаются **«Открыть рабочую копию»**, **«Восстановить из выбранного файла»** и **«Отмена»**. Восстановление требует отдельного подтверждения замены и предварительной резервной копии текущего состояния.

Клик по последней БД открывает её экран разблокировки. Если файл отсутствует или недоступен, приложение сообщает об этом и позволяет выбрать его снова; прежний файл не создаётся молча заново.

#### Получение БД

Открывается сценарий приглашения: сканирование QR или ввод кода, ожидание подтверждения управляющего устройства, загрузка с состоянием обмена и разблокировка. Ошибки и повторное подключение описаны в разделе синхронизации.

### 2. Экран разблокировки

| Элемент | Назначение |
| --- | --- |
| Заголовок | Запрос мастер-пароля |
| Файл БД | Путь на macOS; обозначение внутренней рабочей копии на Android |
| Поле мастер-пароля | Ввод для разблокировки |
| Биометрия | Доступна, если включена и поддерживается для этой локальной БД |
| «Назад» | Возврат к предыдущему экрану |
| «Разблокировать» | Начать подготовку ключа и открытие данных |

Во время операции показывается загрузка. При успехе открывается БД и применяются накопленные зашифрованные изменения. При ошибке показывается уведомление без отображения содержимого БД. Если требуется новый пароль после ротации, интерфейс сообщает об этом и не обещает доступ прежней биометрией.

При наличии локального черновика после разблокировки предлагается восстановить или удалить его.

Блокировка происходит на месте: БД остаётся в селекторе открытых баз, а её дерево, записи и формы целиком заменяются экраном разблокировки. Данные не видны позади формы входа. Другую открытую БД можно выбрать из селектора.

### 3. Экран открытой БД

На macOS экран состоит из дерева групп, таблицы записей и панели выбранной записи. Если запись не выбрана, панель деталей скрыта, а таблица занимает всю оставшуюся ширину справа от дерева. На Android содержимое доступно через последовательную навигацию, описанную ниже.

Макеты: [OpenPencil](wireframes/taypeer.fig), [правила дизайна и карта экранов](wireframes/README.md). Стиль следует предоставленным GPUI Kit Design Guides и референсу Zedis: компактный интерфейс, плоские поверхности, тонкие границы и нейтральный выбор. Текстовые подсказки оставляются только для значимых последствий, причин ошибок и восстановления. Редкие состояния описываются правилами, без отдельного макета каждого варианта.

Настройки открываются иконкой справа в верхнем хедере; отдельного текстового пункта настроек в левой панели нет. Футер показывает размер файла текущей БД и состояние синхронизации. При закрытой БД эти значения не показываются.

#### Левая панель — БД и дерево групп

Текущая БД и селектор других открытых БД располагаются в верхнем хедере окна. Через меню БД доступно действие «Поделиться». Для неуправляющего устройства причина недоступности приглашения объясняется при обращении к действию. Над левым деревом нет текстового заголовка «Группы».

Селектор БД также содержит действия открытия, создания, блокировки и закрытия БД. Закрытие последней открытой БД возвращает на приветственный экран.

При отсутствии активных групп показывается пустое состояние с кнопкой **«Добавить группу»**. Созданные группы появляются на верхнем уровне. Видимого служебного корня нет.

Корзина открывается отдельным действием панели и не считается пользовательской группой. Она доступна и при пустом дереве: пользователь может восстановить удалённые группы и записи или явно очистить корзину. На Android это действие находится в меню БД.

- У группы есть название и иконка. Без пользовательской иконки используется стандартная открытая/закрытая папка.
- Клик выбирает группу и показывает её записи в центральной панели.
- Записи внутри дерева групп не отображаются.
- Drag & drop меняет порядок и вложенность.
- Двойной клик открывает редактирование группы.
- Контекстное меню пустого места содержит одно действие «Создать группу», создающее группу верхнего уровня.

| Действие в меню группы | Результат |
| --- | --- |
| Создать группу | Форма создания подгруппы |
| Изменить группу | Форма редактирования |
| Клонировать группу | Форма клонирования всего поддерева |
| Удалить группу | Подтверждение перемещения поддерева в корзину |
| Загрузить значки | Явно запущенная загрузка иконок для записей выбранной группы |

#### Формы групп

Создание, редактирование и клонирование используют одну форму с разным начальным заполнением.

| Поле | Описание |
| --- | --- |
| Название | Обязательное |
| Описание | Необязательное |
| Значок | Lucide Icons или загрузка по URL |

Кнопки: **«Отмена»** и **«Подтвердить»**. Клонирование не переносит старую историю и не переиспользует ID исходных объектов.

Клон группы создаётся рядом с оригиналом в том же родителе. После создания новой группы она автоматически выбирается, и открываются её записи.

#### Центральная панель — записи и поиск

Вверху находятся поиск, создание записи и меню действий/колонок. Название текущей папки над таблицей не повторяется: выбор виден в дереве. Копирование логина и пароля доступно в деталях выбранной записи и меню команд. Недоступные без выбора действия отключены. Таблица всегда имеет заголовки колонок.

Колонки по умолчанию:

| Колонка | Содержимое |
| --- | --- |
| Название | Название записи |
| Имя пользователя | Логин |
| URL | Адрес |
| Заметки | Текстовое представление заметок |
| Изменение | Время последнего изменения |
| База / группа | Источник записи, в том числе в межбазовом поиске |

Сортировка выполняется кликом по заголовку: по умолчанию название по возрастанию (А–Я); выбор другой колонки включает возрастание, повторный клик меняет направление. Активная колонка показывает стрелку вверх/вниз, остальные сортируемые колонки — нейтральный двунаправленный индикатор. Между заголовками есть тонкие вертикальные разделители; в теле вертикальной сетки нет. Выбранная запись сохраняется по ID при сортировке и фильтрации. Колонки можно скрывать и возвращать; порядок сортировки и видимость колонок локальны для устройства. В узкой панели макета видны «Название», «Логин» и «База / группа»; дополнительные колонки доступны через меню. Без поискового запроса таблица показывает только записи непосредственно выбранной группы. Поиск использует ту же таблицу, заголовки, сортировку, высоту строк и представление значений; отдельного формата карточек результатов нет.

Поиск по умолчанию охватывает всю текущую БД, включая подгруппы. Переключатель добавляет остальные разблокированные БД. Поля поиска: название, логин, URL, заметки, теги и значения незащищённых атрибутов. Пароли и защищённые значения не участвуют. Заблокированные БД не раскрываются для поиска. Результаты общего поиска показывают БД и группу.

Выбор результата общего поиска переключает активную БД и группу на источник результата и открывает запись. Действие **«К результатам поиска»** возвращает исходный запрос, область поиска и результаты.

Для записи доступны создание, редактирование, клонирование, перемещение в другую группу и удаление в корзину с подтверждением.

#### Правая панель — карточка записи

Панель появляется после выбора записи и сначала работает в режиме просмотра. На macOS создание и редактирование записи происходят в той же правой панели. В заголовке записи находится иконка `pencil` с доступным именем **«Редактировать запись»**. В режиме правок её заменяют `x` (**«Отменить редактирование»**) и `check` (**«Сохранить запись»**). Нижних дублирующих кнопок нет. Сохранение подтверждает целую запись, отмена запрашивает выход при наличии изменений. Иконки не зависят от наведения, имеют tooltip и клавиатурные команды. Название в заголовке не заменяется словом «Редактирование»; правка названия отражается в заголовке после сохранения.

Верхние полосы дерева, поиска и заголовка записи имеют общую высоту 44 в базовом масштабе и совпадающую нижнюю границу. Вкладки расположены сразу под этой линией. Верхние команды остаются доступны при прокрутке тела записи. На Android применяются те же иконки с областью нажатия 44 и отдельной верхней полосой 56.

При переходе к другой записи, группе или БД, нажатии «Назад», отмене редактирования или закрытии БД с изменённой формой предлагаются **«Сохранить»**, **«Не сохранять»**, **«Остаться»**. Отложенный переход выполняется после успешной валидации и записи; при ошибке форма остаётся открытой с введёнными данными. Это правило действует и для формы группы. Блокировка не ждёт такого подтверждения и использует правило зашифрованного локального черновика.

Форма создания использует те же содержательные поля. До подтверждения изменения не синхронизируются. Правила локального черновика при блокировке действуют и для создания, и для редактирования.

Просмотр и редактор используют одну сетку, порядок полей и положение меток: на macOS — строки метка/значение без заголовков «Поле / Значение», на Android — одинаковые вертикальные пары. В режиме правок значения заменяются контролами на тех же местах; текст не смещается из-за внутренних отступов input. Повтора пароля записи нет. Справа от поля пароля расположена иконка генератора, справа от URL — иконка явной загрузки favicon с соответствующим доступным именем. Это не меняет подтверждение мастер-пароля при создании БД.

Все похожие формы используют эту же композицию: метки слева, значения на общей вертикали на macOS; метки над значениями в узкой мобильной области. Вариант input внутри структурированной строки записи прозрачен; самостоятельные поля, поиск, числовые и цветовые контролы имеют слабую тематическую заливку. Постоянной обводки нет. Клавиатурный фокус обозначается видимым кольцом; ошибка — цветом метки, рамкой состояния и близким пояснением. Select имеет стрелку раскрытия, выбор файла — явную кнопку. Разделители строк таблицы не являются обводкой полей. Вне записи подтверждение и отмена форм остаются текстовыми действиями.

Режим правок и черновик общие для «Обзора», «Дополнительно» и «Вида». Переключение вкладок не сохраняет и не отменяет изменения. В просмотре нет редактируемых ключей, чекбоксов защиты, добавления вложений или выбора оформления; чтение, раскрытие, копирование и скачивание доступны. При правках все изменения этих вкладок подтверждаются общей галочкой.

##### Вкладка «Обзор»

| Поле | Описание |
| --- | --- |
| Название | Обязательное |
| Имя пользователя | Необязательное; доступно копирование |
| Пароль | Необязательное; скрыт по умолчанию, доступны показ, копирование и генератор |
| URL | Рядом кнопка явной загрузки favicon |
| Теги | Метки записи |
| Истекает | Необязательная дата с чекбоксом включения и предустановками |
| Заметки | Необязательный текст |

##### Вкладка «Дополнительно»

| Поле | Описание |
| --- | --- |
| Дополнительные атрибуты | Пары ключ–значение: добавление, удаление, изменение ключа и значения |
| Защита атрибута | Чекбокс скрывает значение по умолчанию; доступны явное раскрытие и копирование |
| Вложения | Список файлов, размеры, операции и состояние лимита |

Флаг защищённого атрибута управляет отображением, поиском и обращением с буфером. Остальные поля БД также шифруются в файле.

##### Вкладка «Вид»

- Иконка: уже загруженный favicon, Lucide Icons, загрузка по URL или выбор файла.
- Основной цвет.
- Цвет фона.

Пользовательские изображения ограничены **1 МиБ** и сохраняются внутри БД. Загрузка favicon и изображений выполняется только по явному действию; открытие или выбор записи сами по себе не запускают сетевые запросы за иконками.

##### Вкладка «Свойства»

Значения доступны только для чтения и копирования.

| Поле | Описание |
| --- | --- |
| Создание | Время создания объекта |
| Изменение | Время изменения текущей версии |
| Доступ | Последнее раскрытие или копирование секрета на этом устройстве |
| ID | Идентификатор объекта |

«Доступ» хранится локально, не синхронизируется и не создаёт версию записи.

##### Вкладка «История»

Таблица сохранённых версий с просмотром изменений, восстановлением и явной очисткой. Пароли и защищённые атрибуты в истории скрыты до явного раскрытия. История содержит данные предыдущих версий, а не только текстовый журнал действий.

Сравнение и восстановление относятся к выбранной версии и расположены общими командами под таблицей. Очистка истории доступна через видимое меню действий. Если при восстановлении или очистке есть несохранённые правки записи, сначала показывается «Сохранить / Не сохранять / Остаться». При успешном сохранении либо отказе от правок продолжается действие с историей и его собственное подтверждение; «Остаться» и ошибка сохранения прекращают переход. Сравнение не требует отказа от черновика. Восстановление создаёт новую текущую версию по общим правилам истории.

#### Навигация на Android

Используются последовательные экраны:

1. Выбор БД и список групп.
2. Записи выбранной группы.
3. Карточка записи.
4. Отдельный экран создания или редактирования.

«Назад» возвращает на предыдущий уровень. Действия контекстного меню доступны через меню и долгое нажатие; перемещение не требует мыши или правого клика. Поля, вкладки и правила сохранения соответствуют macOS.

В дереве групп стрелка раскрывает или сворачивает подгруппы, а нажатие на название открывает собственные записи группы. Пять вкладок записи расположены в одной горизонтально прокручиваемой полосе.

Пустая БД показывает «Добавить группу». После её создания и выбора доступно создание первой записи. Поиск по текущей или всем разблокированным БД доступен также на Android.

### 4. Генератор пароля

Открывается иконкой игральной кости справа от поля пароля при создании или редактировании записи: модальное окно на macOS, соответствующий экран или модальное представление на Android. Иконка имеет доступное имя и подсказку «Генератор пароля». Круговые стрелки оставлены для синхронизации, а не для генерации.

В модалке нет текстового заголовка: первым идёт поле результата. Справа внутри поля — показ/скрытие, снаружи — иконки генерации и копирования. Под результатом видны шкала качества и три блока на всю её ширину: оценка слева, количество символов по центру, энтропия в битах справа. Далее расположены вкладки, длина и наборы символов. Смысл качества передаётся и текстом, и шкалой, а не только цветом.

#### Верхняя панель

- Текущее сгенерированное значение.
- Показ/скрытие.
- Повторная генерация.
- Копирование по общим правилам буфера.
- Индикатор качества, число символов и энтропия сгенерированного значения.

Кнопка **«Использовать»** вставляет результат в редактируемое поле и закрывает генератор. **«Закрыть»** закрывает его без замены исходного значения.

#### Вкладка «Пароль»

| Элемент | Правило |
| --- | --- |
| Длина | Ползунок и числовое поле, 1–256 символов; по умолчанию 30 |
| A–Z | Латинские заглавные; включены по умолчанию |
| a–z | Латинские строчные; включены по умолчанию |
| 0–9 | Цифры; включены по умолчанию |
| Спецсимволы | Печатная ASCII-пунктуация; включена по умолчанию |
| Дополнительно | Исключение похожих символов и заданных пользователем символов |

Спецсимволы — ASCII-пунктуация в диапазонах U+0021–U+002F, U+003A–U+0040, U+005B–U+0060 и U+007B–U+007E. Пробел и управляющие символы в эти наборы не входят. Кнопки «Расширенный ASCII» в первом релизе нет.

Выбранные наборы формируют общий алфавит после исключений; само включение набора не обещает хотя бы одного символа из него в каждом результате. При пустом итоговом алфавите генерация и «Использовать» недоступны, показывается объяснение.

Активные наборы подсвечиваются. Изменение длины, наборов или исключений автоматически создаёт новый пароль и обновляет показатели.

#### Вкладка «Парольная фраза»

| Параметр | Правило |
| --- | --- |
| Словарь | Встроенный английский EFF Long Wordlist |
| Количество слов | 3–20; по умолчанию 6 |
| Разделитель по умолчанию | Дефис |
| Работа без сети | Обязательна; язык интерфейса не меняет словарь |

Слова выбираются независимо и равномерно; повтор слова допустим. Генерация паролей и фраз использует криптографический источник случайности.

Для равномерного выбора символов энтропия рассчитывается как L × log₂(N), где L — длина, N — размер итогового алфавита. Пароль из 30 символов при всех четырёх наборах без исключений (94 символа) даёт около 196,64 бит. Для фразы из W независимых слов — W × log₂(D), где D — размер словаря. Для EFF Long Wordlist из 7776 слов фраза из 6 слов даёт около 77,55 бит. Фиксированный разделитель дополнительной энтропии не добавляет.

Расчёт для известного генератора отделяется от оценки качества введённого вручную пароля: одному лишь набору символов ручного пароля нельзя приписывать случайность.

Источник словаря и атрибуция: [EFF Long Wordlist](https://www.eff.org/files/2016/07/18/eff_large_wordlist.txt), [описание](https://www.eff.org/deeplinks/2016/07/new-wordlists-random-passphrases), [условия использования EFF](https://www.eff.org/copyright).

### 5. Настройки и состояние синхронизации

Из открытой БД доступны настройки, ручная блокировка, список устройств и состояние обмена. Состояние различает ожидание пира, соединение, передачу, получение зашифрованных данных, необходимость разблокировки для применения, конфликты и ошибку.

Настройки находятся на одном экране с разделами **«Устройство»** и **«База данных»**. В разделе общих параметров явно указана выбранная БД. Обычное устройство видит ограничения своей роли и название управляющего устройства.

Иконка настроек доступна также на приветственном экране и при заблокированных БД: выбор темы в разделе «Устройство» не требует открытия или разблокировки БД. Это не открывает доступ к защищённым параметрам БД.

Параметры устройства применяются сразу: Select и Switch — по выбору, имя устройства — по Enter или завершению ввода. Общей кнопки «Сохранить» в этом разделе нет. При ошибке введённое значение остаётся в поле, рядом показывается причина; новое значение не считается применённым. Это правило не отменяет отдельные подтверждения операций над БД и параметрами безопасности.

Меню БД также открывает корзину, разбор конфликтов, экспорт KDBX, сохранение копии .taypeer и восстановление резервного снимка. Это обеспечивает доступ к восстановлению и переносу данных независимо от выбранной группы.

| Настройки БД | Настройки устройства |
| --- | --- |
| Название и описание | Язык интерфейса |
| Общий мастер-пароль и параметры защиты | Вид, сортировка и колонки таблицы |
| Управляющее и доверенные устройства | Таймер автоблокировки |
| Общие лимиты вложений | Биометрия для локальной БД |
| | Тема: «Системная / Светлая / Тёмная»; по умолчанию системная |
| | Таймер очистки буфера и «Не очищать» |
| | Выбор общих / собственных relay или их отключение |

Список устройств показывает управляющее устройство, доступность пиров и результат обмена. Административные действия доступны только управляющему устройству.

## Импорт и экспорт KDBX

### Импорт

- Поддерживаются **KDBX 3.1, 4.0 и 4.1**.
- Способы открытия: пароль, обычный ключевой файл или оба компонента. БД только с ключевым файлом также может быть источником импорта.
- Аппаратные ключи, компоненты ключа из плагинов и привязка ключа к учётной записи ОС не поддерживаются в первой версии.
- Импорт всегда создаёт **отдельную БД Taypeer**. Он не вливает данные в существующую БД и не сопоставляет её записи с импортируемыми.
- Для новой БД задаётся непустой мастер-пароль Taypeer. Поддержка key file при импорте не добавляет key file как способ открытия собственных БД Taypeer.
- Перед подтверждением показывается отчёт о переносимых данных, неподдерживаемых возможностях и потерях. Исходный файл не перезаписывается.

### Экспорт

Экспорт создаёт отдельный **KDBX 4.1** с отдельно заданным паролем. Наличие нерешённых конфликтов блокирует экспорт до их разрешения: приложение не выбирает секреты за пользователя и не создаёт конфликтные копии автоматически.

| Данные | Правило переноса |
| --- | --- |
| Группы и обычные поля записи | Перенос поддерживаемой структуры и значений |
| Атрибуты | Перенос значений и признака защиты |
| Вложения | Перенос содержимого и имён |
| Теги, даты и срок действия | Перенос поддерживаемых значений |
| Иконки и цвета | Перенос поддерживаемого оформления; несовпадения отражаются в отчёте |
| История | Сохранённые версии записей, представимые средствами KDBX |
| Корзина | Сохранившиеся группы и записи корзины |
| CRDT-журнал и причинные связи | Не переносятся как история CRDT |
| Доверенные устройства и приватные ключи | Не экспортируются |
| Неразрешённые конфликты | Требуют разрешения до экспорта |

Отчёт показывается до создания итогового файла. Не обещается полный обратимый перенос всех метаданных: идентичность Lucide-иконки, источник её загрузки и неподдерживаемые возможности KeePass могут не иметь эквивалента. Окончательно удалённые данные нельзя восстановить из одних меток удаления KDBX.

Официальные источники: [формат KDBX](https://keepass.info/help/kb/kdbx.html), [KDBX 4.1](https://keepass.info/help/kb/kdbx_4.1.html).

## Критерии приёмки

### Создание, интерфейс и редактирование

- Новая БД не содержит групп; в левой панели есть «Добавить группу», а создание записи недоступно до выбора созданной группы.
- Группы верхнего уровня создаются без видимой корневой папки. Удаление последней группы возвращает пустое состояние.
- На обеих платформах доступны согласованные поля, операции, история и поиск; Android-сценарии не требуют мыши.
- Изменение поля без «Сохранить» не создаёт синхронизируемую версию. «Отмена» не меняет запись.
- Блокировка и повторный вход восстанавливают сохранённый зашифрованный черновик; входящие изменения его не затирают.
- Поиск по всем разблокированным БД показывает источник результата и не включает пароли, защищённые значения или заблокированные БД.
- Клонирование создаёт новые ID и историю, сохраняя текущее содержимое поддерева.

### Тема интерфейса

- На macOS и реальном Android первый запуск следует светлому или тёмному режиму ОС. При недоступном режиме проверяется резерв: последний известный системный, иначе светлый.
- В системном режиме смена ОС в обе стороны обновляет все окна, открытый редактор, диалоги и экран разблокировки без перезапуска, потери ввода, фокуса и навигации. Блокировка БД сохраняется.
- Ручной выбор светлой или тёмной темы игнорирует смену режима ОС; возврат к системному применяет актуальный режим. После возвращения из фона тема соответствует выбранному правилу, включая заблокированную на Android БД.
- Выбор темы доступен до открытия и разблокировки БД, сохраняется между запусками, одинаков для всех БД и окон устройства и не переносится при копировании или синхронизации БД.
- Встроенный TOML содержит полный одинаковый набор ролей в `light` и `dark`. В обеих палитрах на en/ru проверяются читаемость текста, видимость фокуса, различимость выделения и состояний элементов. Явные цвета записей не изменяются.
- Пользовательские переопределения и редактор цветов проверяются при их будущей реализации; они не входят в приёмку первой версии.

### Конфликты и обмен

- Правки разных полей объединяются; разные офлайн-пароли одного поля сохраняются вариантами и требуют выбора.
- При конфликте удаления и редактирования данные остаются в корзине и доступны для разбора.
- Конкурирующие перемещения не теряют объекты и не создают циклическое отображение.
- Заблокированное устройство получает и пересылает зашифрованные данные без раскрытия содержимого; применение происходит после входа.
- Прерывание и повтор обмена не создают дубликатов. Если пирам не удалось встретиться онлайн, локальная работа продолжается с явным ожиданием синхронизации.
- Фоновые ограничения Android и завершение процесса корректно прерывают сессию; возобновление не предполагает непрерывную работу процесса.
- Проверяются прямой обмен, работа через разрешённый relay и отсутствие связи при запрещённом relay и недоступном прямом соединении.

### Допуск и защита

- Новое устройство требует действующего приглашения, подтверждения управляющего и мастер-пароля для чтения.
- Просроченное, использованное или отклонённое приглашение не даёт допуска.
- Смена пароля и отзыв требуют новой разблокировки оставшихся устройств после получения нового состояния.
- Получившее отзыв устройство не применяет автоматически последующие изменения от отозванного пира.
- Передача управления оставляет одного управляющего. Потеря управляющего восстанавливается через новый доверенный набор без автоматического переноса старых допусков.
- Файл с паролем позволяет восстановить чтение на новом устройстве; без пароля и работающей биометрии обходного восстановления нет.
- При блокировке не остаётся открытого документа и ключей чтения; фоновый обмен не получает эти ключи ради удобства синхронизации.
- Проверяются 30-секундный таймер буфера, пользовательский интервал, «Не очищать», чужое последующее копирование и отсутствие доступа к буферу Android в фоне.

### Файлы, объём и совместимость

- Для стабильных версий проверяются цепочки миграций, чтение старых файлов новым приложением и сохранность неизвестных полей при совместимой записи. Неподдерживаемое чтение/запись не приводит к перезаписи исходника.
- Несовместимая миграция требует управляющего, разблокировки и исходной копии; повтор и сбой не дублируют данные и не уничтожают исправное состояние. Старые офлайн-правки сохраняются во время ожидания управляющего и проходят проверку происхождения, схемы и конфликтов.
- Получение зашифрованных данных проверяется отдельно от поддержки схемы для чтения/применения. Старое приложение не подтверждает неподдерживаемый или ненадёжно сохранённый обмен.
- Проверяются очистка без возврата данных при повторной доставке, отдельный разбор правок окончательно очищенного объекта и удержание бинарных объектов, нужных конфликтам и неприменённым источникам. Автоматическое объединение и техническая миграция не добавляют строки пользовательской истории.
- Ошибки записи, нехватка места, потеря доступа, прерывание сохранения и повреждение файла не уничтожают предыдущую исправную копию и не показываются как успех.
- На Android открытие создаёт внутреннюю рабочую копию, а исходный файл изменяется только по явному действию пользователя.
- Восстановление зашифрованного снимка возвращает выбранное состояние; очистка рабочей истории не выдаётся за удаление старых резервных копий.
- Проверяются лимиты одного файла и суммы с учётом истории, корзины и повторного использования одинакового содержимого.
- Объединение допустимых офлайн-вложений сохраняет данные при превышении общей суммы и запрещает новые добавления; нехватка физического места оставляет обмен незавершённым.
- Генератор соблюдает диапазоны, наборы и исключения; пустой алфавит обрабатывается явно. Расчёт энтропии соответствует выбранному способу генерации.
- Импорт проверяется на KDBX 3.1/4.0/4.1 с паролем, ключевым файлом и обоими, включая поля, вложения, историю, корзину и неподдерживаемые возможности.
- Экспорт KDBX 4.1 проверяется открытием в KeePassXC и сравнением обещанных переносимых данных. При конфликтах экспорт блокируется, при неподдерживаемых метаданных показывается отчёт.
- Выпускаемые сборки устанавливаются на целевых macOS и Android; интерфейс проверяется на en и ru.
