# Точка продолжения — 2026-10-08

Android использует ручной Save, обязательную группу записи и dev7 / bridge v3.
Текущая расширенная работа включает соответствие FIG, camera QR, сетевые и
платформенные regression-сценарии. Команды продолжения находятся в
[QA runbook](../../docs/android-testing.md), актуальные результаты и отказы —
в [testing](../../docs/testing.md). Прежние восемь Compose-сценариев ниже
сохраняют своё историческое значение и не заменяют новую полную матрицу.

## Реализованный срез

- Настоящий DocumentService над общим runtime/services, отдельные descriptor
  ciphertext callbacks и общий независимый supervisor. Isolated UID не открывает
  host-пути, не использует Keystore или сеть и не получает plaintext документ
  через host open_local.
- Bridge version 3: типизированные команды и masked views. Catalog/create/import,
  unlock, обязательные группы записей, поиск, пять вкладок записи, encrypted
  local forms, Save/Cancel, «Сохранить / Не сохранять / Остаться», exact snapshot
  retry и типизированный `InvalidInput`. История, restore/purge, trash/Undo,
  Lucide/tags/RGBA используют общий Rust-контракт.
- Общий P2P host: public enrollment proofs из isolated worker, подтверждение
  управляющим, приём при блокировке и применение после разблокировки, явная тихая
  foreground-сессия и bounded JobScheduler periods.
- Отдельные выбранные SAF-потоки вложений: bounded Binder chunks, Rust quota,
  encrypted BlobStore и explicit durable export. Reopen, retained history,
  ошибки источника/замены и точный export проверены через настоящий worker.
- Немедленная блокировка при уходе в фон, очистка UI и generation/input fences.
  Возвращение из SAF требует новой аутентификации и точного связывания выбора
  с прежней БД/формой. Секреты не входят в saved state.
- CameraX/ZXing распознаёт QR локально и заполняет временную форму приглашения;
  подключение требует отдельного действия. Отказ разрешения оставляет ручной ввод.
- Native Host хранит relay, idle и clipboard policy. Сравнение истории, свойства
  выбранной версии, поздние источники и exact intent retry используют общие команды.

## Расширенная Android-проверка — работа продолжается

Первоначальные 103-сценарные прогоны выявили отказы. Следующая сборка имени
устройства прошла сетевые / shutdown проверки, но полная матрица ещё содержала
ошибки fixtures. Их исправленные целевые повторы и новая интеграция изображений
описаны в testing. Последний bounded smoke прошёл 17/17 на каждом из API31,
API36 и API36-16КиБ. Новый eager70 дошёл до всех clone-команд, затем FAIL при
обновлении overview. Найдено повторное декодирование history при проекции;
два causal query regression прошли после оптимизации. Проверенная PUBLIC БД
из 70 записей включена в fixtures; её read-only service audit проходит по умолчанию.
Новый Android eager70 использует этот corpus, проверяет все 70 видимых строк,
ограничение 64 previews, eviction/revisit, Native pixels и неизменность ciphertext;
пока нужен Android-прогон. Covered Parent + Access host build
успешен; API31 targeted repeat подтверждает 21/21, API36 draw/search — 2/2.
Расширенный API36 covered regression завершён: 153/154 passed, один отказ старого
типа ошибки credential corruption. Ожидание исправлено, новый APK-повтор нужен.
Eager70 и отдельный camera-denial stage не входили в этот выбранный набор.
После новых source checkpoint нужны полный прогон, три образа и свежая visual matrix.

Root координирует сборки, общий check и процессы эмуляторов. При продолжении
не запускать две instrumentation на одном serial, не сбрасывать общий ADB,
не заменять reviewed baseline автоматически. Тестировать только PUBLIC fixtures.
JaCoCo исключение product-классов с `R` исправлено и проверяется class-ID guard.
84,21% строк / 59,74% ветвей относятся к валидному frozen Parent/Access APK9ed
и его expanded API36 прогону; новые Recovery/Handoff/SAF/Bio требуют нового отчёта.
82,5% / 58,3% остаются исторической метрикой APK имени устройства.
Смешанные LLVM отчёты изображений недействительны;
после заморозки Rust нужен один чистый coverage-прогон.

## Текущая интеграция bridge v3

Android build/lint/APK-проверка прошла. Через реальный Rust worker проверены
group-first, отсутствие записи до Save, точная ревизия нажатия с более поздним
вводом, Save/Cancel и выбор при Back, невалидная форма, encrypted resume после
ухода в фон, вкладки/атрибуты/генератор и SAF без неявной записи.

Первый прогон `DocumentUiTest` дал шесть успешных сценариев и два отказа тестовых
assertions. Исправлены ожидание асинхронного inspector и неоднозначный селектор
текста drawer; точечный повтор дал 2/2. Изменения приложения не потребовались.
Эти результаты относятся к начальной интеграции ручного сохранения;
состояние расширенного полного набора описано выше.

## Историческая интеграция bridge v2

API 31: 8/8 Compose-сценариев. API 36 и API 36 с 16-КиБ страницами: подтверждён
весь набор из 31 платформенной проверки, включая P2P трёх реплик, вложения и отмену
открывающегося worker при блокировке. Android build/lint/ELF/ZIP и release manifest
проверены. Native bridge, платформенные адаптеры и UI зафиксированы отдельными
коммитами. Общий `scripts/check.sh` и текущие чекбоксы — в основном плане.

## Отдельные открытые условия

Физический ARM64 Android 12+, IME/TalkBack, оптическое сканирование камерой,
проверка памяти и OEM lifecycle остаются отдельными условиями.
Recovery и двусторонняя передача управления реализованы в исходниках; новые
7 Recovery и 8 Management Android-сценариев ещё требуют сборки и запуска.
Ciphertext Save a copy прошёл 11 Rust/Native-сценариев (2 storage, 4 runtime,
5 Native); Kotlin SAF интеграция и её Android-сценарии проверяются отдельно.
Биометрия пока не подключена полностью к managed worker/UI. Отдельный PUBLIC
стенд с настоящими OS CryptoObject/JNI прошёл 12/12 на API36 с 16-КиБ страницами,
включая Rust OAEP→OS→32-byte pipe. API31 ранняя отмена prompt остаётся FAIL;
отдельная отмена после rejected finger прошла 1/1, последовательный набор выявляет
нестабильную очистку OS request. Isolated UID читает granted FIFO напрямую,
но `/proc/self/fd` reopen возвращает EACCES; нужен проверенный прямой safe dup.
Имя устройства и пользовательские изображения реализованы с промежуточными
Android-доказательствами. Parent и Access реализованы, shared проверки пройдены,
новая полная Android-матрица ещё не проверена. Новые source checkpoints требуют
свежих APK hashes, visual matrix и покрытия; frozen Parent/Access доказательства
не распространяются на них.
Оптимизированная release-сборка требует собственной проверки после изменений;
эмулятор не подтверждает аппаратную приёмку. Полный список — в
[roadmap](../../docs/roadmap.md).

KeePass, автобэкапы и восстановление резервных снимков в релиз не входят.
Обычная навигация с изменениями требует явного выбора; блокировка не ждёт этого
выбора. Автоматическое продолжение локальной формы и история остаются отдельными
сценариями. До закрытия аппаратной и криптографической приёмки используются только
публичные искусственные данные. SDK, bindings, .so, APK и локальные логи не
включаются в Git.
