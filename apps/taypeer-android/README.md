# Taypeer Android

Продуктовый Android-проект `dev.taypeer`, Android 12+ / ARM64. Каталог, создание,
импорт, разблокировка, документный редактор и история используют общий Rust
runtime. Записи, группы и название/описание БД сохраняются кнопкой.
Незавершённые локальные формы продолжаются после повторной разблокировки.
Текущая работа и открытые условия — в [roadmap](../../docs/roadmap.md#android-оставшиеся-проверки).

Сборка, network/full suites, virtual camera и визуальные regression snapshots
без физического телефона: [Android QA runbook](../../docs/android-testing.md).

## Ручное сохранение и группы

Новая БД не содержит готовой группы. Сначала пользователь создаёт и сохраняет
группу; новая запись требует её явного выбора. «Все записи» остаётся общим
списком записей из групп. Отдельных записей и фильтра «Без группы» нет.

Save подтверждает только захваченную ревизию формы. Обычный успех закрывает
редактор; ввод, поступивший после нажатия, остаётся в нём несохранённым.
Атрибуты, оформление, вложения и смена вкладок не подтверждают запись.
Cancel удаляет только текущую локальную форму. Переход между объектами и Back
предлагают «Сохранить / Не сохранять / Остаться». Невалидная форма возвращает
типизированный `InvalidInput`; ошибка Save не разрешает переход.

Блокировка и уход в фон немедленно отзывают доступ без диалога и не подтверждают
несохранённую форму в БД. Уже начатый Save может завершить commit после отзыва;
его результат сверяется общим сервисом. Зашифрованные локальные формы сохраняются
отдельно от документа.
Генератор и SAF picker также не подтверждают запись. Перед SAF закрепляется
точная локальная форма; после нового unlock результат применяется лишь явным
действием к той же БД и DraftId. Последующий Save подтверждает все поля формы.

`DocumentUiTest` проверяет это поведение через настоящий isolated worker и
сохранённые ciphertext-файлы. Runner сохраняет результаты отдельно для API 31
с 4-КиБ страницами и API 36 с 16-КиБ страницами; успешный частичный сценарий
не означает успешный полный набор. Актуальные результаты и ограничения — в
[testing.md](../../docs/testing.md); результаты прежнего bridge v2
не подтверждают текущий срез схемы 1 и переносимых credentials.

## Граница UniFFI

`native/` — отдельный crate основного Cargo workspace. Только он зависит от
UniFFI: типизированные DTO, ошибки, callbacks и преобразования. Общие crates
не зависят от Kotlin/Compose/UniFFI. Генератор вызывает общий сервис; проверка
импортируемого файла использует `RuntimeHost::inspect_compatibility`.
`Host` подключает защищённые credentials и остаётся владельцем ciphertext-runtime.
Его создание не разблокирует БД. Мастер-пароль в credential store не передаётся.

`DocumentService` — непубличный isolated service, обслуживающий ровно одно поколение
открытой БД. Общий supervisor получает независимый локальный Binder death observer
и очередь принудительного завершения, отдельно от занятых командных pipe.
Snapshot, commit и encrypted local forms передаются ограниченными descriptor
leases. Worker расшифровывает авторский credential после аутентификации точного
immutable snapshot и проверки текущих полномочий. Host передаёт ограниченный
ciphertext credential и не получает author/ReadKey через Binder.
Desktop spool paths и `open_local` не используются в качестве обходного пути.
Смерть host завершает isolated процесс через Binder death recipient.

UniFFI bridge version 3 экспортирует предметные DTO и команды, включая идентичность
БД, поколения, формы, её ревизии и операции. Приватные JSON-кадры остаются деталью
runtime, универсального публичного API документа нет. Выбранные пользователем
вложения имеют отдельный потоковый Binder-порт, не смешанный с ciphertext I/O.
Каждая порция ограничена 64 КиБ; plaintext временные файлы не создаются.
Создание записи принимает обязательную группу, редактирование — ID записи;
DTO записи также содержит обязательную группу. `save` возвращает только
`Saved` или `Unchanged`; сохранение локальной формы имеет отдельную команду.
Текущие instrumentation assets берутся из публичного stable1-корпуса;
eager70 использует отдельный [синтетический набор](../../tests/fixtures/android-eager-icons-stable1/README.md).

Продуктовый `Host.portableWithOsBiometry` создаёт новый профиль `profiles/portable-v1`.
Основные credentials зашифрованы ключом эпохи БД общим Rust codec; обычный вход
не требует Android Keystore. Старые профили не читаются и не мигрируются.
`KeystoreCredentials` сохранён для явных legacy/test API, а необязательные
биометрия и HMAC буфера остаются отдельными OS-механизмами.
Физическое затирание копий JVM/FFI этим не доказывается.

Импорт читает SAF только на вход, проверяет внутренний staging-файл общим Rust
reader, затем публикует новую рабочую копию без перезаписи существующей. Частичный
поток и неверный формат не попадают в каталог. Каталог публикуется после успешной
аутентификации worker; импорт не даёт сетевого допуска и сохраняет источник.
Создание и P2P-получение используют внутренние рабочие копии без выбора директории.

Получение ciphertext отделено от применения после разблокировки. Длительный
обмен включается явно через foreground service с тихим обязательным уведомлением;
короткие периоды используют JobScheduler и общую Rust-логику обмена. Kotlin не
создаёт второй протокол допуска или синхронизации. Уход приложения в фон немедленно
отзывает доступ и очищает UI, даже если выполняется команда. Возвращение из SAF
требует новой разблокировки; выбранное вложение привязывается к той же БД и точной
форме новым явным действием, а не запоздавшим callback прежней сессии.

Буфер хранит несекретную квитанцию (случайная метка, HMAC и сроки). HMAC-ключ
неэкспортируемый в Keystore; простой хеш пароля не сохраняется. Проверка владения
повторяется после получения фокуса; чужое значение не удаляется. Очистка UI и
флаг `FLAG_SECURE` не заменяют проверку памяти.

## Сборка

Требуются Rust из корневого `rust-toolchain.toml`, target `aarch64-linux-android`,
JDK 17, SDK platform 35, build-tools 35.0.0, NDK 27.2.12479018.
Версии Gradle/AGP/Kotlin/UniFFI взяты из принятого Compose-spike. Wrapper проверяет
SHA-256 дистрибутива Gradle. Исторический spike не изменяется.

JNA обновлена отдельно до 5.17.0: 5.16.0 проходит ELF/ZIP-проверку выравнивания,
но падает в `JNI_OnLoad` на API 36 с 16-КиБ страницами. Исправление описано
в [истории JNA](https://github.com/java-native-access/jna/blob/5.17.0/CHANGES.md).

```sh
rtk proxy rustup target add aarch64-linux-android
rtk proxy python3 -m pip install -r apps/taypeer-android/requirements-qa.txt
rtk proxy sh apps/taypeer-android/check.sh
```

`ANDROID_HOME` задаёт установленный SDK; по умолчанию используется `.tools/android-sdk`
в этом проекте. `GRADLE_USER_HOME` по умолчанию также локален `.tools/`.
Variant build собирает Rust, генерирует Kotlin тем же UniFFI 0.29.4 и собирает
ARM64 библиотеку. Debug/release имеют отдельные bindings/JNI directories;
debug включает ограниченный test-support hook для локального TLS fixture,
release использует Rust release profile без этого feature. Cargo использует
общий lockfile. Генерируемые bindings, `.so`, SDK, кеши и APK игнорируются Git.
JVM-сценарии проверяют QR decoder/frame analysis; платформенное поведение
проверяют instrumentation-тесты.

Обычная сборка использует `app/gradle.lockfile`, `-PqaCoverage=true` —
`app/gradle-coverage.lockfile`: coverage добавляет JaCoCo agent в runtime graph.
Оба графа закреплены; обычный APK не содержит неиспользуемый coverage agent.

Артефакты:

- `app/build/outputs/apk/debug/app-debug.apk`
- `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`
- `app/build/reports/lint-results-debug.html`

Проверка ELF всех `.so` и `zipalign -P 16` входит в `check.sh`. Выравнивание файла
не заменяет запуск на 16-КиБ образе.

Для запуска instrumentation на уже запущенном ARM64 AVD:

```sh
rtk proxy python3 apps/taypeer-android/qa.py test --serial emulator-5556 --suite full --authorize-public-biometry
```

Номер выделенного PUBLIC AVD выбирается явно. `full` включает отдельные стадии
отказа камеры и биометрии; флаг разрешает настройку тестового PIN/finger
с проверяемым восстановлением исходной блокировки. `qa.py` собирает APK
и подготавливает локальный TLS relay для offline/restart P2P-теста.
Обычный `connectedDebugAndroidTest` не передаёт обязательные fixture-аргументы.

Для release задаются `TAYPEER_ANDROID_KEYSTORE` (вне репозитория),
`TAYPEER_ANDROID_STORE_PASSWORD`, `TAYPEER_ANDROID_KEY_ALIAS`,
`TAYPEER_ANDROID_KEY_PASSWORD`, затем `:app:assembleRelease`. Без этих параметров
release остаётся unsigned; debug key не становится ключом выпуска.
Это подготовка конфигурации подписи. Подписанная release-сборка требует внешнего
ключа и отдельной проверки выпуска.

## Матрица реализации

Это состав текущего кода, а не отметка прохождения полной Android-приёмки.
Результаты каждого APK и образа фиксируются отдельно в [testing](../../docs/testing.md).

| Область | Текущий статус |
| --- | --- |
| Gradle → Rust ARM64 → Kotlin bindings | Реализовано |
| Отдельный UniFFI-crate, общий TOML, en/ru | Реализовано |
| Keystore credentials, проверяемый импорт ciphertext | Подключены к host, каталогу и SAF UI; без plaintext fallback |
| Isolated Service / смерть host / отдельный процесс | Настоящий документный worker, общий supervisor, независимый Binder death control |
| Дескрипторы и ciphertext staging | Реальный архив проверяется Rust внутри isolated UID; временные файлы приходят через Binder, позиционное I/O без путей |
| Генератор Compose → Rust, очистка UI, буфер | Пароли/фразы, параметры генерации, форма в памяти и блокировка результата |
| Несколько БД и поиск | DocumentManager удерживает отдельные OPEN-workers; поиск по выбранной или всем разблокированным БД вызывает общие Rust-команды |
| Каталог, создание, разблокировка, группы и записи | Подключены к общему Rust runtime |
| Drawer, список, пять вкладок, формы | Собственные записи выбранной группы, поиск, явный Save, Save / Discard / Stay, независимые зашифрованные локальные формы |
| История и сравнение | Маскированные версии, restore/purge, сохранённая и текущая стороны; отдельное раскрытие/копирование каждой стороны |
| Корзина, клонирование и перемещение | Общие команды записей/групп, явное назначение, восстановление и подтверждаемая окончательная очистка |
| Оформление и свойства | Bundled Lucide, RGBA, tags, timestamps и срок действия; локальные изображения, явная URL/favicon-загрузка, групповые favicon и рендер изображений |
| Вложения и SAF-return | Ограниченные выбранные потоки, общий черновик, история и экспорт; возврат связывается с точной формой после новой аутентификации |
| Внешняя копия БД | Host захватывает зашифрованный архив; SAF выбирает внешний output, успех требует завершения записи; рабочая копия и черновики не меняются |
| Управление и восстановление | Смена пароля/отзыв, двусторонний handoff с exact retry и восстановление отдельного доверенного набора подключены к UI/runtime |
| Биометрия | Scoped enrollment/disable и keyed unlock через OS CryptoObject, приватный Native FD и isolated worker; отмена оставляет мастер-пароль |
| Защита и лимиты | Числовая проекция Argon2id/расхода, фактическое время password KDF, явная калибровка и подтверждаемое применение общей политики |
| Родитель группы и время обращения | Parent входит в общий черновик; успешное использование сохранённого секрета подтверждается отдельным локальным Access grant |
| Приглашения, direct/relay, JobScheduler и foreground exchange | Общий host, публичные/собственные/отключённые relay; ciphertext-приём и применение различаются, incoming application обновляет список и inspector |
| Поздние и непринятые источники | Раздельные типизированные команды inspection/reveal/extraction; новое извлечение не открывает закрытую generation и не выдаёт допуск |
| Настройки устройства | System/light/dark, en/ru; Rust загружает и сохраняет idle/clipboard policy, включая произвольные положительные секунды и «Не очищать» |
| QR камеры | CameraX lifecycle + локальный ZXing; результат заполняет приглашение, допуск начинается после явного действия |

| Настоящее устройство, память и криптографическая приёмка | Открыто; эмулятор не закрывает эти условия |

Сравнение читает маскированную сохранённую версию и текущую проекцию; входящее
применение обновляет текущую сторону. Оно не создаёт версии и не меняет черновик.
Раскрытие и копирование каждой стороны — независимые действия; смена версии,
потеря фокуса, закрытие и блокировка отзывают ожидающие защищённые ответы.
Restore подтверждённой версии сохраняет ID записи и добавляет версию истории
в явно выбранной группе. Clone создаёт новый ID без прежней истории. Повтор
неопределённого Restore использует прежние revision/destination/OperationId и
не откатывает более позднее независимое перемещение.
`revisionProperties` читает tags, expiry, appearance и timestamps точной сохранённой
EntryView; текущие и исторические свойства используют один DTO mapping.

`pendingSources` — поздние события уже аутентифицированной истории окончательно
закрытой generation записи/группы. Их исходные варианты остаются маскированными;
раскрытие требует точных origins, `recoverPending` создаёт новый объект.
`receivedSources` — проверенные исходные changes, не принятые в рабочую проекцию:
просмотр не объединяет их, discard задаёт локальное решение, `extractReceived`
создаёт выбранную запись в явной активной группе. Оба пути не восстанавливают
сетевой допуск. При потерянном ответе повтор сохраняет source, destination,
выбранную запись и прежний OperationId; уход из слоя и lock/reopen не означают
нового запроса или подтверждённого успеха.

Idle/clipboard policy принадлежит native Host и загружается до первого копирования.
Kotlin показывает подтверждённый applied view. Повреждённый файл не заменяется
defaults; неподтверждённая запись не показывается применённой. Clipboard очищается
по владению; отказ камеры сохраняет ручной ввод приглашения.

### Границы подтверждённой готовности

Код подключает перечисленные возможности; это не результат нового полного
прогона. [Датированные результаты](../../docs/testing.md) связывают каждый
успех и отказ с точными APK и образами. После изменения исходников нужны новые
APK hashes, полный набор трёх AVD, visual matrix и согласованный coverage.
Предыдущие frozen Parent/Access результаты не подтверждают новые возможности.

Продуктовые включение/разблокировка/отключение биометрии, отмена и background
прошли целевой набор 6/6 на отдельном frozen APK. Текущие исходники отличаются
от его capture; новая матрица остаётся открытой. Новые recovery/handoff,
поиск по нескольким БД, изображения/eager70, parent/Access, защита/лимиты
и SAF-копия оцениваются по своим результатам в testing, без переноса успеха
с соседних Rust-сценариев. Настоящий picker и OEM/provider durability
остаются отдельными условиями.

Физическая камера, Keystore/биометрия, IME/TalkBack, системные жесты, OEM фон,
power-cut и проверка памяти остаются отдельной платформенной матрицей.
Обязательного разбора конфликтов нет: общая детерминированная проекция выбирает
значения, альтернативы доступны в истории.
KeePass, автобэкапы и восстановление резервных снимков исключены из релиза.
До закрытия аппаратной и криптографической приёмки используются только публичные
искусственные данные.

Основания платформенной границы: [Android isolated binding](https://developer.android.com/reference/android/content/Context#bindIsolatedService(android.content.Intent,int,java.lang.String,java.util.concurrent.Executor,android.content.ServiceConnection)),
[Keystore](https://developer.android.com/privacy-and-security/keystore),
[файловые операции](https://developer.android.com/reference/android/system/Os).
