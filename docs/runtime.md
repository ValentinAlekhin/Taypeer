# Общий Rust runtime

Desktop и Android вызывают общие Rust-сценарии. Пользовательский CLI удалён;
частный протокол процесса БД не является внешним API. Точные контракты данных,
хранения, сессий и обмена принадлежат [модели данных](data-model.md),
[хранилищу](storage.md), [сессиям](sessions.md) и [P2P](p2p.md).

## Профиль и процесс БД

`RuntimeHost` владеет профилем, внутренним каталогом и рабочими путями.
Default desktop-профиля: macOS — `~/Library/Application Support/Taypeer/profiles/portable-v1`,
Linux — `$XDG_DATA_HOME/taypeer/profiles/portable-v1` с системным fallback.
Существующие профили автоматически не перемещаются и не объединяются.
Новый public-профиль версии 2 не открывает старый системный credential backend.
Первая аутентификация активирует независимый контекст своей БД; мастер-пароль
или авторский ключ не возвращаются host. Общий формат credentials описан в
[storage](storage.md#переносимые-локальные-credentials-и-независимое-состояние).

Локальное имя устройства проверяется общим Rust-типом: непустое после проверки
пробельных символов, не более 256 байт UTF-8; исходный ввод сохраняется без
обрезки или нормализации. Только отсутствие настройки означает `Taypeer` по
умолчанию. Повреждённый, слишком большой или неподдерживаемый файл не заменяется
значением по умолчанию. Android хранит версионированную настройку в профиле;
desktop сохраняет совместимость существующего `device-ui.json`, используя то же
предметное правило.

`Host.setDeviceName` возвращает подтверждённый `DeviceSettingsView` после
атомарной публикации и подтверждения её надёжности. Отказ до публикации не
изменяет применённое значение; неопределённый результат не выдаётся за успех.
Kotlin хранит отдельный черновик и отправляет его по Enter или потере фокуса,
сохраняя ввод и причину при отказе. Поздний ответ не заменяет новый черновик.
Имя используется только в строке локального устройства. Оно не передаётся
сетью, не заменяет публичный ID пира и не подставляется автором истории.

Создание и получение выбирают внутренний путь. Явное открытие внешнего файла
создаёт внутреннюю копию, сохраняя источник и не выдавая новый сетевой допуск.
Регистрация публикуется только после надёжной записи; повтор операции не создаёт
дубликат. Явный перенос рабочей копии сохраняет проверку поколения и квитанцию.

Desktop запускает собственный executable во внутреннем режиме worker;
Android использует изолированную службу. Каждый worker последовательно вызывает
сервис и владеет документом и ключами одной разблокированной БД. Единственный
ciphertext writer сериализует локальные кандидаты и сетевой приём.

Приватный IPC ограничивает длину кадра до выделения памяти. Обычные представления,
поиск и история маскируют секреты; полная сериализация документа и ключи чтения
не возвращаются host. Раскрытие и генерация — отдельные явные команды,
создающие краткоживущие открытые копии. Ошибки и диагностика не раскрывают данные.

### Несколько разблокированных БД и поиск Android

Android сохраняет отдельный OPEN-worker каждой открытой БД,
включая невыбранные БД. `DocumentManager` владеет процессами; выбор активного
источника меняет UI binding, но не закрывает остальные сессии. Повторный выбор
уже открытой копии использует её живой worker и не создаёт второго писателя.
Переход из незавершённой формы сохраняет обычные Save / Discard / Stay guards.

Поиск по умолчанию вызывает существующий Rust `Entries` для текущей БД.
Область «Все разблокированные» опрашивает только реальные OPEN-сессии. Kotlin
не дублирует правила поиска; пароли и защищённые значения исключает сервис.
Каждый результат связан с исходной рабочей копией, БД, группой и поколением.
Preview и открытие карточки используют эту сессию; активный binding другой БД
не разрешает читать объект по совпавшему ID. Возврат восстанавливает исходный
запрос и область, повторно исключая отозванные источники.

Ручная команда Lock закрывает выбранную БД. Потеря доступа удаляет её результаты
и preview немедленно. Android background, сон, системная блокировка и завершение
host отзывают все сессии и очищают все поисковые проекции. Ответ от старого
запроса, поколения или lifecycle epoch не возвращает удалённые результаты.
`DocumentManager.unlockedSources` и общий `SearchState` подключены к UI;
результаты реальных многобазовых сценариев и ограничения их приёмки находятся
в [testing](testing.md).

Сортировка Android принадлежит локальному presentation owner и одинакова для
обычного списка и результатов по всем разблокированным БД. Актуальный sheet
предлагает название по возрастанию (по умолчанию), название по убыванию, логин
по возрастанию и время изменения — новые первыми. `EntryRow.modifiedAt`
передаёт реальное UTC-время изменения из общего masked `EntrySummary` /
`EntryView`, без нового чтения секретов и без подстановки времени доступа.
Пустой или отсутствующий логин идёт последним; равные значения упорядочиваются
по `DatabaseId`, затем `EntryId`. Выбор остаётся связан с ID, а не позицией.
Изменение порядка не вызывает поиск, сетевую команду или запись БД. Выбор
сохраняется в `DocumentState` при смене маршрута, lock и пересоздании Activity;
новый постоянный ключ настройки и порядок общего Runtime не вводятся.

### Предустановки срока записи на Android

Sheet «Срок действия» предлагает бессрочное значение, «Через 30 дней»,
«Через 90 дней» и выбор даты. Чистый Native Rust API
`resolveRelativeExpiry(RelativeExpiryPreset, nowUtcMillis)` вычисляет
абсолютные UTC-миллисекунды: ровно 30 или 90 интервалов по 24 часа.
Расчёт не зависит от локальной зоны, перехода DST или длины календарного дня.
Переполнение `i64` отказывается типизированно и не меняет ввод.

Kotlin считывает UTC-часы один раз при выборе предустановки и передаёт
подтверждённое абсолютное значение существующей адресной правке expiry
активного черновика. Перерисовка, повторное открытие sheet и Save не добавляют
новые дни. Выбор не сохраняет запись немедленно: общий Save создаёт одну
содержательную версию, а Cancel сохраняет прежние ciphertext и историю.
Calendar picker остаётся платформенным вводом абсолютной даты; новые команды
worker, состояние профиля, формат файла или сетевой обмен не вводятся.

### Защита и лимиты БД на Android

Android-экраны защиты и лимитов используют реализованный
[контракт числовой проекции и явной калибровки](android-policy.md).
`PolicyDetails` согласованно читает действующую политику, общий `StorageUsage`,
параметры текущего password header и nullable реальный замер password KDF.
`CalibrateProtection` выполняет ограниченный preview существующего алгоритма
только по действию пользователя и не меняет документ. Применение сохраняет
прежний `SetDatabasePolicy`, права, administrative receipt и durable ACK.
Keyed-open не выдаёт отсутствующую password KDF за выполненную.
`DocumentSession.policyDetails` и `calibrateProtection` подключены к
`PolicyState` и Compose; это не заменяет проверки конкретного APK и KDF
на физическом устройстве.

### Явная внешняя копия зашифрованной БД на Android

Действие «Сохранить копию» подключено к Android UI и host: экспортируется
целый переносимый `.taypeer`, а внутренний рабочий путь и каталог не меняются.
Это отдельная операция от сохранения формы, переноса рабочего файла,
восстановления управления и выгрузки расшифрованного вложения. Она не выдаёт
сетевой допуск и не подтверждает незавершённый Save рабочего документа.

`RuntimeHost.capture_working_copy_export` принимает точную зарегистрированную
`WorkingCopy`, проверяет её совпадение с каталогом и защищённой регистрацией
профиля, `DatabaseId` и pinned root. Другая копия, произвольный путь или
несовпадающий root отказываются до обращения к output. Получение author seed,
разблокировка и создание writer для экспорта не нужны. Зарегистрированная
закрытая копия может быть выбрана тем же явным действием. Ошибка защищённой
регистрации не превращается в отсутствие или разрешение по одному пути.

До запуска SAF захватывается один проверенный `ArchiveSnapshot` со стабильной
ciphertext lease. Непрозрачный `CiphertextExport` владеет только этой lease и
публичной идентичностью: local working-copy ID, `DatabaseId`, root, fingerprint
и точная длина. Incoming или дальнейшее Save не подменяют захваченный источник.
Экспорт копирует существующие байты, включая сохранённую историю, blobs и
переносимые ciphertext sources; локальные настройки, допуски и незавершённые
черновики не добавляются. Новый формат, перешифрование или декодирование
документа для этого действия не вводятся.

Native `Host.captureDatabaseCopy(WorkingCopyView)` возвращает непрозрачный
`EncryptedDatabaseCopy`. `identity()` содержит `DatabaseId`, local working-copy
ID, root, fingerprint и длину байтов без пути или названия. `export(SelectedOutput)`
возвращает только результат завершения, а `cancel()` необратимо отзывает объект.
Отменённая попытка возвращает content-free typed `ExportCancelled`; занятая
попытка возвращает `StorageBusy`. Ошибки выбранного output сохраняют свой
исходный typed вариант, включая `CommitUncertain`.
Экспорт в `SelectedOutput` выполняется host Rust
вне worker и UI thread. Выбранный output не регистрируется в
`SelectedTransfersHost`, чей доступ связан с OPEN worker. SAF `onStop` по
прежнему немедленно блокирует документ; ciphertext-only попытка имеет отдельное
время жизни и не восстанавливает сессию после возвращения. UI хранит только
capture handle, публичный profile/copy/attempt stamp и состояние действия,
не ciphertext buffer или ключ чтения.

Назначение выбирается системным `ACTION_CREATE_DOCUMENT`; display name
`.taypeer` не меняет имя БД внутри контейнера. Output открывается лениво только
для принятой актуальной попытки. Его capability не разрешает открывать рабочий
путь профиля как назначение или автоматически перезаписывать исходник импорта.
Выбранный URI не становится новым рабочим путём и не сохраняется как
автоматическое назначение будущих Save.

Storage копирует точную длину существующими ограниченными буферами в пределах
архивного лимита 16 ГиБ; Android callbacks принимают не более 64 КиБ за вызов.
Фактически скопированные байты сверяются с захваченным fingerprint до
`SelectedOutput.finish`. Неожиданное изменение сохранённого inode, обрезка,
ошибка чтения, нулевая либо недопустимая запись отклоняют результат; `finish`
не вызывается для неполного или изменённого источника. Правила ciphertext и
fingerprint остаются у общего storage, без самостоятельной копии формата в Kotlin.

У каждой попытки не более одного активного output. `cancel` необратимо
отзывает capture и закрывает выбранный output вне ownership lock; отмена не
ждёт блокирующий provider. Проверка отмены выполняется до записи каждого блока,
до и после `finish`. FD, snapshot и временные callbacks освобождаются на всех
ветках. Закрытие при cleanup не является успешным завершением. Отмена,
смена БД/профиля, ручное закрытие действия и поздний callback не дают UI ACK;
обычная блокировка документа при SAF не подменяет этот stamp worker epoch.
После смерти host/capture пользователь начинает новую явную попытку; другая
текущая generation не подставляется под старый pending result.

Успех следует только `finish` выбранного назначения: flush/fsync,
проверке reliable error channel и фактическому final close по контракту
Android provider. Ошибки write/finish/close, включая `CommitUncertain`, не
подменяются успехом. Неподдерживаемое подтверждение не считается надёжной
записью. Отмена или ошибка не доказывают отсутствие частичного либо уже
опубликованного внешнего файла. Прежняя рабочая копия не изменяется; автоматический
повтор, удаление URI или обещание отката назначения отсутствуют. Явный повтор
сохраняет тот же immutable capture при живом owner и выбирает новый output.

Meaningful автоматические проверки: exact encrypted bytes/root/fingerprint
и длина после copy; reopen exported archive с PUBLIC паролем и сохранной
историей/blobs/received inventory; source file, catalog и encrypted draft
неизменны; capture до incoming/Save экспортирует прежнюю generation;
закрытая зарегистрированная копия не запрашивает author; чужой/root-mismatched
источник не открывает output; short/overlong/zero/throwing output и finish/close
fault не дают ACK; изменение retained inode не вызывает finish; cancellation
во время gated I/O и перед/после finish, смена копии, recreation и настоящий SAF
background не оживляют доступ или stale success. Настоящий picker, OEM/cloud
provider durability и физическая приёмка остаются отдельными проверками.

### Локальное время доступа к записи

Отметкой владеет общий host/profile, отдельно для профиля, `DatabaseId` и
`EntryId`. Она не входит в Document, переносимый файл, историю, черновики или
сеть. Android читает nullable UTC-миллисекунды для текущих свойств и свойств
сохранённой версии того же объекта. Отсутствие отметки показывается прочерком;
ошибка или повреждение хранилища не подменяются отсутствием.

Native раскрывает секрет только через существующую проверенную сессию. Для
сохранённого пароля или защищённого атрибута адаптер дополнительно выдаёт
непрозрачное разрешение события, связанное с профилем и выбранным объектом.
Оно не содержит значения секрета и не позволяет Kotlin назначить другой объект
или время. `RevealSavedForAccess` одной последовательной командой worker
проверяет сохранённый объект, выбранную версию и защищённость атрибута перед
раскрытием. Обычный атрибут возвращает `InvalidInput`; прежняя команда раскрытия
сохраняет свой контракт без создания разрешения Access.
Само получение ответа не записывает Access. Android подтверждает
его только после проверки актуального binding, поколения секрета и выбранной
стороны/версии, когда значение реально принято для отображения либо защищённый
буфер подтвердил запись. Ошибка копирования и отклонённый поздний ответ событие
не создают. Обычные поля, незавершённые новые записи, генератор и отдельные
непринятые источники не получают разрешения Access действующей записи.

Общие часы фиксируют точные UTC-миллисекунды принятого события. Порядок событий
не вычисляется через максимум wall-clock: часы могут идти назад. Владелец записи
сериализует попытки и сохраняет точное событие до подтверждения. Повтор старого
разрешения не откатывает более новое событие. Неопределённая публикация сначала
сверяется с защищённой записью; равенство старому кешу не означает подтверждение.

Каждая версионированная запись ограничена лимитом защищённого профиля; она
содержит только идентичность события, объекта, порядок и время. Платформенный
CredentialStore подтверждает надёжную зашифрованную публикацию, сохраняет
различие отсутствия, повреждения и недоступности и передаёт `CommitUncertain`
без превращения в обычный отказ credentials. Раскрытие или копирование, которое
уже произошло, не отменяется ошибкой Access. UI сохраняет прежнюю подтверждённую
отметку и отдельную ошибку локальной записи; секрет автоматически не раскрывается
и не копируется повторно для повтора этой записи.
После принятого действия подтверждение отметки может закончиться после lock:
оно не раскрывает секрет повторно и не возвращает старую проекцию в UI.

## Ручное сохранение и локальные формы

Просмотр, сравнение и exact восстановление сохранённых групп и метаданных БД
описаны в [контракте истории метаданных](metadata-history.md). Их снимки и
Restore-команды остаются типизированными сценариями общего isolated worker.

Записи всегда имеют пользовательскую группу. Создание, клонирование,
перемещение, восстановление версии и извлечение источника требуют действующую
активную группу; верхняя группа может не иметь родителя.

Сервис хранит несколько локальных форм записей, групп и метаданных БД.
Вкладки записи используют одну форму; адресные patches сохраняют исходный
причинный контекст. Неизменённые секретные поля передаются как `Keep`.
Черновики и staged blobs защищены локально и не синхронизируются.

`SaveDraftSnapshot` вызывается только после явного подтверждения пользователя.
Снимок связывает `DraftId`, target, `DraftRevision` и `OperationId`; повтор
точного запроса возвращает прежнюю квитанцию и не создаёт новую историю.
Невалидная изменённая форма возвращает `InvalidInput` до регистрации новой
попытки. Результат — подтверждённая запись БД либо отсутствие изменений;
локальный зашифрованный черновик не является результатом успешного Save.

Команда фиксирует ввод в позиции явного действия в последовательной очереди.
Более поздний ввод остаётся несохранённым. Потерянный ответ повторяет прежний
снимок; неопределённая запись сверяется с рабочим файлом и квитанцией до нового
commit или удаления формы. Подтверждение не заменяет более свежую проекцию.

`PersistDrafts` отдельно сохраняет локальную коллекцию, не подтверждая версию БД.
`DeleteDraft` надёжно удаляет выбранную форму; другие формы остаются доступными.
При уходе из изменённой формы UI предлагает «Сохранить / Не сохранять / Остаться».
Ошибка Save оставляет форму открытой. Уже подтверждённая запись не отменяется
последующим удалением несохранённых правок.

### Родитель в форме группы

`GroupMetadataPatch.parent` использует `Keep`, `Set(GroupId)` и `Clear` для
верхнего уровня. Пропущенное поле означает `Keep`; оно не превращает старую
форму в перенос к корню. Начальный родитель новой группы остаётся частью
`DraftTarget::NewGroup` и её стабильной идентичности. Последующий выбор хранится
отдельно в этой же форме, не создавая новую группу или операцию перемещения.

Сервис показывает родителя и допустимые назначения из причинного контекста
формы. Проверки назначения, поколения объекта, активности и поддерева принадлежат
общему Document и совпадают с проверками `MoveGroup`. Собственная группа,
потомки, удалённые или пересозданные назначения не принимаются. Kotlin отображает
этот выбор, не воспроизводя правила циклов. Назначение повторно проверяется перед
подготовкой кандидата; ошибка сохраняет ввод и не подтверждает часть формы.

Save существующей группы применяет название, описание, значок и адресную правку
родителя в одной транзакции от исходных heads. Она содержит одну историю и одну
квитанцию. Для изменённого родителя используется последнее положение среди
соседей, определённое той же операцией Save. `Keep` или отсутствие фактического
изменения родителя сохраняет существующий порядок. Неправленные конкурентные
значения сохраняются по общим правилам адресных правок.

Локальный `MetadataDraft` хранит необязательное отдельное состояние родителя с
baseline и текущим выбором. Отсутствие этого состояния сохраняет старое typed
JSON-представление и fingerprints уже удерживаемых попыток Save; явный корень
отличается от отсутствия правки. Чтение старого снимка не дополняет его полями.
После ACK baseline обновляется подтверждённым родителем, а ввод, поступивший
после захвата снимка, остаётся в открытой грязной форме.

Повтор сначала проверяет точную удерживаемую попытку и подтверждённую квитанцию,
не выполняя новый перенос. Позднее изменение родителя не откатывается старым
ACK. Неопределённая публикация сохраняет исходные `DraftId`, `DraftRevision`,
`OperationId` и родителя до сверки с файлом; иной запрос под тем же ID отказывается.

## Бинарное содержимое

Файлы и изображения проверяются сервисом, шифруются в staging и входят в общий
черновик. Надёжное сохранение публикует ссылки, историю и удерживаемые blobs
одной согласованной операцией. Повтор проверяет квитанцию до повторного чтения
исходника или сети. Предпросмотр читает только доступное локальное содержимое.
Загрузка по URL и favicon требует отдельного явного действия пользователя.

Android импортирует значок в точный `DraftId` записи или группы. Сетевое
получение выполняется host Rust через общий загрузчик и его ограничения:
isolated worker не приобретает разрешения Android. Пока идёт HTTP, канал
команд worker не удерживается. До загрузки worker проверяет доступ и квитанцию
точного запроса; после получения повторно проверяет сессию и форму, валидирует
изображение общим сервисом и сохраняет зашифрованную локальную коллекцию с blobs.
Успешный stage не означает сохранение версии БД: общий Save подтверждает текст
и значок одной причинной правкой, включая ещё незавершённую форму новой группы.
После явного запуска UI удерживает точный выбор до результата, отключая повтор,
отмену и переходы этой формы на время ограниченного запроса. Блокировка ОС
остаётся немедленной; поздний ответ не оживляет доступ или закрытую сессию.

Запрос импорта значка фиксирует `DraftId`, `OperationId` и исходный вид выбора
с точным URL, если он задан. Подтверждённый повтор возвращает квитанцию до
`SelectedInput.length`, чтения provider или нового HTTP; другая выборка использует
новый `OperationId`. Это отдельный контракт замороженного выбора значка;
существующий импорт вложения продолжает проверять повтор по содержимому потока.
Квитанция значка принадлежит зашифрованной `DraftCollection` отдельно от полей
формы: общий Save может убрать чистую форму, сохранив подтверждение исходного
выбора. Повтор после Save возвращает исходную идентичность подтверждения и не
восстанавливает старую форму, поля или heads. Если та же форма ещё существует,
ответ содержит её текущую идентичность, сохраняя более поздний ввод. Новый
редактор получает актуальную проекцию, включая уже применённые входящие правки.
Один существующий лимит в 100000 операций ограничивает Save-попытки, отменённые
операции и эти квитанции вместе; перед публикацией сериализованная локальная
коллекция проверяется по `MAX_FILE_SIZE`. Автоматического удаления квитанций
нет. Явное удаление черновика удаляет его квитанции, даже если чистая форма уже
убрана после Save. Пустое новое поле пропускается при сериализации.
Квитанция удерживает исходный `IconRef` и локальный blob, чтобы незавершённая новая
форма могла вернуть загруженный favicon после выбора Lucide. Локальный выбор
проверяет доступ к точной форме и удерживаемому оригиналу; идентичность кандидата
фиксируется до действия. Если оригинал больше недоступен, запрос отклоняется,
а другое изображение не подставляется. Сам выбор сохраняется в общем черновике.
`StoredFavicon(DraftId)` выбирает один кандидат: текущий favicon, иначе последнее
подтверждённое импортированное изображение favicon этой формы, иначе favicon её
baseline. Ответ содержит только идентичность оригинального blob и доступность.
`FormFavicon { draft, identity }` разрешает предпросмотр именно этого кандидата,
а `SelectStoredFavicon { draft, identity, operation }` повторно проверяет scope и
наличие оригинала перед stage. Квитанция локального выбора фиксирует вид действия,
форму и идентичность; повтор проверяется раньше нового разрешения кандидата и не
откатывает более поздние правки. Чужой blob, чужая форма и изменившийся кандидат
не дают полномочий чтения или выбора. Поиск по всей БД и сетевой fallback отсутствуют.
Неопределённая публикация локального stage удерживает точную коллекцию, её
зашифрованные blobs и исходную операцию в `DatabaseState` worker. До подтверждения
UI читает прежнюю форму, а новые изменения отклоняются как `CommitUncertain`.
Повтор той же операции сначала надёжно публикует этот же кандидат и только после
успеха заменяет доступную форму; повторное чтение provider или HTTP не требуется.
Обычный отказ до публикации не устанавливает этот кандидат. При блокировке
сохраняется кандидат неопределённой публикации, а прежняя форма не перезаписывает
его. Доступ закрывается независимо от результата; повторное открытие проверяет
сохранившуюся зашифрованную коллекцию. Это отдельное состояние от неопределённой
публикации рабочей БД и не подтверждает Save или историю.
URI и host-пути не входят в worker-команду. При отказе или позднем ответе прежняя
форма, сохранённая БД и выбранный значок не выдаются за изменённые.

Предпросмотр выбирает только доступный локальный blob в разрешённом scope,
экспортирует его существующим ограниченным `SelectedOutput` и возвращает
платформе ограниченный результат растеризации. Байты изображения не проходят
через JSON кадров команд. Чтение, открытие picker и выбор уже загруженного favicon
не запускают сеть; блокировка и смена поколения отзывают предпросмотр.

Перед получением выбранного output worker проверяет текущую сессию и exact
scope/blob; после получения capability снова проверяет доступ. Внутри каждой
проверки одно проверенное immutable состояние используется для видимости,
длины и authenticated reader, без сохраняемого кэша полномочий. Только успешный
EOF и `SelectedOutput.finish` дают ACK.

Проекции Android строки записи и группы передают текущий вид `IconView`
(`Default`, проверенный ключ `Lucide`, `Image`) без исходных байтов и адреса blob.
Изображение для строки загружается только через разрешённый локальный scope;
этот предпросмотр не является источником повторного импорта оригинала.
Новые пустые карты квитанций групповых форм пропускаются при сериализации,
сохраняя fingerprint существующих captured pending Save.

### Групповая загрузка favicon на Android

Форма выбранной группы передаёт Rust группу, `recursive`, `replace` и новый
`OperationId` только после явного «Загрузить». По умолчанию оба параметра
выключены. Общий сервис выбирает активные записи непосредственной группы либо
её поддерева, пропускает собственные значки при выключенной замене и отмечает
отсутствующий URL. Kotlin не повторяет предметный отбор. Исходные обычные поля,
текущая локальная форма и её незавершённый ввод не входят в пакетную правку.

`PrepareGroupFavicons` возвращает ограниченный план одной живой сессии:
исходную группу, параметры, родительскую операцию и фиксированные строки.
Для строки загрузки фиксируются `EntryId`, точный URL и дочерний
`OperationId`; дочерняя операция однозначно выводится из родительской и записи.
План удерживает непрозрачный Native batch, привязанный к исходной БД и
поколению worker. UI получает только представление строк и результатов, а не
полномочие подменить запрос или загрузить произвольную запись. URL не логируется.
План соблюдает существующую границу метаданных IPC; отдельного безразмерного
кэша, нового durable журнала пакетов или нового файлового формата нет.

`FaviconEntryReceipt` проверяет точный запрос строки до HTTP. Подтверждённая
квитанция возвращает ACK раньше повторного чтения записи или исходника;
другой action, URL, группа, параметры или запись под той же операцией
отказываются. Для неподтверждённой строки Native выполняет существующий
`icons::favicon` в host вне worker mutex. Изолированный worker не получает
разрешения сети. После получения Native снова проверяет живую сессию и
передаёт ограниченный `SelectedInput` вместе с исходным запросом.
`ImportSelectedEntryFavicon` сначала повторяет receipt-проверку, затем проверяет
точную длину, EOF и изображение общими правилами до изменения документа.

Первое успешное применение меняет только icon/provenance сохранённой записи,
оставляя её актуальные обычные поля, родителя и локальные формы. Значок, blob,
одна новая сохранённая версия и exact receipt публикуются одним существующим
кандидатом. ACK выдаётся после надёжной записи. Старый повтор не откатывает
более поздние текст, значок или перемещение. Повреждённый, короткий, длинный или
непрочитанный поток не меняет запись, историю или blobs.

Результаты отдельных строк различают подтверждение, намеренный пропуск,
отсутствие URL, типизированный отказ и неопределённую публикацию.
Успешные соседние строки не откатываются при сетевом отказе. Повтор в том же
batch использует исходные запросы и операции; подтверждённые строки не делают
повторный HTTP и не создают историю повторно. `CommitUncertain` сохраняет
точную неподтверждённую строку и требует существующего согласования записи
перед новым изменением; пакет целиком не показывается успешным.

Отмена, блокировка, закрытие или замена БД немедленно отзывают batch; оставшиеся
запросы не начинают сеть. После ожидания command mutex Native повторно проверяет
отмену до допуска worker-команды. Уже допущенная атомарная запись может завершиться
одновременно с отменой; отмена не обещает её откат и поздний результат не
показывается UI как успешный пакет. Полученный после lock stream не получает
нового доступа к закрытой сессии, его байты освобождаются. Уже надёжно сохранённые
строки остаются в БД. Полная потеря
Native batch или перезапуск приложения требует нового явного запуска, а не
реконструкции прежнего выбора из изменившегося дерева. Это ограниченная попытка
живой сессии, не cold-resume протокол. Существующий desktop `GroupFavicons` и
старые receipt intents сохраняют совместимость.

Проверки этого среза используют только PUBLIC документы и локальные HTTP
fixtures: прямые/вложенные группы и оба фильтра, отсутствующий URL, частичный
сетевой отказ, один history commit и сохранение незавершённой формы, short/extra
EOF и invalid image без изменений, exact повтор без HTTP/второй версии,
отказ изменённого intent до чтения provider, lost ACK с последующим согласованием,
поздний HTTP после lock и смена БД. Android-сценарий отдельно проверяет, что
открытие формы не делает сеть, результат содержит настоящие отдельные статусы,
а завершение одной строки не выдаётся за успешный пакет.

Android SAF передаёт ограниченную capability выбранного потока, связанную с БД,
поколением и формой. Подготовка picker сохраняет локальную форму, а не БД.
Байты читаются порциями до 64 КиБ без plaintext staging; блокировка отзывает
capability. Экспорт подтверждается после завершения записи и fsync выбранного
output. URI и host-пути не являются универсальными командами документа.

## Блокировка, обмен и восстановление

`SessionController` независимо отзывает доступ, инвалидирует старые ответы
и ограничивает завершение worker двумя секундами. Ошибка или зависание I/O
не продлевают доступ. Блокировка сохраняет лишь зашифрованные локальные формы,
если это возможно; отсутствие такой записи не отменяет блокировку.
Возобновление формы после unlock не запускает commit.

Закрытие — явная операция с результатом; `Drop` завершает процесс и не обещает
сохранение. EOF и повреждённый кадр закрывают доступ. Завершение процесса
не доказывает физическую очистку RAM, swap или копий UI.

Получение ciphertext подтверждается после надёжной записи и отдельно от
применения после разблокировки. Копия файла с паролем не выдаёт допуск.
`enable_network` сохраняет запрос на обмен даже у нового dormant host и возвращает
`None`, пока нет активированного допущенного контекста. `start_network` требует
фактический endpoint. Первое успешное обычное открытие своей БД активирует её
контекст; constrained recovery и reader-копия сами обмен не запускают.
`network_snapshot.running` отражает реальные endpoints, а не наличие настройки.

Node публикует независимые наблюдения по БД и аутентифицированному пиру:
`Unknown` / `Connected` и фазу попытки `Waiting` / `Connecting` / `Transferring` /
`Completed` / `Failed` / `Cancelled`. Закрытие последнего соединения возвращает
`Unknown`; ошибка доставки не доказывает offline. Поздняя завершившаяся попытка
не перезаписывает новую. Durable ACK, локальное применение и наблюдение соединения
остаются отдельными фактами; время последнего присутствия не изобретается.

`WorkerApplicationObserver` даёт согласованный снимок без содержимого БД и
ожидания командного IPC. `revision` увеличивается на каждый отчёт применения;
`applied_revision` хранит номер последнего отчёта с надёжно принятыми изменениями
данных или control baseline. `ApplyReport.changed` подтверждает такой переход,
включая новый baseline при нулевом счётчике отдельных оригинальных изменений.
Подтверждённое перечитывание после неопределённого результата записи также
удерживает признак изменения до успешного отчёта; последующая ошибка применения
не теряет это подтверждение.
Пустые, отложенные и ошибочные отчёты сохраняют эту отметку, поэтому пропущенный
опрос не теряет событие изменения. Новый worker начинает с нуля; отозванное
поколение не возвращает снимки. UI отдельно проверяет владельца запросов.

Подписанные переходы управления и сборка нового доверенного набора сохраняют
квитанции, проверку полномочий и исходный файл. Поздние источники не возвращаются
автоматически после очистки; неизвестные ссылки задерживают освобождение blobs.
Android подключает раздельный просмотр и извлечение непринятых и поздних источников
через типизированный UniFFI bridge; это не возвращает сетевой допуск.

### Передача управления на Android

Двусторонний сценарий, проверенная живая OPEN-сессия получателя, надёжная запись
согласия до сетевого ответа и отдельное подтверждение применения control baseline
описаны в [контракте передачи управления](management-handoff.md). Runtime owner,
Native `proposeManagement` / `acceptManagement` / `retryManagement` и Android
`ManagementState` подключены к UI. Результаты общих и Android-сценариев учитываются
отдельно: сам ciphertext exchange не подтверждает готовность или завершение
передачи роли.

### Восстановление управления на Android

Android recovery подключён через Native `openRecoveryDocument` /
`adoptRecovery`, приватный ciphertext gateway и `RecoveryState` к Compose UI.
Ни наличие общего API, ни частичный emulator PASS не закрывают полную Android-
и аппаратную приёмку; результаты конкретных APK находятся в [testing](testing.md).
Сценарий переиспользует
`ArchiveSeed`, `publishRecovery`, `confirmRecovery`, защищённый profile proof,
проверку закрытых source writer и `adopt` существующего runtime. Он не вводит
новый криптографический формат, протокол передачи управления или разрешение
обмена по прежнему доверенному набору.

**Намерение и источник.** Одна команда worker фиксирует ID операции, профиль
и логическую исходную рабочую копию, `DatabaseId`, прежний authority root,
аутентифицированный fingerprint полного исходного архива, текущую полную публичную
`Identity` с авторским и транспортным ключами, точное название новой копии и
попытку нового пароля. Снимок документа и проверенная control chain относятся
к тому же fingerprint. Общие правила проверяют имя и пароль до публикации;
Kotlin не нормализует ввод и не реализует эти правила повторно. Незавершённая
форма разрешается обычным явным выбором до фиксации recovery, не сохраняется
в БД автоматически. Изменённое имя, источник, identity или действие с прежним
ID операции — несовпадение намерения, а не новая попытка под тем же ID.

Для повтора host надёжно сохраняет отдельный неизменяемый **зашифрованный**
source snapshot, привязанный к этой операции и защищённой регистрации источника.
Он читается из захваченного `ArchiveSnapshot`, а не повторно из изменяемого пути;
worker аутентифицирует его root, fingerprint и состав до подготовки кандидата.
Это ограниченный ресурс конкретной незавершённой операции, а не автоматический
backup. Используются существующие ciphertext staging, `TemporaryStorage` /
`CiphertextFile`, точные длины и EOF, лимиты контейнера и потоков. Большой архив
не помещается в JSON или профильный credential: защищённый descriptor / proof
остаётся в существующей границе 64 КиБ, catalog — в своей границе, архив — в
существующем пределе 16 ГиБ. На исходную зарегистрированную копию допускается
одна незавершённая recovery; новый ID не вытесняет неопределённую предыдущую.
Snapshot удерживается до согласованного завершения либо безопасно доказанного
отказа до публикации; неизвестный результат не разрешает его тихо удалить.

Входящие изменения исходного файла после захвата не изменяют зафиксированную
копию и не меняют fingerprint повторной операции. Первый вызов отказывает при
несогласованном состоянии source вместо смешивания снимков. Потерянный ответ,
lock и перезапуск повторяют прежнее намерение по сохранённому snapshot. Пароль
и авторский секрет принадлежат только worker и очищаются при отзыве; host не
сохраняет пароль или его открытый проверочный digest. После потери worker
пользователь повторно вводит пароль для аутентификации того же зашифрованного
кандидата; это не разрешает новую операцию или другой результат по старому ID.
Если encrypted кандидат ещё не существует, одна source receipt не доказывает
сохранность утраченной попытки пароля. Такой повтор сначала согласует отсутствие
публикации; он не выбирает новый пароль под прежним неопределённым намерением.
Продолжение сохранённого кандидата требует его реальной аутентификации; доказанный
отказ до подготовки кандидата позволяет отдельную новую операцию.

**Кандидат.** Общий сервис готовит `ArchiveSeed` из зафиксированного source.
Новый независимый genesis использует ровно текущую полную локальную `Identity`,
новые ключи и пароль. Название применяется общим правилом внутри документа
кандидата **до** его шифрования и первоначального durable ACK; второго rename /
Save после успеха нет. Логический `DatabaseId`, ID записей и групп, содержимое,
история, blobs, pending ciphertext и старые подписанные состояния сохраняются
по существующему контракту recovery; изменение имени относится только к
метаданным новой копии. Старые ключи и подписи остаются защищённым происхождением,
а не полномочиями нового набора. Исходный файл и его локальный зашифрованный
черновик recovery не перезаписывает и не удаляет.

Native и host получают только ciphertext, ограниченные дескрипторы и публичные
идентификаторы. Новый пароль, ReadKey, авторский seed и открытый документ через
recovery gateway не выходят. Android isolated worker получает узкие callbacks
публикации seed и подтверждения receipt через приватный Binder / PFD канал;
это расширение существующего ciphertext gateway, а не доступ к host-файлам.
Физический путь новой внутренней копии выбирает host по замороженной операции,
а не произвольная команда документа. Существующий чужой файл не перезаписывается.

**Публикация и принятие.** Этапы различаются: snapshot зафиксирован, кандидат
опубликован, защищённый proof подтверждён, исходные writer закрыты, catalog
принял новую копию. `publishRecovery` создаёт отдельный файл; `confirmRecovery`
проверяет его реальную регистрацию, root, fingerprint и exact receipt, завершает
fsync файла и каталога и надёжно сохраняет привязанный profile proof. Публичный
locator сам по себе не разрешает открыть admitted worker или запустить обмен.
Открытый catalog не хранит имя или пароль: exact намерение связывается через
непрозрачный digest и аутентифицированную encrypted receipt, защищённый proof
содержит лишь необходимые привязки и публичные identity. Публичная привязка
использует аутентифицированный ciphertext, а не открытый hash пользовательского
имени или пароля.

`CommitUncertain`, потерянный ответ и перезапуск согласуются по фактическому
durable состоянию snapshot, кандидата, регистрации, защищённого proof и catalog.
Совпавший cached receipt не заменяет перечитывание и повторное подтверждение
durability. Exact retry возвращает прежний root и файл; он не создаёт новый
genesis, не применяет новый source fingerprint и не переименовывает опубликованный
документ. До доказанного отказа или согласованного успеха неопределённое намерение
остаётся замороженным. Повреждённый, отсутствующий либо недоступный обязательный
proof различается по типу ошибки; отсутствие proof не выдаётся за успешный этап.

`adopt` проверяет защищённый proof **и** фактическое закрытие всех worker и
ciphertext writer исходной БД. Сообщение «закрывается», логический lock, timeout
или UI-флаг не являются подтверждением закрытия. Android подтверждает выход
Service процессом ОС и освобождает обе Binder capabilities; runtime проверяет
отсутствие активных сессий / зарегистрированных writer. Только затем catalog
атомарно заменяет исходную рабочую копию новым root. До этих проверок новая копия
не активируется, не становится текущей в catalog и не запускает network. Источник
остаётся отдельным файлом. Ошибка смены catalog не уничтожает кандидат или proof;
повтор согласует тот же этап. Отозванное UI-поколение не открывает копию поздним
callback; явное открытие после успешного принятия использует новую регистрацию.

**Противоречие управления.** Для читаемой копии с подтверждённым control fork
нужен отдельный режим read-only / recovery bootstrap. Он аутентифицирует источник
и сохраняет полное fork evidence в snapshot и происхождении нового кандидата,
но не разрешает запись документа, операции управления, применение по старой
цепочке или старый сетевой обмен. Обычные frozen / authority guards сохраняются;
их отключение ради recovery недопустимо. Узкая авторская capability worker
разрешает подписать только независимый genesis этого exact намерения, а не
действовать управляющим прежнего набора. Копия с паролем не получает старый допуск.

Совместимость существующих desktop API и квитанций сохраняется wrappers и
необязательными полями с `default` и пропуском отсутствующего значения.
Отсутствующий Android intent в старой receipt не подставляет новое имя или
transport identity и не проходит как подтверждение новой Android операции.
Сериализация старой квитанции и её fingerprint не меняются при пустых новых
полях; существующие форматы шифрования, provenance и control остаются прежними.

Проверки реализации должны использовать реальные encrypted archives, protected
profile и isolated workers: сохранность исходных байтов, истории, blobs,
pending / provenance и локальной формы; имя внутри первой публикации;
совпадение полной identity; source incoming между публикацией и потерянным ответом
с тем же root / файлом при retry; отказ при чужом source / имени / identity / ID;
ошибки до и после публикации каждого durable этапа и перезапуск;
поддельный публичный locator, отсутствующий / повреждённый / недоступный proof;
задержанное закрытие writer и отсутствие нового catalog / network до реального
close ACK; lock и устаревший callback без повторного открытия; читаемый fork
с сохранённым evidence и отказом старых управления / обмена; независимое новое
подключение устройств. Desktop legacy receipts проверяются фиксированными
образцами. Emulator-сценарии не заменяют физическую приёмку lifecycle / Keystore
и общую проверку формата и секретов.

Текущая схема 1 не мигрирует прежние экспериментальные dev-файлы.
Неподдерживаемый или повреждённый файл отклоняется без перезаписи.
Результаты runtime-тестов не закрывают нативную приёмку macOS, Android, Linux,
криптографическую и физическую приёмку.
