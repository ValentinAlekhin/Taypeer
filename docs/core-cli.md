# Rust-ядро и командный клиент

## Запуск реализованного среза

```sh
cargo run --locked -p taypeer-cli -- session
```

В интерактивной сессии:

```text
db create /tmp/public-demo.taypeer --name "PUBLIC demo"
group create --name "PUBLIC accounts"
group list
```

Затем подставьте ID группы из результата:

```text
entry create --group GROUP_ID --title "PUBLIC example" --username "PUBLIC user" --password-prompt
entry list
history list ENTRY_ID
db lock
db unlock
entry show ENTRY_ID
exit
```

Пароль БД и пароль записи вводятся скрытым запросом; для проверки используйте
только искусственные данные. `--lang ru` переводит запросы и сообщения ошибок;
справка clap пока английская. `--json` задаёт машинный вывод. Без него сложные
представления пока печатаются как форматированный JSON.

Для одиночной команды используйте `--file PATH`. Пароль читается скрытым запросом;
`--password-stdin` предназначен для автоматизации и читает точный UTF-8 до EOF,
включая завершающий перевод строки. Пароль не передаётся через argv или environment.
`--input PATH` принимает адресные JSON-правки (`keep`, `set`, `clear`);
`--input -` нельзя совмещать с `--password-stdin`.

```json
{
  "title": {"action": "set", "value": "PUBLIC renamed"},
  "username": {"action": "set", "value": ""},
  "notes": {"action": "clear"}
}
```

Пропущенный пароль остаётся прежним. Пустая строка и отсутствие различаются.
Черновик после перезапуска восстанавливается только через `draft restore`.
Обычные представления, история и поиск не раскрывают защищённые значения;
`entry reveal` и `conflict reveal --input PATH` — явные действия пользователя.
Для варианта конфликта JSON задаёт `entry`, `field` и полный список `origins`
из маскированного просмотра.

## Граница процесса

Каждая открытая CLI-база имеет отдельный дочерний процесс и единственного писателя.
Родитель отправляет команды через приватные ограниченные кадры; документ Automerge
и ключ чтения находятся в дочернем процессе. `db lock`, `db close` и выход завершают
процесс даже при ошибке сохранения черновика. Ошибка не превращается в успех.
Последовательность команд исключает одновременные записи внутри одного worker.

Интерактивная сессия поддерживает несколько БД, выбор через `db use ID` и поиск
по разблокированным БД. Пять минут без ввода блокируют открытые БД; события редактора
обновляют таймер. Пока блокирующий запрос к worker или скрытый запрос пароля
выполняется, главный цикл не обслуживает таймер. Принудительный deadline worker,
системные события сна/блокировки и очистка состояния редактора ещё не реализованы.

Граница процесса сейчас применяется к CLI. macOS UI всё ещё вызывает сервис
в собственном процессе. Затирание входных буферов и завершение worker не доказывают
очистку всех копий, памяти KDF, swap и core dumps.

## Реализовано

- Адресные правки черновика без подмены пропущенных полей.
- Создание и повторное открытие зашифрованного файла через отдельный процесс.
- Группы, записи, поиск, черновики, история и явное раскрытие.
- Клонирование с новыми ID, восстановление версии в выбранную группу,
  точное удаление выбранных строк истории и разрешение наблюдавшихся конфликтов.
  Эти операции фиксируют идентификатор повтора в той же транзакции, что изменение.
- Конкурентная поздняя правка остаётся конфликтом после разрешения старого контекста.
- Генератор паролей и фраз с OsRng, равномерной выборкой и встроенным словарём EFF.
- Потоковая шифрованная оболочка контейнера; контракт — в [storage](storage.md).

## Остаток согласованного плана

Этот документ фиксирует промежуточный результат, а не завершение полного ядра.

- [ ] Полная локальная модель: перемещения дерева, конфликтующие положения,
  корзина, каскадное удаление, окончательная очистка и отдельные поздние источники.
- [ ] Вложения и иконки, потоки blobs вне Automerge, освобождение недостижимого.
- [ ] Подписанный manifest разделов, полная схема и подтверждённые ресурсные границы.
- [ ] Управляющее устройство, одноразовые приглашения, подтверждение допуска,
  передача управления, отзыв, независимые эпохи и исторические ключи.
- [ ] Iroh: реальный обмен нескольких CLI-процессов, надёжный приём при блокировке,
  отдельное применение после разблокировки, очереди и возобновление.
- [ ] Миграции и восстановление копии без отката схемы/защиты/управления;
  восстановление управления и обработка зависимостей от отозванных авторов.
- [ ] KDBX 3.1/4.0/4.1 import, 4.1 export, отчёт потерь, проверка KeePassXC.
- [ ] Локальное защищённое состояние и адаптеры ОС, строгие deadlines и блокировка,
  очистка собственного буфера обмена, события сна и блокировки системы.
- [ ] Общие идентификаторы повторов для остальных изменяющих команд.
- [ ] Полная CLI-локализация, табличный вывод, PTY-матрица и fault injection.
- [ ] Полная приёмка формата и безопасности по [roadmap](roadmap.md).

UniFFI, новые UI-экраны и Android-интеграция отложены решением владельца для этой
работы. Старый экспериментальный контейнер 0 не поддерживается и не мигрируется.

## Проверка текущего среза — 2026-09-10

Общий `sh scripts/check.sh` прошёл: LikeC4 и ссылки, Rustfmt, workspace check,
Clippy, тесты, Rustdoc, release-сборка и macOS smoke. Дополнительный PTY-сценарий
на локальной macOS прошёл с немедленным скрытым вводом, отменой Ctrl-C,
двумя одновременно открытыми БД, поиском, блокировкой и повторным открытием.
Файловый CLI-тест дополнительно повторяет clone/restore/purge с теми же ID
операций в новых процессах: дубликатов записи и истории нет.

Изменённые представления `applications`, `cliSession` и `implementation`
экспортированы и визуально проверены. Эти результаты относятся к перечисленному
локальному срезу; сетевые, KDBX и полные платформенные сценарии выше остаются открытыми.

[Генератор публичного примера](../scripts/create-cli-demo.py) создаёт одноразовый
файл в `artifacts/cli-demo/` через release CLI и проверяет две записи и историю
после повторного открытия. Он отказывается заменять существующий файл;
описание происхождения, публичный пароль и SHA-256 находятся рядом с результатом.
