# Rust-ядро и командный клиент

## Запуск реализованного среза

```sh
cargo run --locked -p taypeer-cli -- session
```

В интерактивной сессии:

```text
db create /tmp/public-demo.taypeer --name "PUBLIC demo"
group create --name "PUBLIC accounts"
group list
```

Затем подставьте ID группы из результата:

```text
entry create --group GROUP_ID --title "PUBLIC example" --username "PUBLIC user" --password-prompt
entry list
history list ENTRY_ID
db lock
db unlock
entry show ENTRY_ID
exit
```

Пароль БД и пароль записи вводятся скрытым запросом; для проверки используйте
только искусственные данные. `--lang ru` переводит запросы и сообщения ошибок;
справка новых команд дерева/корзины/источников также переведена;
справка прежних команд clap пока английская. `--json` задаёт машинный вывод. Без него сложные
представления пока печатаются как форматированный JSON.

Для одиночной команды используйте `--file PATH`. Пароль читается скрытым запросом;
`--password-stdin` предназначен для автоматизации и читает точный UTF-8 до EOF,
включая завершающий перевод строки. Пароль не передаётся через argv или environment.
`--input PATH` принимает адресные JSON-правки (`keep`, `set`, `clear`);
`--input -` нельзя совмещать с `--password-stdin`.

```json
{
  "title": {"action": "set", "value": "PUBLIC renamed"},
  "username": {"action": "set", "value": ""},
  "notes": {"action": "clear"}
}
```

Пропущенный пароль остаётся прежним. Пустая строка и отсутствие различаются.
Черновик после перезапуска восстанавливается только через `draft restore`.
Обычные представления, история и поиск не раскрывают защищённые значения;
`entry reveal` и `conflict reveal --input PATH` — явные действия пользователя.
Для варианта конфликта JSON задаёт `entry`, `field` и полный список `origins`
из маскированного просмотра.

## Дерево, корзина и поздние источники

```text
group tree
group move GROUP_ID --parent PARENT_ID --before SIBLING_ID --operation MOVE_ID
entry move ENTRY_ID --group GROUP_ID --operation MOVE_ENTRY_ID
group clone GROUP_ID --name "PUBLIC clone" --operation CLONE_ID
```

Без `--parent` группа переносится на верхний уровень. Позиция задаётся одним из
`--first`, `--last`, `--before ID`, `--after ID`; по умолчанию — последняя.
`group list` и `entry list` возвращают обычную проекцию. `group tree` сохраняет
все варианты и возвращает `heads` для явного разбора. Циклы, отсутствующие
родители и неоднозначные назначения не превращают весь документ в ошибку.

Удаление и очистка выполняются в два шага. Сохраните JSON первой команды в файл
и проверьте `affected`: это точные поколения объектов и наблюдавшиеся события.
Вывод не содержит полей записи.

```sh
# Мастер-пароль будет запрошен скрыто.
target/release/taypeer-cli --json --file PUBLIC.taypeer group trash GROUP_ID > selection.json
target/release/taypeer-cli --file PUBLIC.taypeer trash confirm --input selection.json --yes --operation TRASH_ID
```

`entry trash ENTRY_ID` аналогично готовит одну запись. Команда
`trash prepare restore group GROUP_ID --destination PARENT_ID` готовит
восстановление поддерева, а `trash prepare purge group GROUP_ID` — окончательную
очистку. Для записи используйте `entry` вместо `group`; при восстановлении
назначение обязательно. Все эти результаты подтверждаются через `trash confirm`.
Для повторов после сбоя задавайте и сохраняйте один и тот же `--operation ID`.
Появившиеся после подготовки дети не добавляются в подтверждённый состав.
Очистка при нерешённом конфликте отклоняется; повторное подтверждение удаления
позволяет принять просмотренные правки удаления, сохранив конфликты самих полей.

`trash list` работает и при пустом активном дереве. `trash show entry ENTRY_ID
--generation GENERATION_ID` показывает сохранённые варианты со скрытыми секретами.
`pending list` возвращает поздние события очищенных поколений с исходными hash,
actor и revision. `pending show SOURCE_ID` показывает исходное состояние, а
`pending restore SOURCE_ID --destination GROUP_ID --operation RECOVERY_ID`
возвращает его с прежним публичным ID и новым поколением. `pending clone` создаёт
новые ID. Предыдущие очищенные состояния не возвращаются в обычную историю.

Для неоднозначного источника `pending recover --input request.json` принимает
`source`, `mode` (`restore`/`clone`), `destination` и явные `name` либо `fields`.
Другие поздние события остаются отдельными источниками; оригинал обработанного
источника остаётся доступен по его ID. После нескольких конкурентных восстановлений
`conflict generation --input choice.json` принимает `address` и просмотренные `heads`.

`group resolve --input placement.json` принимает `group`, `parent`, `position`,
`review` (массив heads), `name` (необязательный явный выбор). `entry move --review
heads.json` разрешает просмотренные назначения. Новые варианты, не входившие
в просмотр, сохраняются. Открытый черновик нужно сначала сохранить или отменить.

`trash reveal` и `pending reveal` принимают JSON с `target`, `field`, `origins`.
Например, target источника — `{"kind":"source","value":"SOURCE_ID"}`. Поле и
полный список origins берутся из скрытого просмотра. Раскрытие — отдельная команда.
Сетевого импорта/слияния в CLI пока нет: конкурентные сценарии создают локальные
реплики через тестовую границу Document, затем проверяют файл реальными процессами.

## Граница процесса

Каждая открытая CLI-база имеет отдельный дочерний процесс и единственного писателя.
Родитель отправляет команды через приватные ограниченные кадры; документ Automerge
и ключ чтения находятся в дочернем процессе. `db lock`, `db close` и выход завершают
процесс даже при ошибке сохранения черновика. Ошибка не превращается в успех.
Последовательность команд исключает одновременные записи внутри одного worker.

Интерактивная сессия поддерживает несколько БД, выбор через `db use ID` и поиск
по разблокированным БД. Пять минут без ввода блокируют открытые БД; события редактора
обновляют таймер. Пока блокирующий запрос к worker или скрытый запрос пароля
выполняется, главный цикл не обслуживает таймер. Принудительный deadline worker,
системные события сна/блокировки и очистка состояния редактора ещё не реализованы.

Граница процесса сейчас применяется к CLI. macOS UI всё ещё вызывает сервис
в собственном процессе. Затирание входных буферов и завершение worker не доказывают
очистку всех копий, памяти KDF, swap и core dumps.

## Реализовано

- Адресные правки черновика без подмены пропущенных полей.
- Создание и повторное открытие зашифрованного файла через отдельный процесс.
- Группы, записи, поиск, черновики, история и явное раскрытие.
- Клонирование записи и поддерева с новыми ID, восстановление версии в выбранную группу,
  точное удаление выбранных строк истории и разрешение наблюдавшихся конфликтов.
  Эти операции фиксируют идентификатор повтора в той же транзакции, что изменение.
- Конкурентная поздняя правка остаётся конфликтом после разрешения старого контекста.
- Генератор паролей и фраз с OsRng, равномерной выборкой и встроенным словарём EFF.
- Плотный порядок групп, атомарные размещения, явные конфликты дерева и поколений.
- Корзина с точной подготовкой/подтверждением, очистка поколений, устойчивые
  поздние источники с исходным происхождением и атомарными receipts восстановления.
- Потоковая шифрованная оболочка контейнера; контракт — в [storage](storage.md).

## Остаток согласованного плана

Этот документ фиксирует промежуточный результат, а не завершение полного ядра.

- [x] Локальные перемещения дерева, конфликтующие положения, корзина,
  точное удаление поддерева, окончательная очистка и отдельные поздние источники.
  Восстановление источника под прежним ID требует закрытого текущего поколения;
  при уже существующем активном состоянии доступно клонирование источника.
- [ ] Вложения и иконки, потоки blobs вне Automerge, освобождение недостижимого.
- [ ] Подписанный manifest разделов, полная схема и подтверждённые ресурсные границы.
- [ ] Управляющее устройство, одноразовые приглашения, подтверждение допуска,
  передача управления, отзыв, независимые эпохи и исторические ключи.
- [ ] Iroh: реальный обмен нескольких CLI-процессов, надёжный приём при блокировке,
  отдельное применение после разблокировки, очереди и возобновление.
- [ ] Миграции и восстановление копии без отката схемы/защиты/управления;
  восстановление управления и обработка зависимостей от отозванных авторов.
- [ ] KDBX 3.1/4.0/4.1 import, 4.1 export, отчёт потерь, проверка KeePassXC.
- [ ] Локальное защищённое состояние и адаптеры ОС, строгие deadlines и блокировка,
  очистка собственного буфера обмена, события сна и блокировки системы.
- [ ] Общие идентификаторы повторов для остальных изменяющих команд.
- [ ] Полная CLI-локализация, табличный вывод, PTY-матрица и fault injection.
- [ ] Полная приёмка формата и безопасности по [roadmap](roadmap.md).

UniFFI, новые UI-экраны и Android-интеграция отложены решением владельца для этой
работы. Предыдущие dev-файлы (контейнер 0 и контейнер 1 / схема 1)
не поддерживаются и не мигрируются. Текущая dev-схема — 2.

## Проверка текущего среза — 2026-09-10

Общий `sh scripts/check.sh` прошёл: LikeC4 и ссылки, Rustfmt, workspace check,
Clippy, тесты, Rustdoc, release-сборка и macOS smoke. Дополнительный PTY-сценарий
на локальной macOS прошёл с немедленным скрытым вводом, отменой Ctrl-C,
двумя одновременно открытыми БД, поиском, блокировкой и повторным открытием.
Файловые CLI-тесты повторяют clone/restore/purge и восстановление позднего источника
с теми же ID операций в новых процессах: дубликатов записи и истории нет.
PTY-сценарий дополнен корзиной, восстановлением, перемещением и guard черновика.

Для нового локального среза проверены также конкурирующие поколения, поздние
события каждого восстановленного ребёнка, отказ старым формам после смены
поколения родителя, восстановление атрибутов из версии другого доступного
поколения и отказ старым dev-файлам. Представления `domain`, `lifecycle`
и `implementation` экспортированы в `artifacts/lifecycle-architecture/` и визуально
проверены. Эти результаты относятся к перечисленному
локальному срезу; сетевые, KDBX и полные платформенные сценарии выше остаются открытыми.

[Генератор публичного примера](../scripts/create-cli-demo.py) создаёт одноразовый
файл в `artifacts/cli-lifecycle-demo/` через release CLI: две активные группы и записи,
перемещение, три версии исходной записи и клонированное поддерево в корзине.
Рядом сохраняется точный JSON для пробного восстановления через `trash confirm`. Он отказывается заменять существующий файл;
описание происхождения, публичный пароль и SHA-256 находятся рядом с результатом.
