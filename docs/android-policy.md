# Защита и лимиты БД на Android

Контракт Android-проекции существующей политики. Продуктовые значения
принадлежат `spec.md`, формат и KDF — `storage.md`, полномочия и надёжность
сохранения — общим managed-сервисам. Результаты проверок и открытые условия
Android-приёмки фиксируются отдельно в [Android README](../apps/taypeer-android/README.md)
и [testing.md](testing.md). Композиция берётся из актуальных `Android / form/protection` и
`Android / form/limits` в `wireframes/taypeer.fig`.

## Чтение

Одна команда `PolicyDetails` в текущем OPEN-worker возвращает политику,
существующий `StorageUsage` и числовую проекцию защиты. Она проверяет обычную
сессию и поколение; последовательность чтений внутри одной команды не смешивает
разные состояния с конкурентной командой изменения. Native преобразует её в
типизированный UI view. Ошибка чтения остаётся ошибкой, а не нулевым расходом или
значением политики по умолчанию.

Защита показывает Argon2id, реальную память, параллелизм и число проходов
аутентифицированного текущего password header. Действующий формат использует
64 МиБ и p=1; UI не предлагает несуществующие альтернативы памяти. UI получает
числа и идентификатор алгоритма, без header, соли, обёрнутого ключа, ReadKey или
какой-либо открытой сериализации документа.

`passwordDerivationMs: Optional<u64>` — последнее фактически измеренное время
успешной подготовки password wrapping key в этом worker. Измерение использует
монотонные часы и охватывает Argon2id, а не чтение файла, авторизацию устройства,
расшифровку документа или искусственную задержку. Оно принадлежит точному
password header и epoch. При изменении этой связи старое измерение удаляется.
Quota-only изменение с прежним header не превращается в новый замер. Keyed
биометрическое открытие не выполняет password KDF и возвращает отсутствие
такого измерения. UI честно показывает отсутствие вместо времени цели или
синтетического числа. Значение не обещает одинаковую длительность на другом
устройстве либо при следующем открытии.

Экран лимитов показывает в МиБ реальные `attachment_bytes` и общий лимит.
`retained_bytes`, `draft_bytes` и `file_bytes` остаются отдельными величинами:
физический размер ciphertext файла, локальные черновики и удерживаемое
содержимое не подменяют расход продуктовой квоты. История, корзина и ожидающие
источники могут удерживать blobs. `over_limit`, отсутствующие blobs и
неизвестные ссылки не скрываются успешной пустой проекцией.

Для managed БД физический размер читается из свежего проверенного ciphertext
snapshot существующего `CipherPersistence`. Дескрипторный Android worker не
получает host-путь; его отсутствие не превращает расход в ноль. Ошибка snapshot
остаётся ошибкой. Legacy `FileStore` сохраняет чтение filesystem metadata.

## Явная калибровка

`CalibrateProtection { target_ms }` выполняется только по кнопке. Общий Rust
проверяет ту же цель 500–5000 мс и использует тот же алгоритм калибровки,
минимум/максимум проходов, память и параллелизм, что создание нового epoch.
Новый криптографический формат или дополнительная политика здесь не вводятся.

Команда вычисляет ограниченный preview с целью, числом проходов, памятью,
параллелизмом и измеренной длительностью выбранного прохода KDF. Пробный ввод
не является мастер-паролем; промежуточные производные ключи принадлежат worker,
освобождаются в нём и не пересекают UI/host границу. Калибровка не читает
секреты записи, не меняет документ, историю, draft, control, admission или
рабочий файл и не выполняет сеть.

Результат обозначен как preview выбранной цели, ещё не применённый. Он не
заменяет параметры текущего header или время последней реальной password KDF.
Применение использует существующее `SetDatabasePolicy`; при изменении цели
оно заново выполняет подтверждённую калибровку и защищённую публикацию.
Preview не обещает идентичную длительность следующей операции.

Фоновый расчёт принадлежит выбранной БД, поколению сессии и ревизии ввода цели.
Новая цель, закрытие маршрута, смена БД и lock отзывают применение старого
ответа. Блокировка не ждёт окончания тяжёлой Argon2id работы: обычный контроль
сессии и завершение isolated worker остаются действующими.

## Применение и UI

Настройки БД имеют отдельные действия «Параметры защиты» и «Лимиты вложений».
Оба экрана используют общий подтверждённый read view и существующую управляемую
политику. Единицы МиБ/секунды принадлежат представлению; пределы и предметная
валидация остаются в Rust. Правка одного раздела сохраняет значения другого
из принятой формы, без скрытого Save или автоматической перекалибровки.

Apply захватывает один полный policy intent, точный operation и необходимый
ввод текущего мастер-пароля. Только общая Rust-команда определяет право
управляющего устройства, допустимость значений, необходимость реаутентификации,
ротацию epoch, административную квитанцию и надёжность записи. Успех виден лишь
после подтверждённого ACK; фоновый статус обмена его не заменяет.

После неопределённого исхода UI сохраняет точный public policy intent/operation
и предлагает его reconciliation/retry. Новый ввод не создаёт вторую попытку
вместо неизвестной первой. Только типизированный доказанный отказ до
публикации разрешает исправить intent; generic Runtime/StorageIo не означают
такой отказ. Отмена до попытки остаётся доступной, повторный Apply во время
попытки отключён. OS lock немедленно удаляет открытые поля пароля, старые
проекции и preview; поздний ACK не восстанавливает экран.

Управляющее право и текущая сессия повторно проверяются общей командой.
Readonly UI не выдаёт локальные настройки за доступ к управлению. Ошибки,
busy, retry, возможность исправления и отсутствие измерения локализованы en/ru.
Результаты и поля доступны при landscape/font200 через обычный scroll.

## Проверки

Нужны реальные Rust/worker/Native и Android UI сценарии:

- параметры совпадают с валидированным текущим header; successful password open
  даёт реальный замер, keyed open не выдаёт замер пароля, новый epoch удаляет
  замер старого header;
- явная калибровка возвращает bounded реальные параметры и elapsed, а bytes
  файла, control, история и локальные drafts остаются прежними;
- расход attachments совпадает с общим `StorageUsage`, история и pending
  references не подменяются физическим ciphertext размером;
- readonly/невалидные значения/неверный пароль отказываются без публикации;
  исправление подтверждает одну смену политики, quotas не вызывают KDF rotation;
- lost ACK и postpublication uncertainty повторяют прежнюю квитанцию; поздний
  preview/ACK после новой цели, route, lock или смены БД не заменяет UI;
- отдельные Protection/Limits builders совпадают с FIG во всех шести профилях.

Команды находятся в [Android QA runbook](android-testing.md), результаты
конкретных APK — в [testing.md](testing.md). Контракт не заменяет эти
доказательства и физическую приёмку.
