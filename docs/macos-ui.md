# Desktop UI и Rust runtime

Обычный запуск открывает UI по [макетам](../wireframes/README.md) на GPUI Kit.
Файловые операции выполняются общими Rust-сервисами через отдельный процесс для
каждой разблокированной БД. Каталог публичных образцов из production UI удалён.
Футер автоматически выбирает единицу размера файла от байтов до ЭБ (шаг 1000,
как в macOS), показывает до одного десятичного знака и учитывает язык интерфейса.

## Границы crates

Код desktop-приложения остаётся в `apps/taypeer`. Корневой пакет `taypeer`
собирает окно, единственный `Root`, действия и владельцев возможностей.
Зависимости локальных crates объявлены через workspace; feature-crates не импортируют
оболочку. GPUI Kit закреплён прежним полным `rev`.

| Crate | Публичная граница |
| --- | --- |
| `taypeer-database-ui` | Сессии БД, каталог, навигация, поиск, редактор, история и формы |
| `taypeer-sync-ui` | `SyncState`, представление сети, приглашения и событие `ReceivedDatabase` |
| `taypeer-settings-ui` | `DeviceSettingsState`, оформление и сериализованное сохранение настроек |
| `taypeer-runtime-client` | Фоновые команды, `Connection` и `Ticket`; без GPUI |
| `taypeer-desktop-platform` | Lifecycle, защищённый буфер, путь профиля; приватный macOS helper |
| `taypeer-ui` | Тема, локализация, assets, формы и файловые диалоги GPUI |

Database передаёт settings собственный слот настроек БД. Settings и sync получают
узкие `SettingsHost`/`SyncHost` с намерениями пользователя, а не доступ к внутренним
полям соседнего экрана. Владельцы состояния устройства и сети живут независимо от
разблокированной БД; получение ciphertext не означает применения после unlock.
Общая презентация не зависит от feature views. Ошибки форм переводятся через общий
runtime-client; этот слой не запускает команды из render.

`DeviceSettingsState` владеет загрузкой и записью device settings; повторные
отправки блокируются до результата, новые recent files ожидают свою очередь.
Приветственный экран показывает сохранённые последние БД от новых к старым:
имя файла и локальный путь. Выбор повторно проверяет файл и открывает экран
разблокировки; открытая сессия при запуске не восстанавливается.
`PreferencesStore` загружает небольшой startup snapshot один раз, затем сохраняет
изменения в фоне одним writer. Изменения во время записи объединяются в следующий
snapshot, повреждённый файл не заменяется. Ошибка записи видна в UI.
Quit hook завершает текущую запись перед последним snapshot в пределах
штатного grace period GPUI; аварийное завершение не обещает сохранения настроек.

Сторы UI представлены `Entity<T>`. Переносимое состояние не импортирует GPUI.
LikeC4: `macosUi` и `uiEdit` в [модели](../architecture/macos-ui.c4).

## Файлы, права и подтверждение

- Создание спрашивает новый путь, мастер-пароль с повтором, имя, описание и KDF.
  Параметры входят в первую зашифрованную версию; существующий файл не заменяется.
- Открытие использует системный выбор файла и проверку контейнера, затем настоящую
  аутентификацию. При старте показываются последние пути, но сессии не восстанавливаются.
- `RuntimeHost` приобретает профиль при явном открытии/создании или запуске сценария подключения. Обычный запуск
  и чтение настроек не запрашивают Keychain. Каждый worker запускает тот же бинарник
  в приватном режиме `__worker`; пароль передаётся по pipe, не в argv.
- Доступность записи и управляющих настроек приходит из аутентифицированного сервиса.
  БД с доступом только для чтения не получает команд редактирования через UI.
- Формы метаданных, групп, атрибутов, цветов и URL изображения ждут ответа сервиса.
  Ошибки сохраняют ввод. Клон группы получает новые ID; удаление использует точную
  подготовленную выборку и перемещает её в корзину.

Настройки занимают всю рабочую область без дерева групп. Общая полоса вкладок
записи и настроек не имеет внешнего горизонтального отступа: каждый таб имеет
внутренний padding по 12 px, а подчёркивание первого таба примыкает к левому краю
при базовом масштабе. Начало редактирования сохраняет выбранную вкладку и
не фокусирует скрытое поле «Обзора».

## Редактор и асинхронные ответы

Один сервисный черновик объединяет Обзор, Дополнительно и Вид. Изменяются только
адресованные поля; нет загрузки сохранённой записи целиком обратно в сервис.
Неизменённый пароль или защищённый атрибут сохраняется через `Keep`. Для раскрытия
есть отдельные команды, для удаления пароля — отдельное действие `Clear`.
Время сохраняется с миллисекундами; незавершённая дата остаётся в черновике.

Команды worker выполняются последовательно вне UI-потока. «Сохранить» сначала ждёт
доставки ввода и замораживает редактирование, затем подтверждает `SaveDraft`. До
положительного ответа UI не завершает редактор и не выполняет отложенный переход.
Ответ старого отображения черновика не заменяет более новый ввод.
Применение входящих изменений worker передаёт отдельным уведомлением: каталог
обновляется фоновым запросом, без продления времени активности.
Уведомление использует `Worker::application_revision`, а не сравнение статистики
применения: одинаковый отчёт двух последовательных изменений не скрывает обновление.

Результаты поиска принадлежат конкретному запросу; клиент не повторяет правила
поиска по строкам. Детали и история загружаются отдельно. Подтверждения восстановления
версии и очистки истории сохраняют ID операции для точного повтора.

Каждый ответ проверяет открытость исходного `WorkerControl` при получении. Обновление
каталога дополнительно проверяет поколение сессии и номер запроса. После блокировки
старый ответ не может восстановить экран или раскрыть секрет.

## Вложения, иконки и генератор

Добавление вложения и изображения использует системный выбор файла. Сервис читает
и проверяет содержимое, применяет квоты и удерживает его в общем черновике. UI
показывает проверенные размеры. Экспорт выбирает единственный доступный вариант и
новое имя назначения; молчаливого перезаписывания файла нет.

Превью пользовательских иконок читает только доступные локальные blobs с лимитом
`ICON_LIMIT` и повторной проверкой изображения. Ни просмотр, ни поиск не вызывают
сетевых запросов. URL и favicon загружаются только по соответствующей команде.
При блокировке изображения этой БД удаляются из UI и кеша изображений GPUI.

Генератор вызывает общий `taypeer_services::generator`: системная криптографическая
случайность, настройки алфавита, исключения и локальный словарь EFF. Результат и
энтропия рассчитываются при изменении параметров/явном обновлении, не при render.
Вставка значения меняет пароль общего черновика.

## Сессии и буфер

Просмотр использует поля только для чтения с выделением текста. Пустое значение
обозначается прочерком; `AttributeView.has_value` сообщает о непустом защищённом
значении без его раскрытия. Кнопки копирования и раскрытия появляются при наведении
на заполненную строку. Выделение секрета проходит через тот же защищённый буфер.
Запрос helper содержит идентификатор; подтверждение записи не содержит текста.
Уведомление «Скопировано» появляется только после подтверждения системного буфера.
Ширина карточки сохраняется отдельно; дополнительную ширину окна получает таблица.
Cmd+Q завершает приложение после обработки несохранённых форм и закрытия сессий.

`SessionController` использует монотонный таймер и положительный интервал, по
умолчанию 300 секунд. Ввод, клики и действия форм учитываются как активность;
опрос результатов не продлевает сессию. Политика сохраняется отдельно через
`SessionSettings`, включая произвольный положительный интервал.

AppKit helper сообщает о сне и неактивной пользовательской сессии через
[NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace/sessiondidresignactivenotification).
Дополнительно используются уведомления `com.apple.screenIsLocked` / `Unlocked`;
эти имена не имеют публичного стабильного контракта Apple. Поток чтения helper
инвалидирует worker независимо от очереди UI. При потере helper доступ закрывается,
новая разблокировка требует его доступности. UI убирает дерево, запись, редактор,
раскрытые значения и модальные формы. Результат закрытия/сохранения черновика
показывается отдельно; недоставленный ввод не объявляется восстановимым.

Копирование паролей, защищённых атрибутов и результата генератора использует один
адаптер; он также перехватывает Copy/Cut защищённых полей ввода. Секреты получают
типы `org.nspasteboard.ConcealedType` и `TransientType`. По умолчанию очистка через
30 секунд; доступны другой положительный интервал и «Не очищать». Таймер удаляет
только запись с тем же `NSPasteboard.changeCount`; чужое копирование не очищается.
При закрытии helper он очищает только собственный секрет с включённым таймером.

## Синхронизация и приглашения

[SyncStore](../apps/taypeer/crates/taypeer-sync-ui/src/model.rs) владеет сетевыми задачами отдельно
от сессии открытого документа. UI вызывает API общего `RuntimeHost`, а не CLI-процесс.
После успешного открытия/создания БД или явного входа в подключение запускается
автоматический обмен. Приветственный экран сам сеть и Keychain не запускает.
Блокировка сохраняет обмен ciphertext; закрытие БД снимает её регистрацию в host,
выход завершает endpoint. Локальные команды не ждут сетевых запросов.

Экран устройств показывает проверенные DeviceId и роль управляющего. Локальное имя
берётся из настроек; имена удалённых устройств протокол пока не передаёт. Полный ID
доступен из строки устройства. Последняя попытка обмена и локальное применение
отображаются раздельно: ACK не подтверждает применение на удалённом устройстве.
Неприменённые источники показываются счётчиком, без произвольного разрешения.

«Поделиться» создаёт существующее пятиминутное приглашение. QR кодирует библиотека
`qrcode`; содержимое — тот же JSON `InvitationCode`, что понимает CLI. Копирование
использует защищённый буфер. Закрытие диалога убирает bearer из UI; отдельная команда
отменяет приглашение. Подтверждение и отклонение доступны управляющему в диалоге
и на экране устройств. Блокировка удаляет приглашение из отображения.

«Получить БД» принимает полный код через защищённое поле и спрашивает новый путь.
После подтверждения управляющим сохраняется зашифрованный файл; затем показывается
обычный запрос мастер-пароля. Камера не подключена. Пауза отменяет ожидание;
полностью полученные ciphertext-объекты остаются для возобновления. Публичный ID
запроса сохраняется без bearer, незавершённые подключения видны после перезапуска.

Relay выбирается локально: публичные серверы по умолчанию, один собственный HTTPS URL
или прямые соединения без relay. При ошибке изменения возвращается прежняя настройка
и предпринимается восстановление endpoint. Ошибка восстановления видна как остановленная
сеть. Изменение не переносится между устройствами.
`taypeer --profile PATH` позволяет проверять UI с изолированным нативным профилем, включая
его собственный `preferences.toml`.

## Ограничения и проверка

Touch ID отключён с объяснением. Корзина, отзыв устройств, передача управления,
восстановление доступа и разрешение конфликтов через UI пока не реализованы. Существующие конфликты полей
не выбираются произвольно; редактирование неоднозначных описательных метаданных
недоступно. Буфер macOS и рендерер имеют собственные копии данных; физическое
затирание всего графа GPUI, Automerge и системного буфера этим изменением не доказано.

Проверка интеграции — переносимые тесты состояния, сервисов и настоящего worker
на публичных искусственных dev5-файлах, общий `scripts/check.sh` и сборка `.app`.
Нативная проверка синхронизации выполняется отдельно на искусственных профилях;
она не закрывает полную проверку безопасности.
Нативные уведомления/буфер, IME, macOS 15 и Android требуют отдельной приёмки.
[Общий статус](roadmap.md) и [методика](testing.md) сохраняют эти открытые проверки.

## Жизненный цикл и масштаб

Inspector, SessionView, дерево групп и inputs создаются при построении или
наблюдаемом переходе состояния, а не в render. Подписки и задачи удерживает их
владелец. Render читает проекции; пользовательские команды выполняются в обработчиках.
Секретные inputs удаляются и очищаются при смене записи, поколения или блокировке.

Строки и ячейки таблицы получают ID из database ID, entry ID и ключа колонки;
группы — из database ID и group ID. Сортировка и вставка не меняют их идентичность.
Виртуализированная таблица хранит ширины в rem и обновляет геометрию при смене
базового шрифта. Resizable state пересоздаётся при изменении ширины viewport,
масштаба или состава панелей. Сохранённые ширины остаются в прежней шкале 16 px.

Тема принадлежит `taypeer-ui::theme`; после проекции вызывается `Theme::sync_base`.
Обычная геометрия использует rem. Намеренные исключения: геометрия нативного окна
и traffic lights, измеренные размеры resizable/QR canvas, пиксельный якорь шрифта.
RGBA полей записи — пользовательские данные; чёрный/белый QR — данные сканируемого
кода. Они не заменяют семантические цвета интерфейса.

## Будущие Linux и Windows

Общий shell находится в `src/desktop`; текущий GUI по-прежнему включён только
для macOS. Это подготовка границ, а не готовые порты. Не требуется переносить GPUI
на Android: Android остаётся отдельным Compose/UniFFI клиентом.

Перед включением каждой desktop-платформы нужны реализация lifecycle и защищённого
буфера за `taypeer-desktop-platform`, native shortcuts/decorations и profile paths,
проверка credential store и worker IPC общего runtime, файловой атомарности,
системных диалогов, fonts, accessibility и упаковки. Неподдержанная capability
не должна молча разрешать работу с секретами. Общий runtime/storage этим
рефакторингом не менялись; их переносимость требует отдельной задачи.
