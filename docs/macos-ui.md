# macOS UI и Rust runtime

Обычный запуск открывает UI по [макетам](../wireframes/README.md) на GPUI Kit.
Файловые операции выполняются общими Rust-сервисами через отдельный процесс для
каждой разблокированной БД. Каталог публичных образцов из production UI удалён.

## Владельцы состояния

| Владелец | Ответственность |
| --- | --- |
| [AppView](../apps/taypeer/src/macos/ui/mod.rs) | Композиция окна, время жизни экранов, фокус |
| [WorkspaceStore](../apps/taypeer/src/macos/ui/workspace.rs) | Открытые файлы, навигация, поиск, приём результатов, Save/Discard/Stay |
| [Backend](../apps/taypeer/src/backend.rs) | Фоновый `RuntimeHost`, последовательная очередь команд каждого `Worker`, типизированные ответы |
| [NavigationState](../apps/taypeer/src/ui_state/navigation.rs) | Выбор по стабильным core ID, сортировка, возврат к поиску |
| [CatalogStore](../apps/taypeer/src/ui_state/catalog.rs) | Маскированные строки и выбранные детали сервиса; без бизнес-команд и полного документа |
| [EditorStore](../apps/taypeer/src/ui_state/draft.rs) | Ввод трёх вкладок, адресные изменения, доставка команд, ошибки и версия отображения |
| `DatabaseService` внутри worker | Черновик, правила, версии, права, бинарное содержимое и надёжное сохранение |
| [PreferencesStore](../apps/taypeer/src/macos/ui/appearance.rs) | Прежний `preferences.toml`: язык, тема, текст, размеры панелей |
| [LocalSettings](../apps/taypeer/src/local_settings.rs) | Отдельный `device-ui.json`: имя устройства, таймер буфера, последние пути и ID; без секретов |
| [Platform](../apps/taypeer/src/macos/platform.rs) | Безоконный AppKit helper: события ОС, запись чувствительного буфера и очистка по владению |
| `header`, `sidebar`, `entries`, `inspector`, `editor`, `session`, `settings` | Отображение, ввод и подписки по времени жизни экрана |
| [Формы](../apps/taypeer/src/macos/ui/forms/mod.rs) | Общий ввод и ожидание результата; сценарии файлов, групп, атрибутов и бинарных объектов в отдельных модулях |

Сторы UI представлены `Entity<T>`. Переносимое состояние не импортирует GPUI.
LikeC4: `macosUi` и `uiEdit` в [модели](../architecture/macos-ui.c4).

## Файлы, права и подтверждение

- Создание спрашивает новый путь, мастер-пароль с повтором, имя, описание и KDF.
  Параметры входят в первую зашифрованную версию; существующий файл не заменяется.
- Открытие использует системный выбор файла и проверку контейнера, затем настоящую
  аутентификацию. При старте показываются последние пути, но сессии не восстанавливаются.
- `RuntimeHost` приобретает профиль только при явном открытии/создании. Обычный запуск
  и чтение настроек не запрашивают Keychain. Каждый worker запускает тот же бинарник
  в приватном режиме `__worker`; пароль передаётся по pipe, не в argv.
- Доступность записи и управляющих настроек приходит из аутентифицированного сервиса.
  БД с доступом только для чтения не получает команд редактирования через UI.
- Формы метаданных, групп, атрибутов, цветов и URL изображения ждут ответа сервиса.
  Ошибки сохраняют ввод. Клон группы получает новые ID; удаление использует точную
  подготовленную выборку и перемещает её в корзину.

## Редактор и асинхронные ответы

Один сервисный черновик объединяет Обзор, Дополнительно и Вид. Изменяются только
адресованные поля; нет загрузки сохранённой записи целиком обратно в сервис.
Неизменённый пароль или защищённый атрибут сохраняется через `Keep`. Для раскрытия
есть отдельные команды, для удаления пароля — отдельное действие `Clear`.
Время сохраняется с миллисекундами; незавершённая дата остаётся в черновике.

Команды worker выполняются последовательно вне UI-потока. «Сохранить» сначала ждёт
доставки ввода и замораживает редактирование, затем подтверждает `SaveDraft`. До
положительного ответа UI не завершает редактор и не выполняет отложенный переход.
Ответ старого отображения черновика не заменяет более новый ввод.
Применение входящих изменений worker передаёт отдельным уведомлением: каталог
обновляется фоновым запросом, без продления времени активности.
Уведомление использует `Worker::application_revision`, а не сравнение статистики
применения: одинаковый отчёт двух последовательных изменений не скрывает обновление.

Результаты поиска принадлежат конкретному запросу; клиент не повторяет правила
поиска по строкам. Детали и история загружаются отдельно. Подтверждения восстановления
версии и очистки истории сохраняют ID операции для точного повтора.

Каждый ответ проверяет открытость исходного `WorkerControl` при получении. Обновление
каталога дополнительно проверяет поколение сессии и номер запроса. После блокировки
старый ответ не может восстановить экран или раскрыть секрет.

## Вложения, иконки и генератор

Добавление вложения и изображения использует системный выбор файла. Сервис читает
и проверяет содержимое, применяет квоты и удерживает его в общем черновике. UI
показывает проверенные размеры. Экспорт выбирает единственный доступный вариант и
новое имя назначения; молчаливого перезаписывания файла нет.

Превью пользовательских иконок читает только доступные локальные blobs с лимитом
`ICON_LIMIT` и повторной проверкой изображения. Ни просмотр, ни поиск не вызывают
сетевых запросов. URL и favicon загружаются только по соответствующей команде.
При блокировке изображения этой БД удаляются из UI и кеша изображений GPUI.

Генератор вызывает общий `taypeer_services::generator`: системная криптографическая
случайность, настройки алфавита, исключения и локальный словарь EFF. Результат и
энтропия рассчитываются при изменении параметров/явном обновлении, не при render.
Вставка значения меняет пароль общего черновика.

## Сессии и буфер

`SessionController` использует монотонный таймер и положительный интервал, по
умолчанию 300 секунд. Ввод, клики и действия форм учитываются как активность;
опрос результатов не продлевает сессию. Политика сохраняется отдельно через
`SessionSettings`, включая произвольный положительный интервал.

AppKit helper сообщает о сне и неактивной пользовательской сессии через
[NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace/sessiondidresignactivenotification).
Дополнительно используются уведомления `com.apple.screenIsLocked` / `Unlocked`;
эти имена не имеют публичного стабильного контракта Apple. Поток чтения helper
инвалидирует worker независимо от очереди UI. При потере helper доступ закрывается,
новая разблокировка требует его доступности. UI убирает дерево, запись, редактор,
раскрытые значения и модальные формы. Результат закрытия/сохранения черновика
показывается отдельно; недоставленный ввод не объявляется восстановимым.

Копирование паролей, защищённых атрибутов и результата генератора использует один
адаптер; он также перехватывает Copy/Cut защищённых полей ввода. Секреты получают
типы `org.nspasteboard.ConcealedType` и `TransientType`. По умолчанию очистка через
30 секунд; доступны другой положительный интервал и «Не очищать». Таймер удаляет
только запись с тем же `NSPasteboard.changeCount`; чужое копирование не очищается.
При закрытии helper он очищает только собственный секрет с включённым таймером.

## Ограничения и проверка

Touch ID и будущие сетевые настройки отключены с объяснением. Новых экранов
устройств, P2P, корзины и разрешения конфликтов нет. Существующие конфликты полей
не выбираются произвольно; редактирование неоднозначных описательных метаданных
недоступно. Буфер macOS и рендерер имеют собственные копии данных; физическое
затирание всего графа GPUI, Automerge и системного буфера этим изменением не доказано.

Проверка интеграции — переносимые тесты состояния, сервисов и настоящего worker
на публичных искусственных dev5-файлах, общий `scripts/check.sh` и сборка `.app`.
Окна приложения и нативный Keychain в этой задаче не проверяются по указанию владельца.
Нативные уведомления/буфер, IME, macOS 15 и Android требуют отдельной приёмки.
[Общий статус](roadmap.md) и [методика](testing.md) сохраняют эти открытые проверки.
