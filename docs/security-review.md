# Разбор безопасности — 2026-10-18

Исходный срез: `41d8c66`; исправленный код и стенд зафиксированы в `2dd7205`.
Два отдельных агента независимо от авторов исходной
реализации прочитали storage/trust и runtime/services/Android; координатор
проверил исправления и регрессии. Это внутренний разбор исходников;
его область и оставшиеся технические проверки перечислены ниже.

## Область и находки

Проверены Argon2id и AEAD-поток, привязка credentials к DatabaseId/root/epoch,
подписанная цепочка управления и авторство, публикация файла и контрольные
отметки, открытие/ротация/восстановление, dormant host, приглашения, приватный
IPC, отзыв сессий, Android-потоки и диагностика. Это ограниченный обзор;
отсутствие дополнительных находок не доказывает полноту защиты.

| Находка | Последствие и исправление | Проверка |
| --- | --- | --- |
| Medium: Argon2 workspace без wipe | `hash_password_into` освобождал 64 МиБ производного от пароля состояния. В [crypto.rs](../crates/taypeer-storage/src/crypto.rs) теперь явный `Zeroizing<Box<[Block]>>` и `argon2/zeroize`; очистка входит в измерение KDF | Фиксированный Argon2id known-answer через настоящий `derive_measured`; KEK и формат сохраняются |
| Medium: MAC state без wipe | У уже используемого `poly1305 0.8.0` не был включён `zeroize`; Drop состояния gated этой feature. [Storage dependency](../crates/taypeer-storage/Cargo.toml) теперь явно включает её через workspace, без новых пакетов/версий | Оба lock/feature graph обновлены; формат не меняется, AEAD и корпус проверяются прежними регрессиями |
| Medium: read-ahead приватного IPC | Обычный `BufReader` оставлял дополнительную копию plaintext JSON в heap host. [PipeActor](../crates/taypeer-runtime/src/process.rs) читает кадры сразу в zeroizing-буферы | Actor-регрессия с двумя кадрами проверяет точные чтения header/payload без захвата следующего кадра |
| Medium: Android callback buffer | Rust `Vec` после чтения приватного потока освобождался без wipe. [Reader](../apps/taypeer-android/native/src/document/session.rs) сразу владеет им через `Zeroizing` | Границы 64 КиБ, частичная порция, EOF, ошибка и oversized-отказ без копирования |
| Low: секреты в Debug | `EntryPatch` печатал введённые значения, включая пароль. [Debug](../crates/taypeer-services/src/patch.rs) теперь целиком redacted; фактический production logging такого объекта не найден | Обычный и вложенный pretty Debug не содержат PUBLIC-маркер ввода |
| Durability: новые ancestor directories | Синхронизация leaf не подтверждала имена промежуточных каталогов credentials/joins. [Portable profile](../crates/taypeer-runtime/src/profile/portable.rs) подтверждает всю цепочку внутри предоставленного профиля, включая повтор после ошибки | Явная граница профиля, отказ в середине, повтор на уже видимых каталогах и symlink наружу без создания/смены прав внешних каталогов |

Memory-находки требуют доступа к памяти, swap или dump; удалённая эксплуатация
не показана. Затирание известных allocations следует из владения и реализации
`Zeroizing`, а не из чтения освобождённой памяти тестом. OOM-поведение Argon2
не изменено. Тест chunk-контракта Android не является измерением физического wipe.

Создание самого корня профиля и его внешних родителей остаётся открытым условием
power-cut приёмки. Для полной гарантии OS adapter должен передать явную уже
подготовленную базу каталогов. Без неё синхронизация всех предков до `/` выходит
за права Android-приложения; её не добавляли. Проверки внутренних credentials/joins
не доказывают надёжность первоначального provisioning корня профиля. Проверка
symlink выполняется до создания каталогов; она не обещает защиту от одновременно
меняющего дерево процесса с теми же правами пользователя.

Обход transport → author, подстановка credentials другой БД/root/epoch,
принятие неподписанного control, пропуск финального AEAD-кадра и публикация
частично расшифрованного файла в просмотренных путях не подтверждены.

## Что ещё требуется

Подтверждён незакрытый source-level остаток в `chacha20 0.9.1`:
`XChaChaCore::new` хранит временный `subkey`, а `hchacha` — временный
`[u32; 16] state` без явного затирания. Feature `zeroize` очищает основной
ChaCha core/буферы, но не эти temporaries. Исходник закреплённой реализации —
[RustCrypto HChaCha](https://github.com/RustCrypto/stream-ciphers/blob/chacha20-v0.9.1/chacha20/src/xchacha.rs).
Внешняя обёртка нашего AEAD этого не исправляет. Нужен проверенный upstream patch
или совместимое обновление зависимости и повтор регрессий; собственную
криптографическую реализацию не добавляли. Это отсутствие гарантии wipe по коду,
не доказательство наличия конкретной spill/register-копии или эксплуатации dump.

При проверке полного rollback учитывать откат всего локального профиля:
сохранённая рядом контрольная отметка сама по себе не защищает от её
совместного отката с БД.

Остаются открыты вся граница копий UniFFI/JVM/renderer, память целевых устройств,
swap/core dumps, системный буфер и lifecycle, длительный fuzzing и физическая
power-cut приёмка APFS/NTFS/Android. Rust 1.97.1 на Apple уже реализует
`File::sync_all` через `F_FULLFSYNC`; это не измерение поведения накопителя при
отключении питания. Различия проверок и команды — в [power-cut](power-cut.md),
датированные результаты — в [testing](testing.md).
