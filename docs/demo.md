# Файловая разработка и macOS demo

Обычный запуск `rtk cargo run --locked -p taypeer` открывает файловый UI:
«Создать БД» запрашивает имя, мастер-пароль и подтверждение, затем путь;
«Открыть БД» выбирает существующий файл и запрашивает его мастер-пароль.
Подтверждения записей и групп автоматически сохраняются. После перезапуска
файл открывается через системный диалог; пароли и список открытых сессий не сохраняются.
Файловые ошибки показываются отдельно; успешная запись подтверждается после sync.
Рядом находятся локальные `.lock`, `.draft` и `.backups`; для чтения копии нужны
сам `.taypeer` и его пароль. Формат экспериментальный, проверки безопасности остаются
открытыми: [контракт файлового среза](storage.md).

Демонстрационный режим предназначен для разработки на искусственных данных.
Он использует настоящий Automerge-документ, предметные проверки и общий Rust API,
но не создаёт зашифрованные файлы и не хранит БД между запусками.

## Запуск

Из корня репозитория на Apple Silicon Mac:

```sh
rtk cargo run --locked -p taypeer -- --demo
```

Публичный тестовый пароль: `SYNTHETIC-ONLY-Жук-42`.
Это тестовая проверка ввода, а не защита документа. Не вводить настоящие секреты.
Новая тестовая БД содержит ноль групп и записей. Сначала создаётся группа,
затем запись. Подтверждённые изменения и отложенный при блокировке черновик
доступны в пределах этого процесса; после выхода они теряются.

Для локального неподписанного `.app`:

```sh
rtk sh scripts/build-macos.sh
rtk open -n "target/Taypeer Demo.app"
```

Скрипт включает [иконку Taypeer](../wireframes/assets/taypeer-app-icon-v1.md)
в ресурсы `.app`. Штатные `sips` и `iconutil` создают `.icns` из исходного PNG
для обычных и Retina-экранов; производные файлы остаются в `target/`.

Сборка требует macOS 15+ ARM64; проверка на более новой macOS не заменяет
отдельную приёмку macOS 15. Это локальная демонстрационная сборка, не DMG
и не подписанный выпуск.

Без открытия окна, в том числе на Ubuntu:

```sh
rtk cargo run --locked -p taypeer -- --smoke-test
rtk sh scripts/check.sh
```

Smoke выполняет сценарий через Rust-сервис; он не подтверждает работу GPUI.

## Ответственность модулей

| Модуль | Ответственность |
| --- | --- |
| `taypeer-core` | Типизированные ID, группы, поля, атрибуты, валидация |
| `taypeer-document` | Automerge, исходный контекст черновика, адресные правки, варианты конфликтов, история |
| `taypeer-services` | Демонстрационные БД, команды, сессии и ограниченные представления |
| `taypeer` | macOS-экраны, ввод, навигация, локализация и настройки оформления |

Сервис возвращает ошибку для закрытой или устаревшей сессии. Результат связан
с поколением сессии; получатель проверяет его перед применением к UI.
Списки не содержат паролей и защищённых значений. Явное раскрытие проверяет сессию.

Редактор подтверждает целую пользовательскую правку через набор адресных
изменений. Отмена не создаёт историю. Входящие независимые изменения и варианты
конфликтов проверяются двухрепличными тестами без сети. Для конфликтующей записи
первый интерфейс ограничивается чтением и отметкой конфликта; произвольный
победитель не показывается как выбранный пользователем.

На диске допустимы только несекретные настройки интерфейса, отдельно от БД.
Тема и язык не восстанавливают открытую сессию и не сохраняют содержимое форм.

## Ограничения режима --demo

Файловый режим описан выше. Сеть и управление,
вложения, корзина, восстановление истории, UI разбора конфликтов, KDBX,
биометрия, буфер обмена, автоблокировка и Android не входят в этот срез.
Открытые проверки безопасности перечислены в [roadmap](roadmap.md).
Блокировка демонстрационного API не доказывает физического затирания памяти.

Исследовательские workspace в `spikes/` остаются изолированными. Приложение
не зависит от их кода; ревизии и результаты используются как исходные доказательства.

## Локальная проверка 2026-09-09

На Apple Silicon, macOS 26.6.2 (25G83), прошли `sh scripts/check.sh`
(Rustfmt, Clippy, тесты, Rustdoc, release и smoke), `pnpm arch:build`.
Обновлённые представления `implementation` и `demoEdit` экспортированы и просмотрены.

Через Peekaboo проверены создание пустой БД и группы с кириллицей,
ввод/вставка полей и многострочной заметки, сохранение через Cmd-S,
защищённый атрибут, две версии истории, поиск по заметке и исключение
защищённого значения. Cmd-L закрывает редактор; новый вход предлагает явное
восстановление черновика и возвращает изменённые поля. Проверены диалог
несохранённых изменений и «Остаться», переключение БД с сохранением независимой
разблокированной сессии, русский язык, светлая тема и сохранение настроек.
При размере содержимого 1100×720 нижние поля доступны прокруткой;
срок `2030-01-02 03:04` сохранён и показан в просмотре.

Обнаруженная потеря фокуса после удаления редактора исправлена: фокус
переводится на сохраняемый элемент окна. В пересобранном приложении сценарий
«сохранить → история → Cmd-F → ввод» направил строку в поиск и отфильтровал список.
Последний общий скрипт проверки прошёл после исправления; затем повторялся
только этот GUI-сценарий. Локальные снимки находятся в игнорируемом
`artifacts/demo-qa/`, включая `entry.png`, `min-expiry.png` и `cmd-f-fixed.png`.

Это выборочная проверка demo, не полная UI-приёмка. Отдельно остаются macOS 15,
IME composition и длительный быстрый ввод, вся матрица клавиатурной навигации,
автоматическая смена темы ОС и Android. При автоматизации встречались stale
snapshot/фокус и ошибки ScreenCaptureKit; снимки нужного окна получены через
CoreGraphics. Успех доставки клавиш без подтверждения состояния не засчитывался.
