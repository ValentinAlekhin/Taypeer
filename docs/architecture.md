# Архитектура Taypeer

Структура, зависимости и ключевые взаимодействия имеют один источник —
[модель LikeC4](../architecture/model.c4). Модель охватывает v1, а не только
существующий код. Она не определяет байтовый формат и не подтверждает приёмку.

## Просмотр и изменение

Из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm arch:dev
pnpm arch:check
pnpm arch:build
```

На машине владельца команды выполняются через RTK. pnpm 10.17.1 устанавливает
проектный Node.js 22.22.3; системный Node не заменяется. `arch:dev` выводит адрес
локального просмотра (обычно `http://127.0.0.1:5173`). В просмотрщике представления
доступны по `/view/<id>`. Для скачанного артефакта CI распаковать сайт и выполнить
`pnpm exec likec4 preview architecture -o artifacts/architecture`, либо запустить любой
локальный HTTP-сервер из каталога распакованного сайта. Публикация не настроена.

## Границы реализации

Общие бизнес-правила реализуются на Rust; ядро не импортирует GPUI, Iroh, FFI
или API ОС. Порты ввода-вывода определяются потребностями сценариев, адаптеры
подключаются приложением. Логический компонент в модели не требует отдельного
crate: пустые traits и crates на будущие функции заранее не создаются.
Изолированные spike сохраняют свои workspace и lockfile.

Два фронтенда выбраны по [результату UI-исследования](../spikes/README.md#решение-по-фронтендам--2026-09-08):
общие правила остаются в Rust, экраны, навигация и фокус принадлежат платформам.
В целевой интеграции desktop вызывает общие сервисы через worker/runtime,
Android — через адаптер UniFFI, принадлежащий приложению, и isolated worker.
Адаптер предоставляет команды, ограниченные представления и события,
не экспортируя файловый формат или сырое дерево Automerge.
Локализация использует rust-i18n на macOS и Android string resources на Android:
общие смысловые ключи и одинаковые продуктовые сообщения en/ru.

Генератор Android получает типизированный результат общего Rust-сервиса:
значение, общую оценку качества и энтропию, рассчитанную из известного метода
выбора символов или слов.
Kotlin управляет вводом и поколением запроса; изменение параметров отзывает старый
результат, а запоздавший ответ после блокировки или новой правки не применяется.

Наблюдатель применения передаёт два независимых номера: ревизию последнего отчёта
и ревизию последнего отчёта с надёжно применёнными изменениями данных либо control
baseline. Отдельный `ApplyReport.changed` учитывает baseline при нулевом счётчике
оригинальных изменений.
Вторая отметка сохраняется через последующие пустые, отложенные и ошибочные
отчёты в том же поколении worker. Android обновляет статус на каждый отчёт,
а отзывает раскрытые значения и запрошенное копирование при изменении отметки
применения. Это сохраняет событие между опросами и не выдаёт пустой отчёт за
изменение текущего документа. Блокировка и потеря фокуса независимо отзывают доступ.

Камера Android принадлежит платформенному UI: CameraX связывает preview и анализ
с lifecycle Activity, ZXing распознаёт QR локально. Кадры не сохраняются и не
передаются Rust или сети. Результат заполняет временную форму приглашения;
только явное «Подключиться» вызывает существующий проверяемый Rust-допуск.
При закрытии сканера отложенный кадр не завершает старую форму, каждый буфер
освобождается. При уходе в фон код формы очищается. Отказ в разрешении и отсутствие
камеры оставляют доступным ручной ввод; камера не является условием установки.

Android выбирает общие relay по умолчанию, собственный HTTPS relay или прямой
транспорт без relay через типизированный UniFFI-интерфейс. Настройку хранит
локальный Rust-профиль; изменение применяет общий транспорт с возвратом прежней
настройки при отказе. Kotlin отображает выбор и передаёт команды. Прямой режим
не обещает обнаружения изменившихся адресов после перезапуска обоих пиров.
Автоматические сетевые сценарии явно выбирают прямую связь или локальный TLS relay,
поэтому не зависят от доступности публичных серверов.

Android наблюдает непредметный счётчик и типизированный статус применения входящих
в текущем поколении worker. После надёжного применения UI повторно читает список
и открытый inspector через тот же документный интерфейс. Локальный ввод редактора
и его несохранённая ревизия остаются самостоятельными; входящий ответ их не заменяет.
После блокировки или замены поколения наблюдатель и поздние ответы отзываются.
Сетевой приём ciphertext и применение в разблокированном worker отображаются отдельно.

Сравнение версии читает две маскированные проекции через существующие команды
истории и текущей записи. Сохранённая сторона неизменна, текущая сторона обновляется
при входящем применении; это не новый сохранённый снимок документа. Раскрытие и
копирование каждой стороны требуют отдельного действия. Обновление, потеря фокуса,
смена версии или закрытие отзывают ожидающие защищённые ответы. Сравнение не пишет
историю и не принимает решения об объединении вместо общих сервисов.

Отложенные источники Android открываются отдельным явным действием. Непринятые
пакеты (`ReceivedSources`) и поздние события очищенного поколения (`PendingSources`)
имеют разные общие команды. Первые ещё не допущены к применению, вторые уже входят
в аутентифицированную историю документа. CRDT actor позднего события не обозначает
текущий сетевой допуск устройства. Список передаёт идентификаторы без содержимого;
просмотр возвращает маскированное исходное состояние. Отдельная команда раскрывает
только явно выбранный вариант пароля с его точными origins.
Извлечение передаёт общему сервису источник, активную группу и сохраняемый при повторе
ID операции; оно создаёт новую запись или группу, сохраняет происхождение и оставляет
старое поколение закрытым. Неподтверждённый запрос удерживает только идентификаторы
в владельце UI-состояния, в том числе при уходе с экрана и блокировке. Его можно
повторить напрямую, если исходный список уже изменился; это не журнал восстановления
запроса после завершения процесса. Удаление доступно только для непринятого пакета,
требует подтверждения и сохраняет общий маркер отказа от автоматического применения.
Разблокированная сессия и её поколение ограничивают каждый ответ; потеря фокуса,
уход с экрана и блокировка очищают раскрытые значения.

Интервал автоблокировки и политика очистки буфера принадлежат локальному Rust Host.
Настройка сначала надёжно сохраняется, затем применяется и возвращается как
типизированное подтверждённое представление. Создание Host загружает сохранённую
политику; повреждение или неподдерживаемая версия не заменяются defaults.
Kotlin хранит только последний подтверждённый applied view. Копирование использует
его синхронно; оно не удерживает пароль до завершения фоновой загрузки настроек.
Явное отсутствие интервала буфера означает «Не очищать». При подтверждённом отказе
публикации сохраняются прежняя квитанция и её срок; неопределённый отказ ОС не
выдаётся за подтверждённый откат. В последнем случае адаптер удерживает прежнюю
и новую квитанции с исходными сроками до проверки текущего token и HMAC; содержимое
буфера в квитанции не сохраняется. Таймер учитывает оба возможных исхода публикации.

Android-корзина получает маскированный список от общего runtime. Подготовка
восстановления или окончательной очистки удерживает точный `PreparedLifecycle`
внутри текущей native-сессии. UI получает только идентификатор подготовленного
выбора и его состав для подтверждения; подтверждение не готовит выбор повторно
и не захватывает поздние сетевые изменения. Блокировка отзывает такие выборы.
Перемещение и клонирование передают типизированные команды общим сервисам;
Kotlin не повторяет правила дерева, истории или надёжной публикации.
Неподтверждённые перемещение, клонирование и восстановление версии удерживают
исходный ID операции и точный выбор назначения в владельце Android-состояния.
Уход с экрана и блокировка очищают представления, сохраняя эти запросы в памяти
для той же БД. Клонирование также удерживает введённое обычное имя; пароль и
маскированные DTO в этот список не входят. Прямой повтор не требует повторного
просмотра исходника, который уже мог быть очищен. Подтверждённый native-ответ
завершает запрос до обновления экрана; ошибка последующего чтения не отменяет
надёжное подтверждение. Этот ограниченный список не восстанавливается после
завершения процесса. Неподтверждённая смена пароля удерживает точный ввод только
в текущей открытой форме до повтора или блокировки; закрытие формы до разрешения
результата недоступно, блокировка отзывает введённые значения.

### Общий desktop UI

Обычный запуск использует компоненты GPUI Kit, стор окна, кеш маскированных
представлений и общий редактор. [Владельцы состояния](macos-ui.md) соответствуют
`macosUi` и `uiEdit`. `Backend` выполняет команды `RuntimeHost` / `Worker` вне UI,
проверяет поколения и удерживает полный документ только в отдельном процессе БД.

[desktop.rs](../apps/taypeer/src/desktop.rs) собирает ресурсы, команды и окно.
Возможности выделены в шесть локальных crates внутри `apps/taypeer/crates`;
[контракт desktop UI](macos-ui.md#границы-crates) задаёт владельцев и зависимости.
Один desktop-компонент имеет текущий macOS deployment и целевой Linux v1 и будущий Windows
deployments в `desktopTargets`. Статусы модели не подтверждают приёмку портов.
Безоконный Swift/AppKit helper обслуживает уведомления ОС и буфер обмена;
системные файловые диалоги предоставляет GPUI. Отдельный `--smoke-test`
проверяет демонстрационный сервис без открытия окна.

## Сессии и секреты

### Ручное сохранение — целевые границы 2026-10-07

Контракты ниже запланированы по [плану автоматизации](automation-plan.md),
а не подтверждены историческими срезами. Services владеет несколькими
причинными черновиками записей/групп/БД, активным указателем, неизменяемыми
снимками попыток и различием записи БД/локальной формы. Document владеет
числовой OpId-проекцией и историей всех объектов. Storage публикует файлы
единым алгоритмом и хранит один зашифрованный bundle коллекции на рабочую копию.

Host/profile единолично выбирает профиль и внутренние пути: системная директория
через `directories::BaseDirs`, явный суффикс приложения, явный профиль тестовой конфигурации.
macOS default desktop сохраняет `~/Library/Application Support/Taypeer`, Linux —
`$XDG_DATA_HOME/taypeer/profiles/default` с системным fallback. Host публикует
каталог лишь после надёжной записи; открытие внешнего файла создаёт внутреннюю
копию без изменения источника или сетевого допуска. Автопереноса старых
профилей нет; явный перенос своего рабочего файла сохраняется.

Восстановление доверенного набора — явная операция безопасности. После надёжной
публикации нового файла host сохраняет публичную квитанцию, связывающую БД,
прежний root, новый root, канонический файл и точный ID восстановления. Повтор
аутентифицированной операции восстанавливает недостающую квитанцию. После закрытия
прежнего worker и writer явное открытие этого результата проверяет квитанцию,
защищённую регистрацию и файл, затем атомарно меняет catalog item. Старый файл
сохраняется. Обычное открытие внешнего файла с другим root по-прежнему не меняет
закреплённый доверенный набор; сама регистрация без recovery receipt недостаточна.

Desktop/Compose владеют фокусом, навигацией с выбором Save / Discard / Stay
и явными кнопками сохранения. Валидация, снимки, повторы и причинное
редактирование остаются общими Rust-правилами.
Ответ несёт идентичность захваченной ревизии и OperationId; клиент проверяет
БД, поколение сессии и экземпляр редактора. Продолжение формы возвращает
маскированную проекцию. Блокировка независимо от I/O немедленно закрывает доступ.
Android worker получает ciphertext через непрозрачные Binder-дескрипторы,
а не desktop spool-пути; Keystore и сеть принадлежат host.
Платформенный worker использует общий приватный командный поток, dispatch сервисов
и независимый ProcessControl. CipherPersistence реализуется через ограниченные
дескрипторные передачи: immutable snapshot, encrypted candidate и local draft.
Каждая передача владеет lease и освобождается после подтверждённого потребления.
Author capability запрашивается worker только после аутентификации snapshot
(либо явного создания); Keystore API и ключ чтения в эту границу не входят.
UniFFI клиента экспортирует предметные команды и представления; сериализация
приватного IPC и ciphertext-метаданных не является универсальным API документа.

Вложения из SAF используют отдельную capability выбранного пользователем потока,
а не порт ciphertext persistence. Host удерживает descriptor только на время
одной операции. Непрозрачный ID связан с БД, поколением worker и формой;
worker читает порции до 64 КиБ и шифрует их общим BlobStore без plaintext
временного файла. Rust проверяет размер, квоту, видимость и квитанцию повтора.
Экспорт получает отдельный выбранный output; успешный ответ требует завершения
записи и fsync. Отмена или блокировка отзывает capability и не меняет прежнее
вложение. URI и host-пути не становятся приватными командами документа.

Общий PlatformState содержит только SessionController, события, доступность,
активность и настройку буфера. Нативные события и владение копированием остаются
у адаптеров ОС. Windows не входит в v1; узкие границы позиционного I/O,
приватных каталогов, идентичности путей и публикации сохраняются без полного порта.

### Локальный файловый срез

`DatabaseService` использует `taypeer-storage` для создания, открытия и подтверждения
экспериментальных зашифрованных файлов. Кандидат документа публикуется после записи;
при ошибке черновик остаётся доступен для исправления или повторной попытки.
Файловая блокировка освобождает документ и ключ, локальная форма хранится отдельно
в зашифрованном sidecar. Физическое затирание всего графа Automerge не доказано.

Файловые команды доступны через Rust API и desktop/Android UI. Подробный контракт, версия и ограничения — в [локальном хранилище](storage.md).

### Первый демонстрационный срез

`taypeer-core` задаёт типизированные значения и правила без зависимости от
Automerge. `taypeer-document` реализует адресные изменения документа и историю;
`taypeer-services` координирует команды, черновики и поколения сессий.
Headless smoke вызывает сервис напрямую. Внешнего API, UniFFI и стабильной сериализации
эти Rust-интерфейсы пока не определяют.

Демонстрационный сервис хранит искусственные Automerge-документы и отложенные
черновики в памяти процесса. Тестовая разблокировка проверяет публичный образец,
но не выполняет KDF и не является аутентификацией. Подтверждение изменяет только
состояние в памяти: зашифрованный рабочий файл и долговечная запись не
реализуются этим путём. После перезапуска данные теряются.

Каждый доступ к документу проверяет идентичность БД и поколение сессии.
Блокировка закрывает доступ сервисного API и инвалидирует прежние ответы;
повторная разблокировка создаёт новое поколение. Искусственный документ и отложенный черновик
остаются в демонстрационном backend; это не реализация очистки открытой БД
из памяти и не доказательство защиты реальных секретов.

Черновик хранит исходный контекст Automerge. Подтверждение адресно изменяет
только отредактированные поля относительно этого контекста и в той же
транзакции создаёт одну сохранённую версию. Merge версии не создаёт.
Конфликтные поля сохраняют все варианты. Подключение этих данных к macOS UI
и пользовательский разбор в нём остаются впереди.

Подробности запуска и границы первого среза: [демонстрационная разработка](demo.md).

### Реализованная защита процессов БД

`taypeer.sessionGuard` соответствует `SessionController` в `taypeer-runtime`.
Он владеет общей политикой `SessionPolicy`, монотонными часами и независимым
supervisor процессов. Отдельный actor владеет командными pipe и ciphertext
callbacks; он не блокирует отзыв доступа или принудительное завершение.
[Контракт сессий](sessions.md) задаёт поколения, двухсекундное закрытие,
результат черновика, EOF, настройки и ограничения. API событий ОС реализован;
подключение UI и native lifecycle этим срезом не подтверждается.

### Требования продуктовой реализации

Ключи БД и полный расшифрованный документ принадлежат Rust-сервисам. Каждый вызов
проверяет сессию; блокировка закрывает доступ независимо от экрана. Фронтенд
очищает введённые и показанные секреты и отклоняет запоздавшие результаты закрытой
сессии. Отмена задачи или освобождение FFI-обёртки не заменяют явную блокировку.
Открытые секреты не входят в журналы и saved state Android.

Очистка UI не гарантирует физического затирания промежуточных копий JVM/FFI.
Простой drop Automerge также непригоден как доказательство очистки:
[исследование памяти](../spikes/encrypted-sync/REPORT.md). Граница памяти
проверяется вместе с реальными UI и сервисами, а не только синтетической сессией.

Фоновые задания получают и пересылают зашифрованные данные с отдельными сетевыми
учётными данными, без ключей чтения. Получение, применение и автоматическое объединение
имеют разные результаты. Надёжная запись предшествует подтверждению успеха.
Блокировка выполняется даже при ошибке сохранения зашифрованного черновика.

Тяжёлые операции выполняются вне UI-потока; завершение после блокировки не открывает
БД повторно. Сессии, ключи и допуски разных БД изолированы. Файловые диалоги,
биометрия/Keystore, буфер, lifecycle и фоновые задания имеют платформенные
адаптеры. Их API и время жизни проверяются в первой искусственной вертикали.

## Данные и эволюция

Представление документа, конфликтов, истории, очистки и удержания blobs определяет
[контракт данных](data-model.md). Ядро задаёт правила, адаптер Automerge сохраняет
все варианты; общий Rust-контракт выбирает детерминированную проекцию, UI
показывает выбранное состояние и альтернативы в истории. Производные
индексы можно перестроить. Подписанное управление не является обычной CRDT-map.

[Контракт совместимости](compatibility.md) отдельно определяет чтение, запись,
получение и восстановление. Поддержка внешней оболочки не означает поддержку
расшифрованной схемы. Конкретные Rust/UniFFI-сигнатуры появляются вместе со
сценариями; имена в документах не являются готовым публичным API.

В текущем срезе `compatibility` реализован чистым модулем `taypeer-core`:
`SchemaDescriptor`, `ClientCapabilities`, `CompatibilityReport`. Trust подписывает
дескриптор, Document проверяет его соответствие данным, Services ограничивает
операции, Storage и runtime дают отчёт без расшифровки. Evolution остаётся будущим
механизмом миграций. Приём ciphertext не зависит от поддержки reader/writer,
но сохраняет все проверки внешней оболочки, допуска и надёжной записи.

## Тема интерфейса

Выбор пользователя, известный режим ОС и активная палитра — разные значения.
Платформа поставляет события appearance; приложение выбирает палитру по
[правилам темы](../spec.md#тема-интерфейса). GPUI, Compose и разбор TOML темы
не входят в чистое ядро. Обе сборки используют один встроенный источник палитр,
с отдельными адаптерами к UI. Смена палитры не пересоздаёт сессию БД.
Будущая персонализация и правила её файлов описаны только в спецификации.

## Условия проверки формата

До работы с настоящими паролями необходим проверенный проект и приёмка реализации:

- Версии файла, аутентифицированное шифрование и целостность.
- Разделение сетевых учётных данных, ключей чтения, управления и биометрии.
- Подготовка, хранение и ротация ключей, допустимые параметры KDF.
- Авторство зашифрованных изменений, проверка, надёжная запись, повторы и применение.
- Приглашения, передача управления и отзыв при запоздавших изменениях.
- Пропущенные ротации, чтение поддерживаемых старых файлов и несовместимые версии.
- Чтение по файлу и паролю отдельно от допуска и восстановления нового доверенного набора.

Исследовательские решения и ограничения находятся в [отчётах](../spikes/README.md),
оставшаяся приёмка — в [этапе 2](roadmap.md#2-локальная-бд-и-первая-вертикаль-интерфейса).
Решение о начале искусственной UI-вертикали не подтверждает безопасность.
Уплотнение CRDT, ресурсные границы и защищённая память требуют своих проверок;
упоминание Iroh, Automerge или Argon2id их не заменяет.

## Общий runtime и процесс БД

Desktop запускает собственный executable в частном режиме worker; Android
использует изолированную службу. Пользовательского CLI больше нет. Worker
последовательно вызывает общий сервис и удерживает единственный документ.
Host получает ограниченные маскированные представления, а не весь документ
или ключи чтения. Контракт — в [runtime](runtime.md).

Закрытие — явная операция с результатом; Drop только завершает процесс.
Независимый контроллер сразу отзывает доступ и ограничивает завершение двумя
секундами. Ошибка черновика не отменяет блокировку; UI не ждёт IPC в потоке окна.
Нативная интеграция и очистка платформенных копий требуют отдельной приёмки.

## Бинарный локальный срез

`taypeer-core` задаёт AttachmentId/BlobId, иконку, RGBA и продуктовые defaults.
`taypeer-document` хранит только адресные ссылки и оформление, историю,
конфликты и receipts; он пересчитывает удержание по доступным поколениям и
поздним источникам. `taypeer-storage` владеет каталогом и потоками отдельного
бинарного содержимого, зашифрованным staging и атомарными файлами.

`taypeer-services` проверяет сессию, квоту, доступность выбранного blob и
подтверждает кандидата после сохранения. Его загрузчик иконок — единственный
новый сетевой адаптер этого среза: явные HTTP(S)-запросы и проверка изображений.
Desktop отправляет worker команды и выбранные пути; Android передаёт
ограниченные потоковые capabilities. Бинарные байты не входят в JSON IPC.
Группа скачивает favicon по отдельным идемпотентным командам записей.
Новые экраны UI работают с отдельными образцами в памяти; подключение бинарных
сервисов к ним ещё предстоит. Прежний редактор сохраняет незнакомые ему поля
оформления и вложений. Модель взаимодействия — `binarySave`; точный формат и
границы ресурсов находятся в [storage](storage.md) и [runtime](runtime.md).

Секции dev-схемы 3 полностью покрыты существующим AEAD-потоком. Они не являются
подписанным управляющим manifest и не дают сетевого допуска. Полная проверка
сложности парсеров, жёстких сроков worker и секретов на целевых ОС остаётся открытой.

Linux v1 сохраняет общий desktop и runtime с отдельным worker каждой БД.
[Linux-контракт](linux.md) определяет Nix deployment, платформенные адаптеры
и ленивые локальные контексты; [storage](storage.md) и [sessions](sessions.md)
задают credentials, транспортную capability и подготовленную ротацию.
