# План реализации

Состояние сверено с кодом 2026-10-18. Требования первой версии задаёт
[spec.md](../spec.md), команды и датированные доказательства —
[testing.md](testing.md). Наличие реализации, доступность действия в клиенте
и приёмка на целевой ОС — разные статусы. Завершённые планы не являются
инструкциями для текущей версии.

## Состояние реализации

Текущий формат — кандидат stable1: обязательная активная группа записи,
ручное сохранение и несколько зашифрованных локальных форм. Старые dev-файлы
сохранены как исторические fixtures и отклоняются без миграции. Рабочие БД находятся внутри
профиля; открытие внешнего файла сохраняет источник и не выдаёт сетевой допуск.
Новые профили macOS/Linux/Android используют общий зашифрованный backend без
Keychain/Keystore для основных credentials. После перезапуска каждая БД активирует
транспорт своей первой разблокировкой; последующая блокировка сохраняет обмен.
Windows охвачен библиотекой хранения, без клиентского UI и runtime IPC.

## Desktop: незавершённые функции

Пробелы подтверждены по desktop views и их вызовам runtime. Общие команды
большинства перечисленных действий уже существуют; подключение в Android
не означает их доступности в desktop.

- [ ] Подключить смену мастер-пароля и отзыв устройства с обязательной ротацией.
  Добавить обе стороны передачи управления, продолжение прерванного перехода
  и восстановление нового доверенного набора после потери управляющего/fork.
- [ ] Реализовать Touch ID на поддерживаемом Mac: настройка отдельной БД,
  OS-protected key, вход, отключение и fallback к мастер-паролю.
- [ ] Подключить корзину: список, восстановление с активным назначением,
  точная подготовленная выборка и подтверждаемая окончательная очистка.
  Сейчас кнопка отключена; после удаления доступен только Undo.
- [ ] Подключить клонирование и перемещение записи между активными группами,
  а также явный перенос собственного рабочего файла.
- [ ] Дополнить историю групп и метаданных БД просмотром сохранённых значений,
  исходных альтернатив и восстановлением версии. Текущий UI даёт список и очистку.
- [ ] Добавить родителя в общий черновик формы группы, загрузку её значка по URL
  и групповую загрузку favicon с явными рекурсией/заменой.
  Изменение вложенности через DnD уже работает.
- [ ] Добавить замену содержимого вложения, размеры при просмотре, расход квоты
  и превышение после merge. Уже принятые данные при превышении сохраняются.
- [ ] Подключить просмотр, раскрытие, извлечение и явное удаление непринятых
  источников; отдельно — поздние правки очищенного поколения.
- [ ] Показывать фактическое время KDF отдельно от целевого бюджета.
  Доступность пира теперь отражает активное аутентифицированное соединение;
  отсутствие соединения остаётся «Неизвестно», без выдуманного offline/last-seen.
- [ ] Дополнить свойства локальной отметкой «Доступ», срок — включением и
  предустановками, создание БД — оценкой мастер-пароля. Сканирование QR камерой
  desktop не подключено; ручной ввод приглашения доступен.

Критерии: действия проходят настоящие обработчики AppView и runtime, проверяют
надёжный результат повторным открытием файла или наблюдением второй реплики.
Новые native-гарантии требуют отдельной проверки ОС. Существующие сценарии
и сравнение компонентов с FIG перечислены в [testing](testing.md#быстрые-rust-сценарии-macos-ui).

## Android: оставшиеся проверки

CameraX QR, relay, изображения, родителя группы и локальное время доступа.
Recovery, двусторонний handoff, SAF «Сохранить копию» и продуктовая биометрия
подключены. Это не закрывает проверки новых APK.

  Доказательства и оставшиеся FAIL — в [testing](testing.md#следующий-исходный-срез--2026-10-08).
- [ ] Завершить eager70 на настоящем worker: все строки, пиксели, предел preview

- [ ] Выполнить новую полную API31/API36/API36-16КиБ матрицу, отдельные camera-denial
  и biometry stages с явной авторизацией PUBLIC OS fixtures.
- [ ] Обновить шесть visual profiles, пройти review baseline и получить coverage
  на одном frozen APK/classes/source. Старые проценты относятся к своим hashes.
- [ ] Проверить оптимизированную release-сборку и системные picker/камера/биометрию,

## Безопасность и платформенная приёмка

До работы с настоящими паролями остаются обязательными:

- [ ] Проверка всей границы секретов вместе с UI, FFI, KDF, renderer,
  системным буфером, swap/core dumps. Drop Automerge не доказывает стирание;
  отдельный worker не доказывает очистку всех платформенных копий.
- [ ] Независимый разбор криптографического формата, разделения ключей,
  подписанного manifest и авторства, ротаций/отзыва, восстановления и ресурсов
  полной схемы; длительный fuzzing и проверка угроз полного rollback.
  [Внутреннее независимое ревью 2026-10-18](security-review.md) выявило
  копии секретов; локальные исправления и включение Poly1305 wipe не закрывают
  найденные temporaries HChaCha, внешний аудит и всю границу памяти.
- [ ] Матрица I/O-отказов и power-cut на целевых устройствах: durable ACK,
  атомарная публикация, неопределённый результат, конкурентный writer,
  история/blobs/черновики и отсутствие ложного успеха.
  Подготовлен [Linux/ext4 ACK replay baseline](power-cut.md); фактический replay
  ещё не выполнен, ядро тестовой машины OrbStack не поддерживает нужный target.
- [ ] macOS 15+ Apple Silicon: новый переносимый профиль, реальные sleep/lock/resume,
  защищённый буфер с сохранением чужого копирования, picker, IME/VoiceOver,
  клавиатура/overlays, en/ru, темы и масштаб 14/16/18.
- [ ] NixOS x86_64 с niri/Wayland: файловые диалоги, смена темы/масштаба,
  буфер через живое окно, системная блокировка и сон/возобновление.
  Native adapter, credentials, worker IPC и production Nix-пакет уже реализованы;
  частичные подтверждения находятся в [Linux runbook](linux.md).
- [ ] Реальный ARM64 Android 12+: KDF под нагрузкой, Keystore/биометрия,
  системные дескрипторы, storage, память и фоновые ограничения.
- [ ] Windows: нативный запуск storage/core/trust CI и power-cut-проверки.
  MSVC cross-check проверяет типы, а не файловую надёжность или ACL на Windows.

Результаты исследований и принятые решения остаются в [spikes](../spikes/README.md).
Автоматические AppView/AVD-проверки и статические FIG не закрывают эти условия.
