# Проверки подписанного обмена — 2026-09-15

> Исторический отчёт о CLI, удалённом 2026-10-07. Результаты ниже
> не являются приёмкой текущего UI или dev7. Актуальные команды проверок
> общего runtime приведены в [testing](testing.md).

Результаты командного среза dev-схемы 4 на macOS.
Этот отчёт не закрывает продуктовую приёмку безопасности из roadmap.
Все записи и пароли в сценариях искусственные, с маркером `PUBLIC`.

## Проверено

- Финальный обычный `sh scripts/check.sh` прошёл: архитектура, Rustfmt,
  сборка targets, Clippy, 128 Rust-тестов, Rustdoc, release и headless smoke.
  Семь нативных CLI-тестов явно пропущены: после жалобы владельца на системные
  окна они запускаются только через `--native-keychain`. Это не повторная
  нативная приёмка последней правки. Затронутые схемы экспортированы и просмотрены.

- `python3 scripts/test-cli-p2p.py`: три независимых процесса CLI, три профиля
  с настоящим macOS Keychain, приглашение по Iroh, явный допуск управляющим,
  загрузка нового файла, разблокировка и сходимость подписанной правки.
  Заблокированный получатель сохраняет ciphertext и применяет его при входе.
- `cargo test -p taypeer-cli --test p2p -- --ignored`: тот же сценарий через локальный HTTPS
  relay. В каждом CLI отключены прямые IP-транспорты; тестовый сертификат явно
  передаётся как доверенный корень. Проверка сертификата и имени сервера включена.
- Сервисные сценарии до продолжения этапа: долговечные
  правки и копия только для чтения; офлайн-конфликт/история/черновик через ротацию;
  точный повтор административного действия после открытия; отказ старым токенам
  после повторной аутентификации; отказ непринятым источникам отозванного автора
  и их зависимостям внутри checkpoint действующего участника. Независимая правка
  действующего автора в последнем сценарии применяется.

Дополнительно в продолжении этого исторического этапа прошли:

- Три CLI-процесса через TLS relay: отдельный восстановленный файл, повтор с тем же
  ID операции и паролем, неизменность исходника, открытие, очистка и новая правка.
- Сервисные сценарии: ручной просмотр/раскрытие/извлечение/удаление исходника,
  повторная упаковка после перезапуска; сохранение вложения историей и освобождение
  после её очистки; повторное восстановление с исходными подписями, непринятыми
  источниками и бинарным экспортом; handoff после рестарта до доставки преемнику;
  передача подписанного fork третьему участнику и блокировка записи после рестарта;
  сохранение запрета очистки неполной очереди после восстановления в новый набор.

Эти нативные прогоны использовали Keychain и локальные сокеты. Keychain связывал
доступ с исполняемым приложением; отказ в sandbox не подменялся файловыми ключами.
Временные файлы удалялись, но созданные изолированные тестовые записи Keychain
по окончании этапа оставались в системном хранилище. Это историческое ограничение,
а не инструкция запуска удалённого CLI.

## Воспроизведение

Командный клиент и его терминальные сценарии удалены. Исторический запуск
этого среза больше не поддерживается. Общие проверки подписанных пакетов,
доставки, применения, восстановления и runtime выполняются Rust-тестами
на PUBLIC-данных с отдельными временными профилями.

```sh
cargo test --locked -p taypeer-runtime -p taypeer-sync -p taypeer-services
```

## Ограничения результата

- UI-проверка macOS в этом этапе была отложена; native-приёмка текущего desktop
  ведётся отдельно в [roadmap](roadmap.md#безопасность-и-платформенная-приёмка).
- Нативные тесты после последней правки удержания неполной очереди при восстановлении
  не повторялись; сервисный сценарий этой границы прошёл.
- Полная матрица отказов хранения и длительных сетевых прерываний, длительный fuzzing,
  независимый аудит, Android и защита полного отката ОС не были подтверждены.

Действующий контракт находится в [p2p.md](p2p.md), текущие команды — в
[testing](testing.md#подписанный-обмен-основного-workspace).
