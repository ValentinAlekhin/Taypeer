# Защита сессий runtime и CLI

Реализованный срез от 2026-09-15 относится к дочерним процессам `taypeer-runtime`
и командному клиенту. [Требования](../spec.md#автоблокировка) распространяются
на продукт целиком; подключение macOS UI, подписки на события ОС и Android
остаются отдельной работой. `RuntimeHost::open_local` вызывает сервис внутри
процесса и не получает защиту дочернего процесса от этого изменения.

## Политика и активность

`SessionPolicy` в ядре задаёт положительное число секунд; по умолчанию — 300.
Один `SessionController` обслуживает все БД приложения, включая открывающиеся
процессы и получение подписи для подключения устройства. Часы монотонные.
Перед регистрацией активности проверяется истечение предыдущего срока:
нажатие после deadline не оживляет старую сессию. Повторная аутентификация
создаёт новый процесс и уникальное поколение внутри контроллера.

CLI учитывает ввод клавиш, вставку и начало явной команды пользователя.
Скрытый ввод пароля также обновляет активность; показ запроса и ожидание ввода
не обновляют её. Завершение команды, фоновые применение и обмен, чтение
состояния и polling не продлевают срок. Ввод в одной БД продлевает общий срок
для всех БД. Сокращение таймера сразу проверяет новый срок от последнего ввода.

```sh
taypeer-cli settings auto-lock
taypeer-cli settings auto-lock --seconds 120
taypeer-cli --profile /путь/к/профилю --json settings auto-lock
```

Команды доступны без открытой БД и native credentials. Настройка хранится
в `session-policy.json` выбранного профиля, под отдельной файловой блокировкой,
через временный файл, sync и атомарную замену. Отсутствие файла означает default;
нулевое значение, повреждение, неизвестная версия или поля дают ошибку без
перезаписи. Формат настроек: `{"version":1,"policy":{"idle_seconds":300}}`.
Эта настройка не меняет dev-формат 5 БД и не создаёт профиль Keychain.

## Блокировка и результат

Контроллер сначала закрывает доступ всем затронутым поколениям. Очередь команды,
её ожидание и ответ проверяют тот же неизменяемый объект процесса. Один IPC actor
последовательно обслуживает кадры данного поколения; новый процесс имеет другой
actor, канал и gate, поэтому старый ответ не может стать ответом новой сессии.
Фоновый наблюдатель доверия не ждёт завершения применения полученных данных.

Отдельный supervisor владеет `Child`; ни pipe I/O, ни callback файлового
координатора не удерживают его контрольную блокировку. На обычное закрытие
и сохранение зашифрованного черновика отводится **две секунды одновременно всем
процессам**. Затем supervisor посылает принудительное завершение. Опрос выполняется
каждые 20 мс; это программный deadline, а не гарантия планировщика ОС. Состояние
`closed` публикуется только после наблюдаемого выхода процесса. Ожидающий API
даёт дополнительно до 200 мс на наблюдение выхода и возвращает
`ShutdownUnconfirmed`, если выход ещё не подтверждён.

Состояния: `opening → open → closing → closed`; открытие также может сразу
перейти в `closing`. `SessionStatus` содержит ID БД после аутентификации,
поколение, фазу, причину и результат. `db list` показывает `session` и `last_lock`,
`db lock` возвращает результат закрытия, интерактивный CLI сообщает событие
`session_locked`. Машинные ключи одинаковы для en/ru.

| Поле | Значения и смысл |
| --- | --- |
| `reason` | `manual`, `idle`, `sleep`, `system_locked`, `background`, `authority`, `host_exited`, `transport` |
| `termination` | `graceful`: подтверждение Lock и выход; `forced`: принудительное завершение; `exited`: выход без подтверждения Lock |
| `draft` | `preserved`: сервис подтвердил сохранность; `failed`: сервис сообщил ошибку; `unconfirmed`: подтверждения нет |
| `error` | Типизированная ошибка без содержимого БД; отсутствие ошибки само по себе не означает сохранённый черновик |

`preserved` включает отсутствие активного редактора и сохранение отложенного
read-only черновика без перезаписи. `failed` не доказывает отсутствие нового файла:
ошибка sync могла возникнуть после атомарной замены. `unconfirmed` не обещает
восстановить последние правки; предыдущий надёжный черновик может остаться.
Ошибка черновика не отменяет закрытие доступа.

Уже принятый callback записи ciphertext может закончиться после блокировки.
Отменённая команда получает `OperationInterrupted`, а не обещание успеха или
отката. При прерванном открытии зарегистрированный writer может сохраняться
до повторного открытия либо завершения host; очистка не ждёт зависший callback
и не конкурирует с повторным открытием. Сетевой приём остаётся у независимого
координатора и не требует открытого документа.

Дочерний процесс отдельно читает родительский канал. EOF, некорректный кадр
или переполнение ограниченной очереди запускают двухсекундное завершение,
даже если сервис занят. Исчезновение родителя закрывает этот же pipe средствами ОС.
Уничтожение host инвалидирует его процессы до остановки сети.

## Адаптеры и ограничения секретов

`RuntimeHost::sessions()` и `SessionController::lock_all(reason)` предоставляют
hooks для `Sleep`, `SystemLocked` и `Background`. В этом срезе это вызовы API,
а не подписки на системные уведомления. Ручной `db lock` затрагивает выбранную БД;
таймер и общие события затрагивают все процессы.

Скрытый ввод отменяется при истечении срока или внешней инвалидизации, его
принадлежащий CLI буфер стирается. Сериализованный запрос освобождается со
стиранием сразу после отправки; неполученные ответы также стираются. Перед выводом
проверяется актуальность команды. Это не стирает уже выведенный текст, буферы
терминала/Reedline, чужие копии ответа, память KDF, swap или core dumps.
Завершение процесса ограничивает время жизни открытого графа Automerge, но не
закрывает полную проверку памяти и платформенной безопасности.

## Проверки

`cargo test --locked -p taypeer-runtime -p taypeer-cli` запускает:

- искусственные часы: default, границу срока, изменение политики, общий таймер
  двух реальных процессов и отсутствие обновления от фоновых запросов;
- дочерние процессы с зависшей командой, неполным ответом, поздним ответом,
  открытием без ответа, зависшим ciphertext callback, неожиданным выходом
  и ошибкой сохранения;
- реальный dispatch и `DatabaseService` с публичными ключами: зашифрованный
  черновик после выхода процесса, восстановление новым процессом, ошибка записи,
  принудительный выход занятого сервиса с сохранением предыдущих файлов;
- занятый дочерний процесс после EOF родительского pipe;
- CLI en/ru: настройка, повторное чтение, отказ нулевому значению, отсутствие
  создания native-профиля.

Исходники fixtures: [process/tests](../crates/taypeer-runtime/src/process/tests.rs),
[worker/tests](../crates/taypeer-runtime/src/worker/tests.rs) и
[EOF](../crates/taypeer-runtime/src/worker/input/tests.rs). Файлы создаются только
во временных каталогах; пароль `PUBLIC_SESSION_DRAFT_PASSWORD`, авторский seed
`[19; 32]`, транспортный `[59; 32]` заведомо публичны. Два ignored helper-теста
вызываются автоматически родительскими тестами и не обращаются к Keychain.
Семь нативных CLI-тестов остаются отдельным явным запуском.

Проверка приёма/пересылки при закрытом документе сохраняется в
[сервисных сценариях](../crates/taypeer-services/src/managed/tests.rs) и
[прямом транспорте](../crates/taypeer-sync/src/node/tests.rs).
Десктопный UI, настоящие уведомления ОС, native credentials и Android этим
набором не проверяются.
