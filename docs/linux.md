# Linux в первой версии

Целевая среда приёмки — NixOS x86_64, niri/Wayland. Общий desktop UI, локальные
credentials, Linux lifecycle/буфер и Nix-пакет реализованы. Это ограниченный
экспериментальный срез; проверки безопасности и выпуска остаются открытыми.


GUI и CLI используют `$XDG_DATA_HOME/taypeer/profiles/default` с fallback
`$HOME/.local/share/taypeer/profiles/default`; явный `--profile PATH` имеет
приоритет. Общий GPUI UI сохраняет закреплённый GPUI Kit, системную тему и
системные файловые диалоги. Linux использует Ctrl-сочетания и собственный app ID;
Touch ID скрыт. Пользовательские сообщения доступны на en/ru.

Wayland ext-data-control, либо wlr-data-control при отсутствии первого протокола,
создаёт собственный источник и передаёт отметку чувствительности. Копирование
подтверждается после получения владения. Таймер по умолчанию 30 секунд,
произвольный положительный интервал и отключение очистки сохраняют spec.md.
Отложенная очистка проверяет идентичность источника, а не только текст; повторное
собственное копирование заменяет предыдущий таймер, чужое копирование сохраняется.

Закреплённый Nix flake предоставляет пакет, запуск и dev shell для x86_64-linux.
Пакет содержит GUI, соответствующий worker, графические библиотеки, IBM Plex и
необходимые шрифты, desktop-файл и иконку. Production собирается без feature
тестовых credentials. Сборка не закрывает проверки безопасности и выпуска.

Проверки: две БД с разными паролями и независимой активацией после перезапуска;
создание/правки/сохранение/повторное открытие; чтение и экспорт копии без допуска;
повреждение и подмена credentials; сбои создания, ротации и final marker;
отзыв, восстановление приглашения и повтор неверного пароля; черновик при
блокировке, поздние ответы, EOF, сон/возобновление; владение буфером, чувствительная
отметка, таймеры и сохранение чужого копирования. Запускаются общие Rust UI
сценарии, `sh scripts/check.sh`, сборка Nix и проверка упакованного worker.
На реальном niri desktop отдельно проверяются ввод, диалоги, тема, масштаб,
буфер и системная блокировка. Непроведённые проверки остаются открытыми.


Сборка и запуск:

```sh
nix build path:.#taypeer
nix run path:.# -- --profile /tmp/taypeer-public-profile
nix develop path:.
sh scripts/check.sh
sh scripts/check-linux-package.sh result
TAYPEER_PUBLIC_LINUX_WORKER="$PWD/result/bin/taypeer" cargo test -p taypeer-runtime host::linux_tests --locked -- --test-threads=1
```

GUI запускает свой рабочий процесс через тот же исполняемый файл с приватным
аргументом `__worker`; отдельный тестовый `taypeer-ui-worker` в пакет не входит.
Установить пакет можно через `nix profile install path:.#taypeer`, либо добавить
`packages.x86_64-linux.taypeer` в `environment.systemPackages` конфигурации NixOS.
Для native диалогов требуется работающий desktop portal с файловым picker;
для GPU используется системный драйвер Vulkan. Nix wrapper добавляет библиотеки
Wayland/X11 и fontconfig с IBM Plex, Noto Sans и emoji, не меняя профиль пользователя.

Во время незавершённого приглашения отдельный enrollment worker удерживает
аутентификацию staging; host получает только транспортную capability. Исправленный
пароль полученной БД передаётся этому worker и не требует повторного приглашения.
После перезапуска staging сначала открывается первоначально введённым паролем;
если он был ошибочным для БД, правильный пароль БД можно ввести следующим повтором.
Публичный индекс содержит только ID запроса/БД и выбранный путь; приглашение, proof
и авторские credentials остаются в зашифрованных контейнерах.


На текущем niri предварительно проверены запуск упакованного окна, системная тёмная
тема и ввод кириллицы/Unicode в искусственной форме. Интерактивная приёмка
незавершена: реальные файловые диалоги, переключение темы/масштаба, буфер,
системная блокировка и сон/возобновление не подтверждены этими действиями.
Изолированные Rust UI-сценарии отдельно проверяют события и результат операций;
они не заменяют эти native-проверки.


Изолированные Rust UI-сценарии выполнены на Linux: 8/8 проходят, включая надёжное
сохранение и повторное открытие, восстановление черновика, отзыв запоздавших
раскрытий, запрет аутентификации до подтверждённой активности и обмен двух
устройств с получением ciphertext при блокировке. Тестовая платформа не обращается
к реальному буферу, диалогам, профилю пользователя или службе хранения секретов.


Общий `sh scripts/check.sh` завершён успешно на Linux: LikeC4/документация,
Rustfmt, все targets/features, Clippy без предупреждений, workspace-тесты,
UI 8/8, Rustdoc с запретом предупреждений, production release и публичный
headless smoke. macOS Keychain, Android/KDBX и открытые security/release-проверки
этот запуск не подтверждает.

Production worker из Nix-пакета проверен без службы хранения секретов: 6/6
интеграционных сценариев проходят; отдельный приватный helper намеренно исключён.
Проверены независимая активация двух БД после перезапуска, работа транспорта после
блокировки, копия без локальных credentials, повреждённые credentials, ротация
пароля и восстановление её прерванных этапов, восстановление создания после сбоя
final marker, повтор неверного пароля приглашения и получение удалённой ротации.


Отдельные проверки Linux-адаптера проходят 4/4. Дополнительно на текущем niri
проверен реальный Wayland протокол буфера (1/1): отметка чувствительности,
подтверждение владения и очистка по таймеру. Эта проверка адаптера не использует
живое окно приложения и не подтверждает системную блокировку или сон.
