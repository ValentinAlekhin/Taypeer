# История групп и метаданных БД на Android

Этот срез закрывает историю всех объектов из `spec.md` и
`wireframes/COVERAGE.md`. Композиция использует Android `history`,
`history-version` и `history-compare`; содержимое группы и БД остаётся
метаданными своего объекта, а не полями искусственной записи.

## Чтение и сравнение

Общий сервис возвращает одним чтением выбранную доступную сохранённую версию,
текущую проекцию того же объекта и её причинные heads. Для группы он также
возвращает допустимые назначения из этого же контекста, используя существующие
проверки родителя формы группы. Чтение не создаёт форму, версию или квитанцию и
не выполняет сетевой запрос. Окончательно очищенная версия недоступна.

Снимок группы содержит название, описание, выбранный значок и родителя.
Сравнение показывает эти поля сохранённой и текущей стороны отдельно.
Снимок БД содержит только название и описание. Защита, лимиты, доверенный набор,
рабочий путь и локальные настройки не являются восстанавливаемыми метаданными.
Время сохранения выводится с точностью до миллисекунд в UTC; неизвестный автор
не заменяется именем текущего устройства.

Native передаёт ограниченный `MetadataRevisionView`: вид объекта, target,
revision, savedAt, сохранённый и текущий `MetadataSnapshotView`, reviewed basis
и `GroupParentCandidate`. Snapshot содержит name, description, parent и
маскированный `IconView`; у БД parent/icon отсутствуют. UI не получает исходное
дерево Automerge, бинарные оригиналы или защищённые значения.

Историческая иконка группы имеет отдельный `BinaryTarget::GroupRevision` и
`IconScope::GroupRevision`, связанные с group/revision. Существующий renderer
читает именно значок выбранного снимка и выдаёт только ограниченный PNG.
Lucide/default не заменяются первым удерживаемым image-альтернативным blob.
Preview не использует сеть и очищается вместе с текущей сессией/маршрутом.

## Восстановление

Пользователь отдельно подтверждает выбранную версию. У группы подтверждение
включает явного активного родителя либо верхний уровень; UI отображает общий
список кандидатов, не воспроизводя правила циклов и поколений. У БД выбора
назначения нет. Объект сохраняет свой ID. История восстановления не создаёт
группы, поддерево, новую БД или сетевой допуск.

Команды `RestoreGroupRevision { group, revision, parent, heads, operation }` и
`RestoreDatabaseRevision { revision, heads, operation }` связывают выбранный
снимок с reviewed контекстом. Shared Document проверяет доступность версии,
активность и неизменность поколения группы между reviewed и текущим состоянием,
поколение назначения и существующие guards `MoveGroup`. Сам объект, потомок,
недоступное или пересозданное назначение отклоняют всю операцию. Restore
метаданных не возвращает группу из корзины и не открывает очищенную generation;
для этого существуют отдельные lifecycle-действия.

Название, описание, значок и явное изменение родителя применяются одной
транзакцией от reviewed heads. Неизменённый родитель сохраняет порядок.
Каждое новое подтверждение Restore создаёт одну версию `RevisionKind::Restore`,
в том числе при равных значениях; выбранная старая версия остаётся неизменной.
Квитанция exact operation находится в той же транзакции. Новая операция не
затирает неизвестные поля и сохраняет общую причинную семантику альтернатив.

Shared service использует существующий owner кандидата и durable commit.
Успех относится только к подтверждённому сохранению БД. Retry проверяет exact
receipt до повторного поиска source, назначения и текущего поколения. Поэтому
потерянный ответ, последующая очистка выбранной версии или независимая поздняя
правка не создают вторую историю и не откатывают позднее состояние. Изменение
revision/parent/basis под прежним operation возвращает typed operation conflict.
`CommitUncertain` согласуется существующим storage owner; равное чтение файла
само по себе не является durability ACK.

## Владение Android-состоянием

Перед началом восстановления изменённый редактор проходит существующее явное
сохранение БД либо сохранение локального зашифрованного черновика. Ошибка обоих
путей оставляет редактор открытым. Просмотр и сравнение не подтверждают правки.

Состояние истории ограничено выбранной БД, поколением сессии, объектом и revision.
Новый выбор или incoming application обновляют текущую сторону и отзывают
старые preview/ответы. Lock немедленно очищает текущие снимки, описания и PNG;
поздний ответ не открывает прежний экран.

После начала Restore отдельный owner удерживает только exact публичный intent:
database, kind, target, revision, reviewed heads, parent и operation. Back,
закрытие слоя и lock не подтверждают успех и не превращают retry в новый intent.
После разблокировки той же БД прямой retry доступен без повторного чтения
очищенного source. Подтверждённый commit отделён от последующей ошибки обновления
проекции. Ни имя/описание снимка, ни PNG, ни protected values не входят в этот
удерживаемый запрос, saved state или логи.

## Проверки этого среза

- Shared Document: точный GROUP/DB snapshot, read-only comparison, один ID и
  одна Restore-версия; восстановление равного снимка; same-parent без reorder;
  недоступное назначение/цикл/смена поколения отклоняются атомарно.
- Shared managed service: encrypted save/reopen; receipt replay после поздней
  правки и purge source; конфликт operation; ошибка до публикации и потерянный
  ответ после durable publication без дублирования истории.
- Native: реальные masked DTO и локальный исторический image preview; отказ
  после lock; отсутствие сети, мутации или раскрытия оригиналов при чтении.
- Android: выбранный GROUP/DB View/Compare/Restore, exact поля и история;
  dirty navigation; retained lost reply через Back/lock/reopen; поздний ответ
  старой БД/версии не возвращает экран. Тесты используют только PUBLIC fixtures.

Модель описывает целевой контракт. Статус сборки и фактические результаты
записываются отдельно после запуска Root; этот документ не объявляет тесты PASS.
