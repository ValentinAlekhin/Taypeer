# OpenPencil: проверенный порядок работы

Наблюдения от 2026-10-07: macOS, OpenPencil Desktop и MCP 0.15.1,
CLI 0.14.0, Peekaboo 4. Это особенности этих версий, а не требования FIG.
Перед работой с живым редактором читай этот файл. На новой версии сначала
проверь, сохраняются ли ошибки; не переносить обходы без проверки.

## Подключение и выбор документа

Локальный MCP: `http://127.0.0.1:7600/mcp`; RPC — на том же порту `/rpc`.
Ответ HTTP-сервера ещё не означает, что приложение подключено.
`list_documents` или команда ниже должны вернуть реальный открытый документ:

```sh
rtk proxy openpencil documents --json
```

Нужен документ с точным путём `<корень проекта>/wireframes/taypeer.fig`.
Не брать ID активной вкладки без проверки пути. После перезапуска все ID
обнаруживать заново. Если вернулось `app is not connected`, проверить, что
приложение запущено и файл открыт; не запускать второй MCP-сервер наугад.
`design.py` читает локальное обнаружение MCP и передаёт токен только на loopback;
не печатать `mcp.json` целиком и не переносить токен в инструкции или команды.

## Сборка и замена FIG

1. Подготовить кандидата штатными `design.py build / verify / export` и
   просмотреть изменённые PNG по [README](README.md). Основной FIG пока не менять.
2. Сопоставить сохранённый файл с живым документом. Если сессия уже сломана,
   сначала сохранить ручные правки отдельной доверенной копией. Для перезапуска
   нужны подтверждённо сохранённые документы; неизвестный несохранённый ввод
   нельзя отбрасывать ради восстановления MCP.
3. В исправной сессии открыть основной FIG и до контрольного сохранения
   не создавать тестовые вкладки и не переключать документы. В 0.15.1 это
   позволяло не попасть в ошибку уничтоженного рендерера.
4. Перед первым нативным сохранением выполнить обход зависания исходного
   архива: присвоить текущей странице её же имя через поддерживаемый API.
   Подставить обнаруженный ID вместо `DOCUMENT_ID`:

   ```sh
   rtk proxy openpencil eval --document-id DOCUMENT_ID -c 'const page=figma.currentPage; const existingName=page.name; page.name=existingName; return {id:page.id,name:page.name};' --json
   rtk proxy python3 wireframes/scripts/design.py publish --document-id DOCUMENT_ID
   ```

   Setter инвалидирует кеш исходного архива; видимое имя остаётся прежним.
   Это мутация редактора, поэтому неизменность сцены подтверждает обычная
   защита `publish`, а не предположение об одинаковом имени.
5. Дождаться завершения уже запущенного `publish`. Успех — результат
   `published`, существующие копии в `build/backups/` и совпадение нового
   хеша с кандидатом. Проверить `design.py verify --published` и `status`.
   Не удалять защиту живой сцены, не менять baseline вручную и не копировать
   кандидат поверх основного файла после отказа проверки.
6. Повторно открыть основной FIG перед сохранением из приложения. Нативная
   контрольная копия меняет путь живой вкладки на `build/backups/live-*.fig`;
   это ожидаемый эффект `save_file`. Старую вкладку нельзя сохранять поверх
   выпущенного основного FIG.

## Ошибки и следующий шаг

| Симптом | Проверенный вывод и действие |
| --- | --- |
| `save_file` / `publish` зависает или получает HTTP 502; в дереве уже виден путь копии | Путь меняется до завершения записи. Проверить наличие и чтение копии на диске. Зависание нетронутого импортированного FIG обходится setter имени страницы выше |
| `Cannot pass deleted object as a pointer of type Paint*` | После переключения вкладок сохраняющий код держит уничтоженный renderer. Setter имени это не исправляет. После сохранения ручных правок нужен перезапуск приложения и основной FIG в свежей сессии |
| `open_file` возвращает `RPC timeout (20s)` | Сначала заново запросить документы. В наблюдавшемся случае появилась пустая вкладка `Page 1` без пути; это не открытый FIG. После уже завершённого выпуска помог перезапуск и нативное открытие основного файла |
| Повторное открытие известного пути возвращает прежнее содержимое | Открытие может переиспользовать существующий store по исходному пути. Переименование вкладки после неудачного сохранения не доказывает смену этой идентичности |
| `switch_page` сообщает успех, но документ остаётся на прежней странице | В этой сессии MCP восстанавливал прежнюю страницу после вызова, в том числе без явного `document_id`. Проверить `current_page_id` отдельным `list_documents`; перейти по странице через Peekaboo, затем повторно проверить |
| `Raster export selection must stay on a single page` при одном артборде | Проверить фактическую текущую страницу и принадлежность узла. После нативного перехода на нужную страницу `select_nodes`, `viewport_zoom_to_fit` и `export_image` с актуальным ID работали |

Таймаут не считать успехом или разрешением на повтор. Сначала проверить
состояние и файл, затем исправить конкретную причину. Не ждать зависшее
сохранение минутами, не создавать пустой документ для проверки записи и не
перебирать вкладки: такой probe в этой версии повредил renderer исходного
документа. У `save_file` нет подтверждённого режима без thumbnail; не вызывать
скрытые store/renderer API и не править установленный OpenPencil ради обхода.

## Нативное открытие и показ результата

Если документы сохранены и требуется восстановить сломанную сессию, штатный
выход и запуск с файлом работали без участия владельца:

```sh
rtk peekaboo app quit --app OpenPencil --no-remote --json
rtk peekaboo app launch OpenPencil --open /ABSOLUTE/PROJECT/wireframes/taypeer.fig --foreground --wait-ready --no-remote --json
rtk peekaboo app focus OpenPencil --foreground --no-remote --json
```

После запуска проверить через MCP точный путь и дерево страниц. Для перехода
на страницу использовать свежие AX-элементы:

```sh
rtk peekaboo see --app OpenPencil --tree --no-screenshot --no-remote --json
rtk peekaboo click --app OpenPencil --snapshot SNAPSHOT_ID --on PAGE_ELEMENT_ID --no-remote --json
```

Сверить `current_page_id` отдельным чтением. Найти изменённый артборд по имени
в новом дереве страницы, выбрать его и приблизить через MCP. Для `export_image`
можно опустить целевые параметры лишь после подтверждения активного документа
и страницы. В успешном выпуске так проверен живой `macOS / edit` с check/x.
Актуальные аргументы MCP 0.15.1: `select_nodes { ids: [ARTBOARD_ID] }`,
`viewport_zoom_to_fit { ids: [ARTBOARD_ID] }` и
`export_image { ids: [ARTBOARD_ID], format: "PNG", scale: 1 }`.
Старый пример `viewport_zoom_to_fit { id }` из каталога 0.12 не использовать
без проверки схемы установленного инструмента.

Для снимка окна Peekaboo 4 использует `see --no-elements --path ...`, для
сочетаний клавиш — `press cmd+s`; старые `inspect-ui`, `image` и `hotkey`
удалены. В Stage Manager список окон показывал миниатюру 148 × 129 вместо
окна 1280 × 800. Помог `app focus`, затем новое наблюдение. Не использовать
старые window/snapshot/element ID после перезапуска. Ошибка захвата не
доказывает порчу FIG: экспорт сохранённого файла и MCP raster export остаются
отдельными способами проверки макета.

## Основание диагностики

Разбор кода 0.15.1 объяснил зависание ожиданием `originalFigArchive` и
перезаписью обработчика message port при lazy population: [экспорт FIG](https://github.com/open-pencil/open-pencil/blob/v0.15.1/packages/core/src/io/formats/fig/export.ts),
[population worker](https://github.com/open-pencil/open-pencil/blob/v0.15.1/packages/core/src/kiwi/fig/population/client.ts).
Диагностика `Paint*` указала на глобальный proxy активного store и очистку
canvas при переключении документов: [active store](https://github.com/open-pencil/open-pencil/blob/v0.15.1/src/app/editor/active-store/index.ts),
[canvas lifecycle](https://github.com/open-pencil/open-pencil/blob/v0.15.1/packages/vue/src/canvas/surface/lifecycle.ts).
Для MCP-переключения страницы зафиксировано наблюдаемое поведение; отдельная
причина в коде не подтверждена. Обходы проверены успешным штатным `publish`,
повторным нативным открытием и живым raster export; это не исправление OpenPencil.
