# Taypeer — макеты OpenPencil

Основной файл: [taypeer.fig](taypeer.fig). Открывать в OpenPencil. Ориентир — предоставленный пользователем скриншот Zedis и правила GPUI Kit Design Guides: тёмные плоские поверхности, постоянные панели, компактные строки, нейтральное выделение и точные границы регионов.


## Файлы и рабочие команды

```text
wireframes/
├── taypeer.fig                 Основной редактируемый макет
├── README.md                  Принятые правила и работа с макетом
├── .gitignore
├── requirements.txt           Pillow для обзорных PNG
├── assets/                    Lucide: базовая FIG, дополнительные пути, лицензии
├── source/
│   ├── compact.js             Исходники экранов, компонентов и темы
│   ├── desktop.js             Полные macOS-сценарии, формы, состояния и контрольные варианты
│   ├── android.js             Телефонные экраны, формы, состояния, размеры и карта v1
│   ├── checks.js              Проверки продуктовых инвариантов
│   ├── snapshot.js            Сравнение визуального дерева без нестабильных ID
│   └── published.json         Контрольная точка последнего выпуска локального FIG
├── scripts/
│   ├── design.py              build / verify / export / publish / status
│   ├── verify.py              Проверки и экспорт сохранённого FIG
│   └── test_workflow.py        Защита ручных правок и предыдущих превью
└── build/                     Генерируется, исключён из Git
```

[COVERAGE.md](COVERAGE.md) связывает требования первого релиза с экранами,
компонентами и переходами. В `assets/demo-invitation.json` хранится искусственный
длинный код и соответствующая QR-матрица; это не действующее приглашение.

Нужны Python 3.11+, OpenPencil CLI (проверено на 0.14.0) и Pillow из `requirements.txt`. MCP нужен для работы с открытым редактором. Команды запускаются из корня проекта; RTK используется по правилам проекта.

Перед работой с живым редактором прочитай [проверенный порядок OpenPencil](OPENPENCIL.md):
подключение MCP, обходы ошибок 0.15.1, безопасное сохранение и нативное открытие.

```sh
rtk proxy python3 wireframes/scripts/design.py build
rtk proxy python3 wireframes/scripts/design.py verify
rtk proxy python3 wireframes/scripts/design.py export
```

Сборка создаёт **кандидат** `build/taypeer.fig`, не затрагивая основной макет. Проверки записывают `build/qa.json` и индекс. Экспорт создаёт `build/previews/` с PNG каждого артборда и обзорными листами. Старый набор превью заменяется только после успешного экспорта всего нового набора.

После визуального просмотра кандидата:

```sh
rtk proxy openpencil documents --json
rtk proxy python3 wireframes/scripts/design.py publish --document-id DOCUMENT_ID
```

Здесь `publish` — **замена локального `taypeer.fig`**, без загрузки во внешние сервисы. Команда проверяет свежесть кандидата и исходников, изменения сохранённого файла относительно сборки и последней контрольной точки, а также несохранённые изменения конкретного открытого документа. Для этого локальный MCP сохраняет полный живой FIG в `build/backups/` и читает его тем же парсером, что и файл на диске: app-eval OpenPencil 0.14 может не раскрыть дочерние векторы экземпляров. Сравнение не исключает эти векторы. Сохранение копии может изменить имя/путь живой вкладки; после выпуска основной файл открывается заново. Перед заменой создаётся копия в `build/backups/`. Первое создание контрольной точки допускается только при воспроизведении существующей сцены.

При отказе защиты нужно сохранить ручные изменения и перенести их в исходники, затем пересобрать. Обхода через force нет. Если редактор не отвечает, можно подготовить кандидата и превью; основной файл остаётся на месте. Во время замены не следует одновременно редактировать документ. Снимок сравнивает визуальное дерево, а не все возможные метаданные FIG; резервная копия сохраняет исходный файл целиком.

После замены необходимо **повторно открыть файл в OpenPencil**, запросить новые ID страниц/узлов, выбрать нужный артборд и приблизить его. Сохранение старого открытого документа может затереть новый файл.

```sh
rtk proxy python3 wireframes/scripts/design.py verify --published
rtk proxy python3 wireframes/scripts/design.py export --published
rtk proxy python3 wireframes/scripts/design.py status
rtk proxy python3 -m unittest discover -s wireframes/scripts -p 'test_*.py'
```

`--published` проверяет или экспортирует основной файл, а не кандидата. В Git сохраняются основной FIG, исходники, контрольная точка и лицензированные ассеты. Кандидаты, отчёты, превью, резервные копии, Python-кеши и локальная среда исключены через `.gitignore`.

Проектный скилл: [taypeer-design](../.agents/skills/taypeer-design/SKILL.md). Общие особенности инструмента описаны в установленном скилле `open-pencil`.

## Состав

В основном `taypeer.fig` 172 артборда. Имена и состав существующих сцен сохранены;
экраны каждой платформы собраны на одной странице, а библиотека — отдельно.
Набор отражает
сохранение по кнопке, несколько локальных черновиков, историю альтернатив и внутренние
рабочие копии и диалоги «Сохранить / Не сохранять / Остаться». KDBX, резервные
снимки и обязательный выбор конфликтов исключены из набора.

Покрытие требований находится в [COVERAGE.md](COVERAGE.md), статическая и будущая
Android-приёмка — в [ANDROID-QA.md](ANDROID-QA.md).

## Правила композиции

- Основная задача: найти запись, прочитать или скопировать значение, при необходимости изменить его. Объект и выбор постоянно видимы. Состояние редактирования принадлежит записи, состояние блокировки — базе, параметры устройства — установке приложения.
- Desktop: `TitleBar` высотой 34 px → `Resizable` с `Sidebar/Tree`, таблицей записей и `DescriptionList`/редактором → `StatusBar`. Селектор БД центрирован относительно окна. Над деревом нет слова «Группы», над таблицей не повторяется имя папки. Без выбранной записи таблица занимает всю ширину справа от дерева. Поиск сохраняет её колонки и геометрию строк. Футер показывает размер БД и состояние синхронизации; настройки открываются только иконкой справа в хедере и занимают всю рабочую область без дерева и таблицы.
- Android: на основном экране выбранная группа, поиск, список названий/логинов и FAB создания записи. Дерево и свёрнутый переключатель БД находятся в прокручиваемом боковом меню. Стрелка раскрывает подгруппы, название выбирает группу и закрывает меню. Постоянной нижней навигации нет; меню открывается кнопкой и свайпом внутри списка вне системного края. В карточке и редакторе свайп меню отключён. Пять полных подписей вкладок прокручиваются горизонтально; действия имеют непересекающиеся области от 48 × 48 dp.
- Обычные Add/Open/Edit/Refresh используют default или ghost. Primary обозначает создание БД и подтверждение операций безопасности. Деструктивная команда содержит точный глагол и отдельное оформление.
- Подсказка остаётся только там, где меняет решение: последствия отзыва, доступность альтернатив в истории, причина ошибки. Иконкам нужны tooltip и доступное имя; это не постоянно видимый текст.
- Генератор вызывается иконкой `dice-5` справа от поля пароля. В модалке нет заголовка: результат, показ/скрытие, генерация и копирование, затем качество, длина и энтропия. `refresh-cw` означает синхронизацию, `sliders-horizontal` — настройки, `folder-plus` — новую группу, `file-plus-2` — новую запись, `file-key-2` — файл БД. Desktop-иконки Lucide: 16 единиц, линия 1,4; мобильные компоненты отдельно масштабированы до 20 с линией 1,75. Область действия 48 dp увеличивается независимо от рисунка; настольная библиотека не меняется.
- Просмотр и редактор используют одну сетку меток и текста значений без заголовков «Поле / Значение» и без сдвига текста. Название записи остаётся в заголовке до сохранения нового имени. В просмотре доступна pencil и меню записи; copy/reveal заполненной строки появляются при наведении. Пустое значение обозначается «—» без этих действий. В редакторе desktop справа команды сохранения check, отмены x, возврата arrow-left и меню записи; на Android кнопки Отмена и Сохранить закреплены над клавиатурой. Правки всех редактируемых вкладок сохраняются по кнопке или Cmd+S. При уходе из изменённой формы доступны Сохранить / Не сохранять / Остаться. Повтора пароля записи нет; у URL — явная загрузка favicon. Значок синхронизации крайний справа в футере. Метрики генератора выровнены по краям и центру шкалы.
- Аналогичные формы используют desktop-метку 144 и промежуток 16; мобильные пары располагаются вертикально. Input имеет явный вариант row (прозрачный внутри структурированной строки) или standalone (слабая тематическая заливка). В строках записи обводки нет, включая фокус; ввод обозначается кареткой и выделением текста. У standalone-полей фокус и ошибка имеют отдельную рамку состояния. Select показывает chevron, выбор файла — кнопку. Эти варианты задаются в inputFrame, а не глобальными исключениями по именам экранов. Нативные поля и поиск нового Kit Settings сохраняют стандартные рамки Kit; правило прозрачных строк записи на них не распространяется.
- На desktop общая полоса дерева, поиска и заголовка записи — 44; нижняя граница совпадает точно. Вкладки записи занимают следующие 38; заголовок и строки таблицы записей — по 32 px, как текущий GPUI Kit DataTable. Таблица без зебры и внешней рамки; тонкие разделители продолжаются в ячейках. Default-колонки «Название / Логин / База / группа» имеют ширины 200 / 180 / 240 при rem 16; URL / Заметки / Изменение — 240 / 280 / 180, минимум каждой — 6 rem. При нехватке ширины используется горизонтальная прокрутка. Колонки можно скрывать, переставлять и менять их ширину; название остаётся доступным. Поиск с очисткой и отдельной кнопкой области поиска использует тот же builder. По умолчанию название А–Я; другой столбец включает возрастание, повторный клик меняет направление. Выбор сохраняется по ID, сортировка локальна для устройства и одинакова в поиске и обычном списке. Подтверждённый пользователем источник композиции таблицы — текущая реализация Entries/DataTable; это исключение не распространяется на историю и устройства.
- В «Дополнительно» и «Виде» редактируемые действия появляются только в режиме правок. Свойства доступны для чтения. История предлагает общие команды для выбранной версии; очистка находится в меню. Исходные альтернативы доступны в истории; окончательная очистка требует подтверждения. История также доступна группам и названию/описанию БД.

Текущие desktop-вкладки отражают реализованную проекцию: «Дополнительно» показывает
атрибуты и вложения без выдуманного общего расхода хранилища; «Вид» — иконку,
цвет текста, цвет фона и предпросмотр. Выбор изображения из файла или по URL
остаётся явной командой, отдельного сохранённого поля URL иконки нет. Свойства
содержат создание, изменение и ID; время отображается в UTC с миллисекундами.
Автор версии, время последнего доступа и общий расход вложений пока не показаны
в desktop UI и не подставляются искусственными значениями. Макеты сохраняют
текущую проекцию; недостающие действия и поля перечислены в
[roadmap](../docs/roadmap.md#desktop-незавершённые-функции).
Это не снимает требования `spec.md` и не подтверждает их реализацию.
Родитель группы выбирается контекстом создания в дереве;
текущая форма группы редактирует название, описание и иконку с кнопками Отмена и Сохранить.
- Реализованная проекция списка истории показывает «Сохранено / Название» с имеющимися датой и названием версии. Имя устройства не подставляется искусственно при отсутствии этих данных в runtime; сетка истории остаётся 38 для заголовка и 44 для версии.
- Даты истории используют UTC с миллисекундами; для выбранной версии доступны «Просмотр», «Сравнить» и «Восстановить». Снимок сохраняет настоящее название записи и предлагает «Текущая запись» над вкладками; восстановление остаётся командой истории.
- Таблица устройств сохраняет сетку 38 / 48. Удалённые строки показывают публичный префикс ID и подтверждённый результат последней попытки обмена; отсутствие попытки обозначается отдельно. Доступность остаётся «Неизвестно», имя и последнее присутствие не подставляются. Получение БД использует код и мастер-пароль; макет сканера не подтверждает подключение desktop-камеры.
- Desktop-настройки используют композицию GPUI Kit `Settings`: боковая навигация «Устройство / База данных», поиск по настройкам, заголовок страницы и группы `Outline` размера `Medium`. Боковая панель по умолчанию 250 px; настройками она заменяет верхние вкладки. Сброса всех настроек нет; отдельная команда меню таблицы возвращает её раскладку по умолчанию. Настройки занимают рабочую область целиком, без дерева групп и таблицы записей.
- Настройки устройства применяются сразу; имя — по Enter или завершению ввода, ошибочное значение остаётся с локальной ошибкой. Общей кнопки сохранения нет. Самостоятельные формы и подтверждения сохраняют текстовые команды. Это новый целевой макет настроек: текущий desktop runtime пока использует прежнюю композицию с вкладками.
- Выбор «Тема / Theme» расположен в разделе «Устройство»: «Системная / System», «Светлая / Light», «Тёмная / Dark». По умолчанию системная. Иконка настроек доступна также на приветственном экране и при заблокированных БД, чтобы смена темы не требовала разблокировки.
- Подписи desktop-команд не заканчиваются многоточием. Внутренняя навигация использует нативные компоненты/Actions; ссылки предназначены только для внешних ресурсов.

## Готовые компоненты GPUI Kit

Аудит относится к установленному `gpui-kit` 0.6.0, закреплённому ревизией
`21f6ce6097c686e98e0ca62ff6178bb4612541a1` из `longbridge/gpui-kit`.
Состав и поведение сверены с исходником этой ревизии, а не с плавающим `latest`.

| Текущая композиция | Готовый компонент и применение |
|---|---|

Полный [`Settings`](https://github.com/longbridge/gpui-kit/blob/21f6ce6097c686e98e0ca62ff6178bb4612541a1/crates/component/src/setting/settings.rs)
в этой ревизии всегда рисует sidebar с поиском. Его нельзя вставить под прежние
вкладки как отдельный `SettingGroup`: рендер страниц и групп не является публичным
API. В целевом макете сохраняются две страницы «Устройство» и «База данных»;
`SettingPage::resettable(false)` исключает общий сброс страницы. Kit допускает
ширину sidebar 160–360 px и вертикально размещает поля при ширине содержимого
не более 480 px. Заголовок группы находится над обведённой карточкой.
При отсутствии совпадений нативный `Settings` оставляет область содержимого
пустой: отдельного сообщения в закреплённом компоненте нет. Пояснения к образцам
поиска расположены за пределами продуктового UI и не вводят новые строки приложения.

`SettingField::dropdown` подходит языку, теме и размеру текста; он рисует нативную
outline-кнопку с chevron, а не собственный Select во всю ширину строки. Встроенный
[`SettingField::input`](https://github.com/longbridge/gpui-kit/blob/21f6ce6097c686e98e0ca62ff6178bb4612541a1/crates/component/src/setting/fields/string.rs)
вызывает setter при каждом изменении: для имени устройства при реализации нужен
`SettingField::render` с существующим retained input, чтобы сохранить Enter/Blur,
ожидание записи и локальную ошибку. Пользовательские интервалы, собственный relay
и операции защиты БД сохраняют отдельные формы, проверку роли и явное подтверждение.
Новые значения не считаются применёнными до подтверждения надёжной записи.

Видимость, порядок и ширина колонок управляются только на рабочем экране:
меню таблицы, перетаскиванием заголовков и resize. В настройки эти контролы
не входят; «Название» всегда видно. Команда меню «Сбросить раскладку»
возвращает видимые «Название / Логин / База / группа» и этот порядок; скрытые
«URL / Заметки / Изменение» следуют за ними. Ширины при базовом rem 16:
200 / 180 / 240 / 240 / 280 / 180 px соответственно, минимум — 96 px.
Сброс меняет только видимость, порядок и ширины колонок; сортировка, поисковый
запрос, размер текста и ширины панелей сохраняются.

В разделе БД добавлены «Устройства и доступ» с текущей ролью, управляющим
устройством и переходом на экран устройств; «Рабочий файл» с внутренним путём,
размером и режимом доступа; «Данные» с переходами к истории БД, корзине,
локальным черновикам и отложенным правкам. Эти списки остаются самостоятельными
рабочими экранами. Новых файловых операций, desktop-команды «Сохранить копию»
или строки версии формата не добавлено. Все новые группы целиком показаны
в `States / preferences`, поэтому их можно проверить независимо от прокрутки
полного экрана настроек.

Это целевая навигация FIG. Текущий desktop runtime ещё не содержит этих групп;
колонки пока живут в `NavigationState` и delegate таблицы, без сохранения в
файле preferences. История метаданных и отдельные черновики уже доступны;
корзина, общий список черновиков и просмотр отложенных источников требуют
дальнейшего подключения UI. Макет не повышает статус реализации этих сценариев.

Desktop-выбор цвета уже реализован готовым Kit `ColorPicker` в
[`details::color_control`](../apps/taypeer/crates/taypeer-database-ui/src/ui/details.rs).
Его trigger — цветной квадрат `Medium` 32 px и подпись текущего HEX либо «—»;
внешняя команда сброса появляется только для установленного значения. Стрелки
Select и отдельной команды подтверждения цвета нет. `Dialog / color-picker`
сохраняет имя сцены, но изображает открытый popover в контексте вкладки «Вид».
В `System / components` добавлены образцы вкладок `Palette` и `HSLA`.

Палитра повторяет закреплённый Kit: 12 featured-цветов текущей тёмной темы и
девять семейств `stone / red / orange / yellow / green / cyan / blue / purple / pink`
по 11 оттенков от 950 к 50 из
[`default-colors.json`](https://github.com/longbridge/gpui-kit/blob/21f6ce6097c686e98e0ca62ff6178bb4612541a1/crates/component/src/theme/default-colors.json).
Во второй вкладке действительно есть четыре регулятора `Hue / Saturation /
Lightness / Alpha`. При выбранном цвете или hover-preview внизу видны preview-swatch
и HEX input со стандартной рамкой Kit. Выбор образца, Enter в HEX и движение
HSLA-регуляторов передают значение общему черновику; запись БД по-прежнему
подтверждается кнопкой «Сохранить» самой записи. Сброс находится рядом с trigger,
а не внутри popover. Android-композиция выбора цвета здесь не меняется.

Кнопки, поля, Select, меню и Dialog уже используют Kit. Дерево построено на
`TreeState/Tree`, таблица записей — `DataTable/TableState`, вкладки — `TabBar/Tab`,
панели — `Resizable`, генератор — `Slider` и `Checkbox`, выбор цвета — `ColorPicker`.
Их собственные краски и
продуктовая композиция не означают самописный механизм. Дополнительные кандидаты
выше представлены образцами и картой замен; массовое переоформление других
экранов и изменение Rust/Kotlin не входят в это обновление.

## Плотность, темы и размеры

Цвета привязаны к семантическим переменным в FIG. Единственный источник обеих палитр — `resources/theme.toml`; build внедряет его в генератор и учитывает в проверке свежести кандидата. Имена переменных FIG сохраняются через явное соответствие bg/background, fg/foreground, selected/selection, dim/disabled, onPrimary/on_primary; raised и остальные роли используют одноимённые значения. Цвет состояния сопровождается текстом. Адаптеры темы связывают те же роли с GPUI Kit на macOS и Compose на Android. Выделение строки DataTable рисуется поверх содержимого с alpha 0,2. Разделение фронтендов не меняет композицию и продуктовые правила макетов.

По правилам раздела «Тема интерфейса» [spec.md](../spec.md) системный режим определяет только светлый/тёмный вариант, без системного акцента или динамических цветов. Тема действует на все окна и БД устройства; смена ОС обновляет открытые формы и диалоги без потери ввода, фокуса и навигации, а после возвращения из фона режим проверяется снова. Ручной выбор фиксирует палитру. Явные цвета записей сохраняются; шрифты и геометрия не входят в цветовой конфиг.

Пользовательский TOML с частичными переопределениями и графический редактор этого же файла — будущий этап. Цвета пользователя допускаются без проверки или предупреждений о контрасте и без скрытой коррекции; предусмотрен сброс к встроенным палитрам.

Шкала: 2, 4, 8, 12, 16, 24, 32; desktop-текст 12–20, крупный заголовок только в обзоре. Desktop-кнопка 32, строка таблицы записей 32, строка описания 44. DataTable Medium сохраняет высоту строк/заголовка 32 при тексте 14/16/18; остальные относительные размеры используют rem и Size API. Скругление контрола 4, окно 8. Hairline — осознанное исключение. В макете Inter (включая значения для надёжного офлайн-экспорта); в desktop UI и внеэкранных тестах — встроенный Inter 4.1 из [ресурсов](../resources/fonts/inter/README.md), для секретов/кодов — отдельный системный моноширинный шрифт. Android использует системный UI-шрифт платформы.

| Регион desktop | Минимум | По умолчанию | Дополнительное место |
|---|---:|---:|---|
| Окно | 1100 × 720 | 1320 × 820 | Рабочие панели |
| Группы | 192 | 224 | До 280 |
| Записи | 330 | Остаток после дерева и карточки | Дополнительная ширина окна; без выбора — весь остаток |
| Детали | 380 | 520 | Выбранная ширина сохраняется при росте окна |

Размеры задаются относительно базового rem 16. При сужении панели ограничиваются минимумами; таблица сохраняет выбранные ширины и доступность колонок с горизонтальной прокруткой. Полный текст доступен в tooltip и деталях. Разделители перетаскиваются, размеры сохраняются и ограничиваются текущим окном. Дополнительную ширину получает таблица, выбранная ширина карточки сохраняется. Компонентные вкладки 614 остаются контролем вручную выбранной ширины, а не начальным размером карточки. У каждой панели собственная прокрутка и scrollbar у внешней границы. Заголовок записи с командами остаётся видимым. На Android клавиатура уменьшает область формы; команды Отмена и Сохранить закреплены непосредственно над ней.

## Клавиатура и компоненты

Tab/Shift+Tab следуют от chrome к дереву, списку, деталям и локальным действиям. Стрелки перемещают выбор дерева/списка; Left/Right сворачивают и раскрывают группу. Enter открывает выбранный объект или подтверждает форму; в многострочных заметках вводит новую строку. Cmd+F — поиск, Cmd+S — сохранить текущую форму, Escape — отменить верхний слой, затем вернуть фокус к вызвавшему контролу. Переход из изменённой формы требует выбора Сохранить / Не сохранять / Остаться. Ошибка сохранения сохраняет открытый редактор. Блокировка закрывает доступ немедленно.

Важные команды доступны через видимую кнопку, меню и Actions; hover не является единственным путём. Фокус, выбранная строка, наведённая строка и открытое меню различаются. Focus ring не обрезается. Switch применяется сразу; RadioGroup выбирает один вариант; независимые параметры генератора используют Checkbox. DropdownMenu/ContextMenu, Dialog/AlertDialog и Select сохраняют нативный контракт фокуса и закрытия.

## Проверка и ограничения

`source/compact.js` содержит общие примитивы и исходную компактную композицию;
`source/desktop.js` дополняет её macOS-сценариями. Они строят редактируемые макеты
из `assets/lucide-base.fig` (28 исходных иконок), `assets/lucide-extra.json`
(11 дополнительных) и QR-матрицы демонстрационного приглашения. Генератор получает
JSON от команды сборки; второй встроенной копии путей нет. Все исходники и ассеты
учитываются в проверке свежести кандидата.

`source/checks.js` проверяет сохранённую геометрию, общие границы панелей,
совпадение значений просмотра/редактора, сортировку и варианты полей. Дополнительно
проверяются отсутствие пересечений артбордов, поля нового пароля при отзыве,
отсутствие обязательного выбора конфликта и исключённых команд, отдельное копирование альтернатив,
положение QR, отсутствие содержимого БД при входе и настройки до разблокировки.
Локальный отчёт после проверки — `build/qa.json`.

Это статические макеты, не приложение GPUI и не кликабельный прототип. Светлая
тема, селектор режима, минимальное окно и увеличенный текст представлены
контрольными артбордами. Они проверяют видимую композицию, но не подтверждают
динамическое переключение темы, rem, клавиатурное поведение или изменение размеров
живого окна. В первой версии обязательны проверки на настоящих компонентах:
обе встроенные палитры, системное переключение и ручной выбор темы, en/ru,
базовый шрифт 14/16/18, минимальное окно, фокус и восстановление после ошибок.
Тёмная тема остаётся основным направлением. Подготовка переводов выполняется при
реализации UI; пользовательские темы относятся к будущему этапу персонализации.

Геометрия FIG фиксирована для стабильного повторного открытия в OpenPencil; текст, векторы, экземпляры и переменные остаются редактируемыми. Реализация должна использовать адаптивную композицию, а не переносить координаты из макета в код.

Ассеты встроены и не требуют сети для просмотра. [Lucide](https://lucide.dev/license) — ISC, часть иконок происходит из Feather/MIT; уведомления в [assets/LICENSE-LUCIDE.txt](assets/LICENSE-LUCIDE.txt). Старые подробные макеты, HTML-черновик и дублирующие экспорты удалены после выделения используемых ассетов и проверки идентичности новой сборки.

Desktop-команды изображения используют `image` и `link` из той же закреплённой
ревизии Lucide `c2c28580b3009b8de62224c1fec6f78abb3e37d8`, что и каталог приложения.
SVG преобразованы API импорта OpenPencil 0.14 в редактируемые пути в

## Android: телефонная композиция и проверка

`source/android.js` переиспользует палитру и лицензированные исходные векторы,
но владеет мобильными сеткой, полями, зонами действий, вкладками и прокруткой.
Размеры — логические dp, текст — 16 sp / подписи 14 sp. Непересекающаяся область
ввода заканчивается перед самостоятельными кнопками раскрытия, копирования,
генератора или загрузки иконки. В макете окно прокрутки содержит полный
редактируемый контент, который может выходить за его границы; все остальные
переполнения считаются ошибкой.

Кнопки Отмена и Сохранить редактора фиксируются над IME. Подтверждения безопасности сохраняют отдельные команды формы. При 200% команды
располагаются вертикально; активное поле остаётся в видимой области. Контрольный
размер не масштабирует готовую картинку: он заново размещает UI. Системные панели,
камера, picker, биометрия и уведомления показаны схематично — конкретное оформление
определяет Android. Это не интерактивный прототип и не приёмка на устройстве.

После экспорта быстрые листы доступны локально: `build/previews/android-contact.png`,
`build/previews/android-form-contact.png`, `build/previews/android-states-contact.png`,
`build/previews/android-qa-contact.png`, `build/previews/android-flow-v1.png`.
Каждый набор разбит по 12 артбордов; `build/previews/index.json` содержит все
отдельные PNG. Эти генерируемые файлы не входят в чистый checkout.

Основания: [жесты Android](https://developer.android.com/develop/ui/views/touch-and-input/gestures/gesturenav),
[доступность Compose](https://developer.android.com/develop/ui/compose/accessibility/api-defaults).
Видимые строки основного набора — русские; переводы, Kotlin/Rust-реализация,
планшеты и складные устройства в эту работу не входят.
