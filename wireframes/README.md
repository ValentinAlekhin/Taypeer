# Taypeer — макеты OpenPencil

Основной файл: [taypeer.fig](taypeer.fig). Открывать в OpenPencil. Ориентир — предоставленный пользователем скриншот Zedis и правила GPUI Kit Design Guides: тёмные плоские поверхности, постоянные панели, компактные строки, нейтральное выделение и точные границы регионов.


## Файлы и рабочие команды

```text
wireframes/
├── taypeer.fig                 Основной редактируемый макет
├── README.md                  Принятые правила и работа с макетом
├── .gitignore
├── requirements.txt           Pillow для обзорных PNG
├── assets/                    Lucide: базовая FIG, дополнительные пути, лицензии
├── source/
│   ├── compact.js             Исходники экранов, компонентов и темы
│   ├── desktop.js             Полные macOS-сценарии, формы, состояния и контрольные варианты
│   ├── checks.js              Проверки продуктовых инвариантов
│   ├── snapshot.js            Сравнение визуального дерева без нестабильных ID
│   └── published.json         Контрольная точка последнего выпуска локального FIG
├── scripts/
│   ├── design.py              build / verify / export / publish / status
│   ├── verify.py              Проверки и экспорт сохранённого FIG
│   └── test_workflow.py        Защита ручных правок и предыдущих превью
└── build/                     Генерируется, исключён из Git
```

[COVERAGE.md](COVERAGE.md) связывает требования первого релиза с экранами,
компонентами и переходами. В `assets/demo-invitation.json` хранится искусственный
длинный код и соответствующая QR-матрица; это не действующее приглашение.

Нужны Python 3, OpenPencil CLI (проверено на 0.14.0) и Pillow из `requirements.txt`. MCP нужен для работы с открытым редактором. Команды запускаются из корня проекта; RTK используется по правилам проекта.

```sh
rtk proxy python3 wireframes/scripts/design.py build
rtk proxy python3 wireframes/scripts/design.py verify
rtk proxy python3 wireframes/scripts/design.py export
```

Сборка создаёт **кандидат** `build/taypeer.fig`, не затрагивая основной макет. Проверки записывают `build/qa.json` и индекс. Экспорт создаёт `build/previews/` с PNG каждого артборда и обзорными листами. Старый набор превью заменяется только после успешного экспорта всего нового набора.

После визуального просмотра кандидата:

```sh
rtk proxy openpencil documents --json
rtk proxy python3 wireframes/scripts/design.py publish --document-id DOCUMENT_ID
```

Здесь `publish` — **замена локального `taypeer.fig`**, без загрузки во внешние сервисы. Команда проверяет свежесть кандидата и исходников, изменения сохранённого файла относительно сборки и последней контрольной точки, а также несохранённые изменения конкретного открытого документа. Перед заменой создаётся копия в `build/backups/`. Первое создание контрольной точки допускается только при воспроизведении существующей сцены.

При отказе защиты нужно сохранить ручные изменения и перенести их в исходники, затем пересобрать. Обхода через force нет. Если редактор не отвечает, можно подготовить кандидата и превью; основной файл остаётся на месте. Во время замены не следует одновременно редактировать документ. Снимок сравнивает визуальное дерево, а не все возможные метаданные FIG; резервная копия сохраняет исходный файл целиком.

После замены необходимо **повторно открыть файл в OpenPencil**, запросить новые ID страниц/узлов, выбрать нужный артборд и приблизить его. Сохранение старого открытого документа может затереть новый файл.

```sh
rtk proxy python3 wireframes/scripts/design.py verify --published
rtk proxy python3 wireframes/scripts/design.py export --published
rtk proxy python3 wireframes/scripts/design.py status
rtk proxy python3 -m unittest discover -s wireframes/scripts -p 'test_*.py'
```

`--published` проверяет или экспортирует основной файл, а не кандидата. В Git сохраняются основной FIG, исходники, контрольная точка и лицензированные ассеты. Кандидаты, отчёты, превью, резервные копии, Python-кеши и локальная среда исключены через `.gitignore`.

Проектный скилл: [taypeer-design](../.agents/skills/taypeer-design/SKILL.md). Общие особенности инструмента описаны в установленном скилле `open-pencil`.

## Правила композиции

- Основная задача: найти запись, прочитать или скопировать значение, при необходимости изменить его. Объект и выбор постоянно видимы. Состояние редактирования принадлежит записи, состояние блокировки — базе, параметры устройства — установке приложения.
- Desktop: `TitleBar` → `Resizable` с `Sidebar/Tree`, таблицей записей и `DescriptionList`/редактором → `StatusBar`. Над деревом нет слова «Группы», над таблицей не повторяется имя папки. Без выбранной записи таблица занимает всю ширину справа от дерева. Поиск сохраняет её колонки и геометрию строк. Футер показывает размер БД и состояние синхронизации; настройки открываются только иконкой справа в хедере.
- Android: те же объекты на последовательных экранах. Стрелка группы раскрывает дерево, название открывает записи. Пять вкладок записи прокручиваются горизонтально. Размеры touch-контролов — от 44 логических единиц.
- Обычные Add/Open/Edit/Refresh используют default или ghost. Primary обозначает подтверждение: Create, Save, Apply. Деструктивная команда содержит точный глагол и отдельное оформление.
- Подсказка остаётся только там, где меняет решение: последствия отзыва, сохранность вариантов конфликта, причина ошибки. Иконкам нужны tooltip и доступное имя; это не постоянно видимый текст.
- Генератор вызывается иконкой `dice-5` справа от поля пароля. В модалке нет заголовка: результат, показ/скрытие, генерация и копирование, затем качество, длина и энтропия. `refresh-cw` означает синхронизацию, `sliders-horizontal` — настройки, `folder-plus` — новую группу, `file-plus-2` — новую запись, `file-key-2` — файл БД. Все иконки Lucide: 16 единиц, линия 1,4, единые скруглённые концы; touch-область увеличивается независимо от рисунка.
- Просмотр и редактор используют одну сетку меток и текста значений без заголовков «Поле / Значение» и без сдвига текста. Название записи остаётся в заголовке до сохранения нового имени. Справа — pencil, либо x/check; нижнего футера редактора нет. Команды управляют черновиком всех редактируемых вкладок. Повтора пароля записи нет; у URL — явная загрузка favicon. Значок синхронизации крайний справа в футере. Метрики генератора выровнены по краям и центру шкалы.
- Аналогичные формы используют desktop-метку 144 и промежуток 16; мобильные пары располагаются вертикально. Input имеет явный вариант row (прозрачный внутри структурированной строки) или standalone (слабая тематическая заливка). Постоянной обводки нет; фокус и ошибка имеют отдельную рамку состояния. Select показывает chevron, выбор файла — кнопку. Эти варианты задаются в inputFrame, а не глобальными исключениями по именам экранов.
- Общая полоса дерева, поиска и заголовка записи — 44; нижняя граница совпадает точно, вкладки/заголовки таблицы занимают следующие 38. В заголовках колонок — вертикальные разделители и индикаторы сортировки. По умолчанию название А–Я; другой столбец включает возрастание, повторный клик меняет направление. Выбор сохраняется по ID, сортировка локальна для устройства и одинакова в поиске и обычном списке.
- В «Дополнительно» и «Виде» редактируемые действия появляются только в режиме правок. Свойства доступны для чтения. История предлагает общие команды для выбранной версии; очистка находится в меню. При незавершённых правках восстановление/очистка сначала проходят Save / Discard / Stay, затем собственное подтверждение.
- Настройки устройства применяются сразу; имя — по Enter или завершению ввода, ошибочное значение остаётся с локальной ошибкой. Общей кнопки сохранения нет. Самостоятельные формы и подтверждения сохраняют текстовые команды.
- Выбор «Тема / Theme» расположен в разделе «Устройство»: «Системная / System», «Светлая / Light», «Тёмная / Dark». По умолчанию системная. Иконка настроек доступна также на приветственном экране и при заблокированных БД, чтобы смена темы не требовала разблокировки.
- Все команды, требующие следующего ввода или отдельного окна, получают «…». Внутренняя навигация использует нативные компоненты/Actions; ссылки предназначены только для внешних ресурсов.

## Плотность, темы и размеры

Цвета привязаны к семантическим переменным в FIG. Нейтральные background/panel/chrome/selected; foreground/muted; border; primary/onPrimary; danger/warning/success. Цвет состояния сопровождается текстом. В реализации адаптеры темы продукта связывают роли с GPUI Kit на macOS и Compose на Android; один общий источник встроенного TOML содержит полные секции `light` и `dark` с одинаковым набором ролей, включая фокус и состояния компонентов. Разделение фронтендов не меняет композицию и продуктовые правила макетов.

По правилам раздела «Тема интерфейса» [spec.md](../spec.md) системный режим определяет только светлый/тёмный вариант, без системного акцента или динамических цветов. Тема действует на все окна и БД устройства; смена ОС обновляет открытые формы и диалоги без потери ввода, фокуса и навигации, а после возвращения из фона режим проверяется снова. Ручной выбор фиксирует палитру. Явные цвета записей сохраняются; шрифты и геометрия не входят в цветовой конфиг.

Пользовательский TOML с частичными переопределениями и графический редактор этого же файла — будущий этап. Цвета пользователя допускаются без проверки или предупреждений о контрасте и без скрытой коррекции; предусмотрен сброс к встроенным палитрам.

Шкала: 2, 4, 8, 12, 16, 24, 32; текст 12–20, крупный заголовок только в обзоре. Desktop-кнопка 32, строка списка 36, строка описания 44. Скругление контрола 4, окно 8. Значения здесь описывают базовый масштаб; в коде использовать rem и Size API. Hairline — осознанное исключение. В макете Inter (включая значения для надёжного офлайн-экспорта); при реализации — системный UI-шрифт платформы и системный моноширинный шрифт для секретов/кодов.

| Регион desktop | Минимум | По умолчанию | Дополнительное место |
|---|---:|---:|---|
| Окно | 1100 × 720 | 1320 × 820 | Рабочие панели |
| Группы | 192 | 224 | До 280 |
| Записи | 380 | 480 | До 560; без выбора — весь остаток |
| Детали | 480 | 614 | Весь остаток при выбранной записи |

Размеры задаются относительно базового rem. При сужении сначала уменьшаются панели, затем скрывается вторичный логин в списке; название остаётся, полный текст доступен в tooltip и деталях. Разделители перетаскиваются, размеры сохраняются и ограничиваются текущим окном. У каждой панели собственная прокрутка и scrollbar у внешней границы. Заголовок записи с командами остаётся видимым. На Android клавиатура уменьшает область формы, а не перекрывает сохранение в верхней полосе.

## Состояния без отдельных артбордов

Сокращено число иллюстраций, а не поведение продукта из [spec.md](../spec.md).

| Условие | Отображение и результат |
|---|---|
| Новая база / удалена последняя группа | Пустая секция групп с «Добавить группу…»; создание записи недоступно |
| Пустая группа / нет результатов | Короткая строка в соответствующем списке; создание записи / очистка запроса |
| Loading | Индикатор рядом с текущей операцией, disabled commit, введённые данные сохраняются |
| Offline / ожидание / передача | Одна строка статуса обмена; локальная работа продолжается |
| Ошибка / нет доступа / нет места | Короткая причина рядом с объектом и доступное действие восстановления |
| Заблокированная база / новый пароль после ротации | Контент заменён разблокировкой; понятная причина нового входа |
| Черновик / уход из редактора | Восстановление зашифрованного черновика; Save / Discard / Stay при навигации |
| Неуправляющее устройство | Видимая роль; приглашение/отзыв недоступны с пояснением причины |
| Истёкшее приглашение | Вместо кода — «Приглашение истекло», управляющему доступно новое |
| Конфликт поля / удаления / перемещения | Одна композиция выбора итогового варианта; точное название объекта и последствия |
| Импорт / экспорт / восстановление | Та же форма с progress, коротким отчётом или ошибкой; важные потери данных подтверждаются |

## Клавиатура и компоненты

Tab/Shift+Tab следуют от chrome к дереву, списку, деталям и локальным действиям. Стрелки перемещают выбор дерева/списка; Left/Right сворачивают и раскрывают группу. Enter открывает выбранный объект или подтверждает форму; в многострочных заметках вводит новую строку. Cmd+F — поиск, Cmd+S — сохранить редактор, Escape — отменить верхний слой, затем вернуть фокус к вызвавшему контролу. При несохранённых изменениях Escape следует guard-правилу, а не теряет ввод.

Важные команды доступны через видимую кнопку, меню и Actions; hover не является единственным путём. Фокус, выбранная строка, наведённая строка и открытое меню различаются. Focus ring не обрезается. Switch применяется сразу; RadioGroup выбирает один вариант; независимые параметры генератора используют Checkbox. DropdownMenu/ContextMenu, Dialog/AlertDialog и Select сохраняют нативный контракт фокуса и закрытия.

## Проверка и ограничения

`source/compact.js` содержит общие примитивы и исходную компактную композицию;
`source/desktop.js` дополняет её macOS-сценариями. Они строят редактируемые макеты
из `assets/lucide-base.fig` (28 исходных иконок), `assets/lucide-extra.json`
(9 дополнительных) и QR-матрицы демонстрационного приглашения. Генератор получает
JSON от команды сборки; второй встроенной копии путей нет. Все исходники и ассеты
учитываются в проверке свежести кандидата.

`source/checks.js` проверяет сохранённую геометрию, общие границы панелей,
совпадение значений просмотра/редактора, сортировку и варианты полей. Дополнительно
проверяются отсутствие пересечений артбордов, поля нового пароля при отзыве,
отсутствие заранее выбранного победителя конфликта, отдельное копирование вариантов,
положение QR, отсутствие содержимого БД при входе и настройки до разблокировки.
Отчёт — [build/qa.json](build/qa.json).

Это статические макеты, не приложение GPUI и не кликабельный прототип. Светлая
тема, селектор режима, минимальное окно и увеличенный текст представлены
контрольными артбордами. Они проверяют видимую композицию, но не подтверждают
динамическое переключение темы, rem, клавиатурное поведение или изменение размеров
живого окна. В первой версии обязательны проверки на настоящих компонентах:
обе встроенные палитры, системное переключение и ручной выбор темы, en/ru,
базовый шрифт 14/16/18, минимальное окно, фокус и восстановление после ошибок.
Тёмная тема остаётся основным направлением. Подготовка переводов выполняется при
реализации UI; пользовательские темы относятся к будущему этапу персонализации.

Геометрия FIG фиксирована для стабильного повторного открытия в OpenPencil; текст, векторы, экземпляры и переменные остаются редактируемыми. Реализация должна использовать адаптивную композицию, а не переносить координаты из макета в код.

Ассеты встроены и не требуют сети для просмотра.
